- No review tool or model names in committed files (D111). (005)
- A test that parses config as text passes vacuously unless it has controls for a commented-out line, an inline comment and a matching line in another block; write them with the test, before review. (T001)
- A test that parses shell commands out of YAML must read every command form (block and quoted scalars, import-path packages, redirections), or count the `go` words against the invocations it read and fail on a gap. (T003)
- When waiting for a background review leg, wait on its output file, not a pgrep match: other sessions run review processes too. (T001)
- A partial-leak check needs a test secret with no English words in it; Go's JSON decode errors quote at most 4 characters of the body, so check fragments, not the whole secret. (T005)
- `mutate.py` copies only `tools/`; the live and lz-live tests read `../../../stacks` and `mise.toml`, so mutate them in a whole-checkout scratch copy. (T005)
- A redaction test needs the token to differ from every other token of the same credential; a fake issuing one token per credential lets a wrong-token fix pass. A split-write test through a child process cannot force two reads: pair it with an in-process hold-back test. (T006)
- A crash-window test must compare the pointer file's identity across the switch (`os.SameFile`), or a rewrite in place passes; a retention test must read the kept generation, not list it; crash injection proves ordering, not durability. (T007)
- A reader crash-window fixture lays a partial newer generation and a stale `current.tmp` beside a valid `current`; give each set a stale generation under the other writer's name so a shared-pointer bug reads wrong values instead of failing. A stub in a file a docs page pins is also a docs edit (re-pin it). (T008)
- A pin over a harness run checks that the run succeeded and the verb did its work (never `_, _ = execute(...)`); a caller-HOME leak check searches every variable's value for the sentinel; `plan -- all` on a fresh lane harness exits 2 by design. (T009)
- An allow-list test needs, per reserved name, a row with the exact prefix and the rest in another case; refusal rows run through the same closures as existing refused rows and check the error names the refused name. (T010)
- A field the answer chose is a body quote too: stop echoing it instead of bounding it. Before changing an error's type, grep for `errors.As` checks and text matches on it. (T011)
- A requirement naming "the run's redactor" covers every caller of the guarded type: grep the production callers before calling it done; the owner of a redactor sets it on what it calls, a caller's redactor never wins. (T012)
- A writer that deletes old copies needs a per-kind allow-list of what it may write; validate map keys as given, never look values up by a cleaned key; an fsync/rename seam makes durability ordering testable (check the first sync after the switch). Mutant loops must always end. (T013)
- A reader that must agree with a writer runs the writer's path checks from the same base directory; a retry that treats an interrupted write as done owes its unfinished cleanup; symlink tests cover every ancestor from the root. (T014)
- "No child process on any path" covers every exec.Command in the binary: grep exec.Command and "HOME=" across its packages first. git reads $HOME/.config/git/ignore even with GIT_CONFIG_GLOBAL=/dev/null. A helper that creates a resource and can then fail cleans it up itself. (T015)
- To show "appended as each event arrives", read it while the child runs and stop before the deadline; a deadline test checks when the run stopped, timing the run call alone; a recorded deadline is not proof it is enforced. (T017)
- To exhaust a long budget offline, start a fake clock late (wall clock plus what is spent) and let its `After` advance it, anchored to a deadline the test fixes before and after the paired task; a wall-clock row that hangs under a mutant hides the fake-clock cases in the same binary, so run mutants without it too. (T019)
- "Registered before the call" is an ordering claim: the fake records the trap when the call arrives, or a cleanup added after it returns passes; an error after the resource exists is also a dropped connection (hijack and close; Go does not replay a POST). (T020)
- An outcome that is a special case of a status (a 404 meaning "not configured") needs a row with the same status and another code; at the chain, pin only what the requirement fixes ("not pass" where it names a judge outcome), and build fixtures from the shared passing set minus the new assertion. (T021)
- A deadline test that reads only the recorded value passes an unbounded context: read the deadline a real call carries (the API transport's request context) with the test's own timeout off; mark a run failed on `ctx.Err()`, not only on an error, since the store's calls ignore the context. (T022)
- `apply_complete` is every completed action (update and delete too, delete without an id), not every created resource: check a reused event consumer against a capture from the pinned tool (`resources/tofu` of the runtime, `terraform_data`, offline). (T022)
- To show which context a child process ran under, observe it where the child is made (`childEnv.command`, nil in production) and compare deadlines exactly against another call that must share it; to test "fail on `ctx.Err()`", end the context from a seam and let every call still answer (`context.WithoutCancel` in the fake). (T023)
- A budget whose only state is its end time makes "one budget per check" untestable by sharing alone: a new budget with the same end is equivalent. Give it state that carries across instances (a reserve raised by the slowest read) and pin it with a slow call on the fake clock; test an outcome precedence (`blocked` only when alone) with a mixed-error row. (T024)
- A cleanup armed before a create must know who owns the name when the create's answer is ambiguous (5xx, dropped, or success on a name that existed): read it first, remove only what the read found absent, report (never remove) what it found, and walk every read × create answer pair in a table before review; a 409 alone settles only one cell. (T025)
