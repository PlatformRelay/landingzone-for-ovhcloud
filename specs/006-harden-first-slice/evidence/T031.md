## What the tests pin (readings for T034)

Data-model fixes the signature; these readings are this task's, and T034 may change one only as a TEST-class change with evidence from spec.md.

1. **Input forms.** `Manifest` and `Layer` as `pack` reports them (`sha256:<hex>`); `Resources` and `Entry` as bare hex, the form of `-manifest-sha` and `bundle.Hash`. `Builder` is a free string the builder id must contain.
2. **Digest sets.** Subjects and resolved dependencies carry `{"sha256": "<hex>"}`, bare hex, as in-toto's DigestSet does (believed: in-toto attestation spec v1, `spec/v1/digest_set.md`, hex-encoded values keyed by algorithm).
3. **Subjects.** Exactly two, the manifest and the layer, each with exactly one digest and a name of its own (names not fixed).
4. **Materials.** The commit is a value somewhere under `predicate.buildDefinition.externalParameters` (key not fixed); `resolvedDependencies` holds one entry whose name or uri contains `resources.json` with the resources digest, and one named (name or uri) entry with the entry digest; `buildType` is not empty (SLSA v1 requires it); `runDetails.builder.id` contains `lz-pack` and `Builder`.
5. **Reproducible and unsigned.** Two renders are byte-identical. `statementWellFormed`, applied to the unit statement and to the file `lz-pack` writes, checks: keys strictly ascending in every object (a token walk, so whitespace and string escaping are free and a duplicate key fails); top-level keys exactly `_type`, `predicate`, `predicateType`, `subject` (an unsigned statement: a DSSE envelope or a `signatures` field fails, FR-017 "not signed"); `_type` and `predicateType`; no leaf under a time key (`startedOn`, `finishedOn`, `timestamp`, …) and no string that parses as a time.
6. **Refusals.** An empty field (any of the six) is refused with an error and nil bytes, and so is a value that is not what the field names: a commit that is not a full lowercase object id (40 or 64 hex; rows `main`, a 7-character prefix, upper case), a manifest or layer not `sha256:<64 hex>`, resources or entry not bare 64 hex. Each refusal row first renders the full input (the control).
7. **Command line.** `lz-pack` takes `-commit <sha>` (the form `lz-release --commit` uses in research R9) and writes `<out>/provenance.json`; without `-commit` it exits non-zero and leaves no layout. "Beside the packed image" is read as beside `index.json` inside the layout directory: a sibling file would break `TestPackRoundTrip`'s one-sibling check. The layout then holds exactly `blobs`, `index.json`, `oci-layout`, `provenance.json` (no signature beside the statement). These tests do not pin what happens when writing the statement fails after the layout is written; the reference port leaves the layout, which T034 should not (*Deferred and rejected*). The entry digest is that of the bundle's `lz-offline`, the bytes packed as `runtime/lz-offline`.
8. **Harness.** The test binary doubles as `lz-pack` through `TestMain` (`LZ_PACK_TEST_MAIN_ARGS`, a JSON argument list; a fresh `flag.CommandLine`), so the flag and the file are tested as the owner runs them without fixing `pack`'s Go signature.
9. **For T034.** `pack` already sits at cognitive complexity 19 (pre-existing); writing the statement in a helper keeps it from growing. Write it inside `pack`'s removal-on-error, so an image never stands without its statement.
11. **Layout and builder (round 2).** The command-line case takes its expected subjects from the layout (`index.json`, then that manifest's layer), not only from what `lz-pack` prints, and requires the builder id to carry `lz-pack@<version>` with a non-empty version. A time key at any depth of a leaf's path counts, so `{"timestamp": {"seconds": 1}}` fails.
10. **Harness guard.** The child runs `main` only when `LZ_PACK_TEST_MAIN_ARGS` is set *and* its only argument is `-test.run=^$`, so an exported variable in a shell or CI cannot turn the test binary into `lz-pack`.

## Reference port (control, outside the repository)

`provenance.go` as the control used it (a sketch of T034, not its design), with `commitID = ^([0-9a-f]{40}|[0-9a-f]{64})$` and `bareHex = ^[0-9a-f]{64}$`:

```go
func provenance(in provenanceInput) ([]byte, error) {
	for _, v := range []string{in.Commit, in.Manifest, in.Layer, in.Resources, in.Entry, in.Builder} {
		if v == "" {
			return nil, errors.New("PROVENANCE: incomplete input")
		}
	}
	if !commitID.MatchString(in.Commit) || !bareHex.MatchString(in.Resources) || !bareHex.MatchString(in.Entry) {
		return nil, errors.New("PROVENANCE: malformed input")
	}
	for _, d := range []string{in.Manifest, in.Layer} {
		if !strings.HasPrefix(d, "sha256:") || !bareHex.MatchString(strings.TrimPrefix(d, "sha256:")) {
			return nil, errors.New("PROVENANCE: malformed digest")
		}
	}
	hexOf := func(d string) map[string]any { return map[string]any{"sha256": strings.TrimPrefix(d, "sha256:")} }
	statement := map[string]any{
		"_type": "https://in-toto.io/Statement/v1",
		"subject": []any{
			map[string]any{"name": "manifest", "digest": hexOf(in.Manifest)},
			map[string]any{"name": "layer", "digest": hexOf(in.Layer)},
		},
		"predicateType": "https://slsa.dev/provenance/v1",
		"predicate": map[string]any{
			"buildDefinition": map[string]any{
				"buildType":          source + "/lz-pack@v1",
				"externalParameters": map[string]any{"source": map[string]any{"commit": in.Commit, "uri": source}},
				"resolvedDependencies": []any{
					map[string]any{"name": "resources.json", "digest": hexOf(in.Resources)},
					map[string]any{"name": "lz-offline", "digest": hexOf(in.Entry)},
				},
			},
			"runDetails": map[string]any{"builder": map[string]any{"id": source + "/tools/cmd/" + in.Builder}},
		},
	}
	return json.Marshal(statement)
}
```

## Learnings

Class: guidance.
- When a value passes through a renderer and then a command line, run the same well-formedness check on the file the command writes as on the renderer's output; a correct renderer behind a command that rewrites its output otherwise passes.
- Take a command-line test's expected values from the artefact it wrote (the layout's index and manifest), not from what the command prints: printed and written values come from the same process and can be wrong together.
- An empty expected value in a `strings.Contains` check makes it vacuous; a helper shared by unit and command-line cases needs a non-empty needle in both.
- "Not signed" is testable: pin the unsigned statement's exact top-level key set and the directory listing beside it.
- Re-read a review brief after editing it (T030's lesson, repeated here: a failed edit sent round 1's text again).
