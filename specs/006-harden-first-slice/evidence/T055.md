## What changed (verified 2026-10-19, by reading the diff)

- `RunTarget` gains `seconds` (required by the strict decoder, so a record from before this change no longer decodes: `RUNS_SYNTAX`).
- `splitLog` keeps each line's timestamp; `observeLog` notes the line each target closed on (`LZ_TARGET_OK` or Task's failure line); `timeTargets` parses every line's time (RFC 3339) and sets each target's seconds: from the checks step's first line, or the previous target's end line, to its own end line, rounded up. A line without a time, or a target ending before it began, is `CAPTURE_LOG`.
- Round-2 fix: `FoundationRun` gains `outside_seconds`, set by `timeTargets` from the log's first line to the checks step's first line (the whole log when there is none) plus from the last target's end to the log's last line, rounded up once; either span negative is `CAPTURE_LOG`. The job's timeout counts from the job's start, about a second before its first log line (job `started_at` 18:51:40Z, first line 18:51:41.58Z on run 39306063817; believed, not verified against GitHub's documentation); the rounding up covers part of it.
- `judgeGreen` (head runs only) calls `judgeBudget`: `RUN_UNTIMED` for a target with 0 or negative seconds, or negative outside seconds; `RUN_OVER_BUDGET` when the targets' sum plus the outside seconds plus `FoundationChildDeadline` (240 s) exceeds `timeout_minutes` × 60. The sum is a float so no recorded value can wrap it. The red control is not budgeted: it stops early by design.
- `FoundationChildDeadline` (exported, 240 s) in `checks`; `lz-offline`'s `TestChildDeadline` now also requires `childDeadline == checks.FoundationChildDeadline` (its 240 s pin unchanged).
- KI-001 pins `foundation_ci.go`: blob `15bc8ff…` → `8e5e536…`, `last_verified` → `3bbc505e10ebc7bce5e0721f0e740f784ed8b92b` (the base). Its text (CI source admission) is unaffected; `verified.at` unchanged, no sentence added.

## Learnings

Class: guidance.

- A time budget for a CI job must count the whole job the timeout covers (set-up, fetches, after the last step), not only the steps it measures; check the job's `started_at`/`completed_at` against the measured spans before writing the rule.
- A rule that judges a run record cannot run inside a foundation target that the record's runs are bound to (digest cycle); put it in the run judge, test it with fixtures in the target, and say so in the task text.
