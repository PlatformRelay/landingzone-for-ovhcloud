## Decisions (left open by T040)

1. **An absent map is a finding** (task decision, 2026-10-19). FR-019 fails a map that "omits an admitted top-level directory present in the checkout"; an absent map omits every one, and a gate that a deleted page turns off fails open. It reports `MAP_MISSING_DIR` for each admitted directory (no new rule id beyond data-model's). A map that is not a regular file is absent, as the pages walk already skips a linked page. Consequence: `docsRepo` gains a map (TEST-class change, *Test changes*).
2. **A subpath row does not map its top-level directory** (task decision). The page's own contract is "every top-level entry and its main subdirectories, one line each", and US6 says every admitted top-level directory "is in the map": the strict reading gives each top-level directory its own line. Pinned by the new row `directory mapped only by a subpath` (kills T040's surviving `subpath-maps-dir`).
3. **Real map** rewritten: the six abbreviated `modules/` cells spelled out (`modules/cloud-quota/` and so on), rows added for `.github/`, `pipelines/` and `tests/`, and a sentence saying what `task docs:check` holds the map to. Result: `MAP_UNJUDGED=2` (`.sonarcloud.properties`, `.gitignore`), no finding (verified 2026-10-19, host and entry).
4. **One admitted list**: `checks.EntryAdmitted()` returns the snapshot's names; `snapshot` calls it (same names, same order; behaviour unchanged). A copy in `lz-check` would let the entry admit a new name the map check silently leaves unjudged.
5. **Paths the entry cannot hold**: a map path that is not clean (`tools/../docs`, `./tools/hello.txt`, judged before the admitted-name test, review round 1) is `MAP_PATH_GONE`; so is one under an admitted name that passes through a symbolic link (the snapshot copies regular files and directories only) or a name the snapshot skips (`.git`, `.local`, `.terraform`, `.cache`, `.env*`, `.envrc`, now `checks.EntrySkipped`, shared with `snapshot` as the admitted list is; review round 1), even when it resolves on the host.
6. **Registry**: no `checks.yaml` change. Every path the real map names under an admitted name is already covered by `docs:check`'s scope and inputs or has a digested file below it (`pipelines/` and `pipelines/github/` through `pipelines/README.md` and `pipelines/github/foundation-source.json`; never through `foundation-runs.json`, which the existing guard keeps out). The new `mapReadsCovered` row of `TestRegistryInputsCoverReads` parses the real map with the check's own `mapPaths` and fails for any admitted map path without that cover, so a future row (`examples/`) forces an input. Gap: admitted names absent from the checkout (`catalog`, `examples`, `profiles`, `policies`, …) cannot be inputs, because `Digest` fails on a missing path; creating one changes the check's outcome (`MAP_MISSING_DIR`) but not its digest until it is mapped and listed (*Harness gaps*).
7. **Rows** (review rounds 1 and 2): map paths are the first cell's code spans of each table body row, the rows after a delimiter row up to a line without a pipe; a row may be indented up to three spaces and needs no leading pipe (CommonMark/GFM); rows inside fenced blocks are examples and not read; a pipe line outside a table is not read.
8. **Trailing `/`** (review round 2, strong leg note): dropped without checking the entry's kind (`Taskfile.yml/` passes, `tools` maps the directory). Accepted leniency, as T040 left it unpinned: stage B.

## Learnings

Class: sensor. A Markdown-reading gate parses the format, not the file in front of it: a table body row may be indented up to three spaces and needs no leading pipe, a fenced example carries its own delimiter row, and a path may arrive as `./x`; pin each with a row before review (both review rounds found one). A refactor that moves an inline list out of a pinned file re-pins every page that references it, after each later edit too.
