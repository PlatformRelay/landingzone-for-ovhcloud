## Task text (tasks.md)

T029 [US3] Write entry-limit tests in tools/cmd/lz-offline/limits_test.go and tools/cmd/lz-offline/limits_host_test.go. Requirements: FR-013; ADRs: 0008, 0021. Depends on: none. Cases (given / when / then → defect exposed): (1) given limits and a bwrap argv / when `scopeArgv` builds the command / then it carries `MemoryMax`, `TasksMax`, the unit and the unchanged bwrap argv → exposes a dropped limit or an altered sandbox. (2) given a missing `systemd-run`, an unreachable user manager, or controllers lacking `memory` or `pids` / when `limitsUnavailable` runs / then it names the reason and the entry never starts the child → exposes a start without limits. (3) given a fake cgroup directory whose `memory.max` or `pids.max` differs from the request / when `checkScope` runs / then it refuses → exposes limits silently not applied. (4) given `memory.events` with `oom_kill 1`, and `pids.events` with `max 1` / when `limitTripped` reads them / then `memory`, then `tasks` → exposes a limit kill reported as an ordinary failure. (5) host, outside the entry (premise P2): given a child allocating twice the limit, and a fork storm past the task limit / when run under the entry with limits / then each is stopped within 10 s with `RESOURCE_LIMIT memory` or `RESOURCE_LIMIT tasks`, a valid child passes and `--die-with-parent` still ends the tree → exposes limits that do not hold on a real host. Verify: `task test:runtime-image` through the entry and, on the workstation, `go -C tools test -tags hostlimits -run TestHostLimits ./cmd/lz-offline`: every case fails against the stubs and a stub entry that starts the child without limits. Evidence: `evidence/T029.md`; PR; initial status `not-run`.

## Reading of case 5

"Under the entry with limits" is read as P2's probe (spec.md:165: "host-tagged test runs an allocating and a forking child under the scope and reads `memory.events` and `pids.events`"): the test composes the entry's limit steps (`limitsUnavailable`, `scopeArgv`, `checkScope`, `limitTripped`) around a bwrap sandbox with the entry's isolation flags, and runs its own binary inside as the child. It does not run a built `lz-offline` binary: that needs an admitted runtime bundle (`bundle.Admit`, 647 MB of resources) and would allocate twice the entry's 8 GiB placeholder on the host when run against a stub without limits. The test's limits are small (64 MiB, 32 tasks), so a child that escapes them stays harmless. (believed: the reading; verified 2026-10-16: the bundle size, `du -sh` of the installed entry's resources.)

## Findings for T032 (observed on this host)

- A transient user scope is removed as soon as its last process ends, and its files then fail to read (`read …/memory.events: no such device`; verified 2026-10-16 by the host control). Research R5's "read `memory.events` and `pids.events` after the child ends" does not work as written: the entry must read while the scope exists (poll, as this test does) or keep it alive.
- `pids.max` refuses forks; it does not stop a storm that ignores the refusal. The host case's storm exits on the first refused fork. A storm that retries keeps running until the 240 s deadline, so SC-003's "stopped within 10 s" needs the entry to end the scope when `pids.events max` rises (believed; not run). The host case cannot pin this: its harness is not the entry and would never stop a retrying storm.
- This host's swap is full (`swapon --show`: 8G size, 8G used, 2026-10-16), so `MemoryMax` alone OOM-kills here. On a host with free swap, a cgroup over `memory.max` swaps instead of being killed (believed, cgroup v2 semantics; not run): T032 likely needs `MemorySwapMax=0`, which `TestScopeArgv` admits (extra properties are allowed). The host control's memory row went green on a host whose swap was full; full swap is a plausible reason it was killed rather than swapped (believed; no controlled comparison was run). Not pinned in the unit tests: FR-013 fixes no swap mechanism; T032 decides, and its host run must be on a host with free swap or record that it was not.

## Learnings

Class: guidance.
- A transient user scope (`systemd-run --user --scope`) is removed when its last process ends and its cgroup files then fail with ENODEV: read `memory.events`/`pids.events` while it exists, never after the child ends.
- `pids.max` refuses forks but does not stop a storm that retries; a "stopped within N s" claim needs the supervisor to act on `pids.events max`.
- A cgroup memory-limit test that passes on a host with full swap says nothing about a host with free swap: record the host's swap state with the result.
- Equality refusal tests need values on both sides of the request (higher and lower), or an inequality check passes every row.
