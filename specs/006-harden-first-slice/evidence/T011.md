## What changed

- `API.do` (`binding.go:73`): every error is a `*callError` naming the call and the class: `answered <code>` (status path, text unchanged), `answered 3xx` (a transport error after a recorded answer: Go parses a 3xx's `Location` before `CheckRedirect` and returns no response when that fails, `net/http/client.go`, Go 1.27.1, read 2026-10-15, verified), `quiet`'s `timed out` / `cancelled` / `request failed` (other transport errors; `Client.Do` documents its errors as `*url.Error`), `answered 200 with a body that does not decode`. No `%w` of a transport or decode error is left.
- `API.Account` (`binding.go:130`): appends `bindNext` = `check the API endpoint, the network and the credential, then re-run` to every failure. `Bind`, `lz-live probe` (`probe.go:156`) and `lz-live lane` (`lane.go:56`) all reach the binding client through it.
- `quietToken` (`leftovers.go:173`): passes a `*callError` through (it used to match a `*url.Error` and the exact `token endpoint answered <code>` text); anything else stays `no usable token in the answer`. Without this the leftover and bearer clients would have lost the transport class (`timed out`), since `token()` no longer returns a `*url.Error`. `newBearer`'s 400/401 check (`ovhapi.go:91`) reads `token endpoint answered %d`, whose text is unchanged.
- Reading of "status class" (from T005): `3xx` where only the class is known; the full code where Go returns the answer (`302`, `401`, `200`), which names the class too. Believed; for review.
- Reading of "next action": one generic action for every class. A per-class action (credential for 4xx, endpoint for 3xx) would be sharper; not done, FR-003 asks for one and the task names no wording. Believed; for review.

## Maintainability

1. Duplicates existing code? No: the transport branch reuses `quiet` (`leftovers.go`); `quietToken` shrank.
2. Hard to read? No; `do` has four error lines, one per class.
3. Hidden coupling? `newBearer` parses `token endpoint answered %d`; that text is unchanged and `TestLeftoversAPITokenAnswerNoEcho/status` pins the 503. The new `answered 3xx` parses as code 3 there, which is not 400/401, so it stays a plain error.
4. Magic values? `bindNext` named.
5. Dead code? `quietToken`'s `*url.Error` and exact-text branches removed, since `token()` returns neither now.
6. Error handling weakened? No: errors keep their call and class; the `%w` chains dropped carried only answer-chosen text. Nothing upstream used `errors.As` on a `*url.Error` from the binding client (grep, 2026-10-15, verified).
7. Tests brittle? The new test asserts the call, the class token and `then re-run`; other wording is free.
8. Scope creep? `leftovers.go`'s `quietToken` beyond the named file, to keep the leftover and bearer clients' classes after `do` changed.
Verdict: easier to change; every binding-client error now comes from one type.
