## Decision: a lockless stack whose stage has no lock is refused

T027 left open what `Generate` does when `stages/<stage>/.terraform.lock.hcl` is absent (evidence T027 *What the tests pin*). Options: (A) skip the copy and leave the stack without a lock; (B) refuse with a new code before anything is written. Chosen: B, `NO_STAGE_LOCK`. Reason: FR-011 says each new stack gets its stage's lock, and contracts/checks.md V003 lists "new stack without lock" as the defect to catch; A produces exactly that stack, which `task lint` and the live runner then refuse at `-lockfile=readonly` init (believed, from `TestRepositoryStackLocksMatchStages`'s comment; not run here). Cost: seven existing tests generated in roots without `stages/` and owed TEST-class changes (*Test changes*). The code is an addition: data-model fixes `Generate`'s signature and the two FR-011 codes, not that no other code exists. Only a stack that lacks a lock needs a stage lock: a tree whose stacks all carry locks generates without `stages/`.

Further choices, not pinned by T027 and open to review:
- A lock a stack already has is never replaced, whatever it holds, and anything at the lock path (a link included, `os.Lstat`) counts as one. The copy is written to a temporary file in the stack directory and published with `link(2)`, which refuses an existing path, then the temporary file is removed: it never writes through a link, and a write that fails leaves no partial lock that a later run would keep as the stack's own (review round 1). A failure after `terramate generate` (a copy) can leave generated files with some locks missing; the next run copies the rest. FR-011's "nothing written" is the refusals', which all come before the first write. A stack lock that differs from its stage's stays `TestRepositoryStackLocksMatchStages`'s finding, not generation's.
- `UNRECONCILED_ROW` names the first such row in manifest order (`Path` the row's stack path, `Detail` its id), found by the same discovery `Reconcile` uses: a row whose path holds no stack block.
- `CheckStageLocks` compares every provider, not only `ovh/ovh`; a provider only one stage pins, a stage directory without a lock and a missing `stages/` are no finding; hashes compare as sets (sorted, a repeat dropped); comments and constraints do not count. A lock that cannot be read or parsed, holds anything but `provider` blocks (a misspelt block, a top-level attribute), or has a provider block without `version` or `hashes`, is a finding naming the stage (fail closed: a check never passes on a lock it did not compare). Each later stage is compared with the first stage, in name order, that pins the provider: one finding per differing stage, not per pair.

## Learnings

Class: guidance.
- A copy that must never replace an existing file is also a copy that must never leave a partial one: write a temporary file in the same directory and publish it with `link(2)`, or a failed write becomes the file a retry keeps.
- A parser for a fail-closed comparison refuses what it does not know at the level that decides what is compared (a misspelt block, a top-level attribute): skipping it reads as "pins nothing", which agrees with everything.
- A refusal a requirement implies (no stage lock to copy) turns every test that generates in a bare root red: list the generation fixtures first (`grep generateIn\|Generate(`) and give them the precondition in one helper.
