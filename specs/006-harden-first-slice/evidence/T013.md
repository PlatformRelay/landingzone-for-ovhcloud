## Maintainability

1. Duplicates existing code? No; the KEY=value formatting is extracted and shared with `WriteCredentialFile`, not copied.
2. Hard to read? The function follows data-model's numbered steps, each commented.
3. Hidden coupling? `setSync`/`setRename` are package variables used only by the set writer; tests that swap them are not parallel (`withUmask`) and restore them in `t.Cleanup`.
4. Magic values? The generation pattern is data-model's (`^gen-[0-9A-Za-z-]+$`), named `genName`.
5. Dead code? No; `SetStepCleanup` is honoured though no test injects it (data-model fixes the constant).
6. Error handling weakened? No; every filesystem error returns; errors name paths and keys, never values.
7. Tests brittle? The durable test compares absolute paths the writer builds with `filepath.Join`, the same way the test does.
8. Scope creep? `currentGeneration` reads the pointer for the writer only; T014 owns the reader (`CredentialSetPath`) and may reuse or replace it.
