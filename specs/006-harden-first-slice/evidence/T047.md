## Learnings

- class: sensor. A check's inputs should name every non-Go file its own tests read, not only task lists. Proposed task: pin `test:traceability`'s remaining reads (`pipelines/github/foundation-source.json`, `.github/workflows/foundation.yml`, the README set `docs_test.go` reads) with a subtest per read, as T047 does for the task lists; optionally make T047's subtest two-directional (an input `specs/*/tasks.md` that no creator owns fails).
- class: guidance. Test the judge's own read set through the judge's own lookup (factor the helper out), not a copy of it, so the pin cannot drift from what the judge opens.
