## Decisions this task makes (independent-review)

- **`commit` argument** (T036 left it open): a full lowercase 40-hex object id that names a commit in the repository (`rev-parse --verify <id>^{commit}` answers the same id). An abbreviation, a ref name (`HEAD`), an upper-case id, a tag or tree id and an unknown id are refused with `RELEASE_COMMIT`. Reason: `source_commit` must be the exact commit the bytes depend on (schema `^[0-9a-f]{40}$`), and a ref would make the bytes depend on where the ref points; hex only also keeps the argument from being read as a git option.
- **Clean git environment**: every git call gets `cmd.Env` built from scratch: the caller's `PATH`, `HOME` and `GIT_CONFIG_GLOBAL` at the null device, `GIT_CONFIG_NOSYSTEM=1`, `GIT_ATTR_NOSYSTEM=1`, `GIT_NO_REPLACE_OBJECTS=1` (replace refs would change what history reads), `GIT_GRAFT_FILE` at the null device (a local `.git/info/grafts` would cut history; review round 2), `GIT_NO_LAZY_FETCH=1` (a partial clone would fetch a missing blob from its promisor remote and write it; review round 1), `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`, `LC_ALL=C`. Only plumbing reads run (`rev-parse`, `for-each-ref`, `ls-tree`, `cat-file`, `rev-list`); none writes.
- **Fail closed rather than render a document the schema refuses**: a shallow repository (`RELEASE_SHALLOW`: the changelog would be cut silently), a commit with no `mise.toml` or a `[tools]` table the renderer cannot read exactly (`RELEASE_TOOLCHAIN`: non-string values, dotted keys, multi-line strings, escapes (also in a table name or a top-level key, review round 1), duplicates, a version with whitespace; table names are read as TOML keys, so `["t ools"]` is another table), a partial clone missing an object (git's own error, nothing fetched), and an empty subject in the range (`RELEASE_SUBJECT`).
- **Changelog range**: commits reachable from `commit` but not from the newest train tag reachable from it, newest by version with each part compared as a number (`2026.09.10` after `2026.09.9`), or from the root when none is (`rev-list --topo-order --reverse <commit> ^refs/tags/<newest>`). This is T036's recorded reading ("the newest train tag reachable from the commit"). Round 1 excluded every reachable train tag instead; review leg 1 showed that changes the contract on merged histories, so it was replaced. A train tag is a tag named exactly `YYYY.MM.N` (data-model's pattern).
- **Schema validation stays in the test**: research R9 mentions `checks.DecodeStrict`; importing `internal/checks` would pull `internal/report` and the HCL dependencies into a standard-library package and widen `test:release`'s registry inputs. The output is built from typed values, and `TestManifestGolden` validates it against the schema.
- **`lz-release` repository**: `--repo` defaults to `.`; git finds the repository from there, so the quickstart's `go -C tools run ./cmd/lz-release manifest …` (working directory `tools/`) renders the repository's root tree (`ls-tree --full-tree`).

## Learnings

Class: guidance.
- A renderer that must read "git objects only" also turns off git's history rewriters and fetchers: `GIT_NO_REPLACE_OBJECTS`, `GIT_GRAFT_FILE=/dev/null`, `GIT_NO_LAZY_FETCH`; a clean `cmd.Env` alone keeps the caller out, not the repository's own grafts, replace refs or promisor remote.
- A hand-written reader of another format (TOML) compares names as the format defines them: quoted keys keep their spaces and escapes; refuse escapes rather than drop them, at the top level and in table names too.
- "Since the previous tag" on a merged history needs one tag picked deterministically (newest by version, compared as numbers); a fixture with a side-branch tag older in history but newer in version separates the readings.
