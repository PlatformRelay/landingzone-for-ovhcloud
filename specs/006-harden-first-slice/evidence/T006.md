## Task text (tasks.md)

T006 [US1] Write leftover-token redaction tests in tools/internal/live/chain_test.go. Requirements: FR-004; ADRs: 0009, 0021. Depends on: T004. Cases: (1) given a fake listing that returns the bearer token as a resource id / when the chain's leftover check runs / then no file of the run record (`listings/*.json`, `leftovers.json`, logs) and no captured stream contains it, and the listing is recorded with the id redacted → exposes the token never reaching the redactor. (2) given the token inside a longer id / when the same runs / then the token part is redacted → exposes an exact-match-only fix. (3) given the token split across two writes of a stream / when the same runs / then neither write shows it → exposes registration after the stream started. (4) given a `LeftoverCheck` with `Red` set / when the first listing is requested / then `Red` already holds the token → exposes registration after the first listing. Verify: `task test:live-lane`: all four cases fail on today's code.

The chain's exit code is not asserted.
- Case 2 (`token-inside-longer-id`): the same with id `lz-<token>-t006` and the slice-prefixed name `lz-t006-token-inside`, so it is also a leftover: the listing record and `leftovers.json` must carry `lz-[REDACTED]-t006`.
- Case 3 (`token-split-across-writes`): the plan of `demo-dev-gra11-network` (planned after the baseline listed) prints `T006-split-before:<first half>` and `<second half>:T006-split-after` of the token the last listing request carried (the baseline's; the transport writes it next to the world log, the fake tofu reads it) as two writes 100 ms apart (`laneStack.PlanSays`). The terminal must show `T006-split-before:[REDACTED]:T006-split-after` and no half of a listing token next to its marker. 8. Scope creep? The knob in `apply_test.go`, the transport mode and the stub field are needed for cases 3, 1–3 and 4.

## Learnings

Class: guidance.
- A redaction test that names "the token" has to make that token distinguishable from every other token of the same credential: a fake that issues one token per credential lets a fix that redacts the wrong token pass.
- A split-write test through a child process cannot force two reads on the parent side; pair it with a deterministic in-process test of the hold-back and say which defect each one pins.
