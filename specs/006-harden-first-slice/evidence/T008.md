## Task text (tasks.md)

T008 [US1] Write credential-set reader and migration tests in tools/internal/live/credentials_test.go. Requirements: FR-005; ADRs: 0009. Depends on: T004. Cases (given / when / then → defect exposed): (1) given `current` naming a missing directory, `../x`, or a name not matching `gen-…` / when `CredentialSetPath` resolves / then it refuses with `CREDENTIAL_POINTER_INVALID` → exposes a pointer that escapes the set directory. (2) given today's flat files and no `current` / when `LoadCredentials` runs / then it reads the flat files → exposes a broken migration. (3) given flat files and a `current` / when `LoadCredentials` runs / then it reads the generation → exposes flat files winning after the switch. (4) given a set write after a `tenant-state` apply / when `LoadCredentials` loads the tenant's state credentials / then they come from that tenant's set → exposes one shared pointer for all writers. (5) given any write / when it completes / then `account.env`, the passphrase, `sandbox.env` and the bootstrap `state.env` are byte-identical → exposes a writer moving the binding. Verify: `task test:live-lane`: every case except the flat-file read fails against the stub.

## What the tests pin (for T013 and T014)

Readings (data-model *Credential set* and *Fixed signatures*, spec FR-005, research R4; read 2026-10-15):
- `CredentialSetPath`'s `root` is the config root (as `CredentialSet.Root`), `rel` is relative to the account directory (data-model: the generation holds "the set's files at the relative paths readers use today", e.g. `platform-deployer.env`), and the result is the full path: `<root>/accounts/<a>/sets/<instance>/<gen>/<rel>`, or `<root>/accounts/<a>/<rel>` while `current` does not exist. Believed: the signature takes `root`, so a root-relative result would be an odd contract; the tests compare `filepath.Clean(got)` with the full path.
- The writing instance of a file is the one `writerOf` names today: `account-governance` for the deployer files, the tenant's `tenant-state` row (`demo-state`, `ops-state`) for its `state.env` and `platform-state.env`. `sandbox.env` and the account `state.env` are in no set (data-model), so the bootstrap rows read them flat whatever sets exist.
- The refusal is judged by the error text's prefix `CREDENTIAL_POINTER_INVALID` (data-model: "error text starts").

Cases, task case → test:
1. `TestCredentialSetPathPointerInvalid` (8 subtests; flat files present in every one, so a fallback shows): `missing-directory`, `parent-escape` (`../x` with a set at `sets/x`), `not-a-generation-name` (`x` with a directory `x` beside it) are the task's three; added within the same claim ("a pointer that escapes the set directory"): `account-directory` (`../..`, which is the account directory holding the flat files), `absolute`, `empty` (resolves to the set directory itself), `generation-is-a-file`, `generation-is-a-symlink` (a `gen-` name that is a symlink to a directory outside the set; data-model: "an existing sibling directory", and G3's no-symlink rule).
   Positive controls in `TestCredentialSetPathResolves`: `current-names-generation` (a previous generation, and a newer partial generation named by `current.tmp`, both present: neither is followed), `no-set-flat`, `first-write-crashed-flat` (a partial generation and `current.tmp`, no `current`: the flat path).
2. `TestCredentialsFromSets/flat-files-without-current`: every row of the two-tenant manifest, with a crashed first write (partial generation and `current.tmp`, no `current`) beside the flat files. Passes against the stub, as the task's Verify expects (today's `LoadCredentials` reads the flat files).
3. `TestCredentialsFromSets/generation-after-switch`: flat files plus a set with `current` for every writer, a previous generation and a newer partial one with `current.tmp` (T007's crash-window lesson for readers: follow `current`, not the newest name nor `current.tmp`). Every row reads its generation's values; the bootstrap rows still read the flat `sandbox.env` and account `state.env`.
4. `TestCredentialsFromSets/each-writer-its-own-pointer`: `account-governance` and `demo-state` sets with different generation names, each set also holding a stale generation under the other's current name, so a reader that takes one pointer for every writer reads stale values or fails; `ops-state` has no set yet and its files stay flat (per-writer migration).
5. `TestCredentialSetWriteKeepsBinding`: through `WriteCredentialSet`: a first `account-governance` write (the migration), a `demo-state` write, a second `account-governance` write; after each, `sandbox.env`, `account.env`, `state-passphrase.env` and the account `state.env` are byte-identical and still 0600 regular files. Added within the same claim: `ops`'s flat `state.env` and `platform-state.env` (a writer with no set yet) stay byte-identical, so a migration that removes more than its own flat files fails (FR-005: readers see the previous set whole).

Not covered (believed, by design): "resolve `current` once per load" (a pointer switched between two files of one load) needs a writer racing the reader and is left to T014's review; whether the first migration removes its own flat files (data-model step 5; spec FR-005 does not require it, and a reader that prefers the generation is correct either way); a `current` with a trailing newline (data-model: "whole content is the name"; the tests write none and judge none).

## Learnings

Class: guidance.
- A reader crash-window fixture should lay every leftover a crashed writer can leave (a partial newer generation, a stale `current.tmp`) beside a valid `current`; mutants that follow `current.tmp` or the newest name are then killed.
- A per-writer pointer test needs a stale generation under the other writer's current name in each set, or a shared-pointer reader fails only by a missing file rather than by reading wrong values.
- A pinned docs page (`references:`) makes even a stub in the pinned file a docs edit: re-pin the blob and `last_verified` in the same commit.
