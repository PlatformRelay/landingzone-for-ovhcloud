## What changed (2026-10-16, verified by reading the diff)

- `deadline.go`: `retryBudget{end, reserve}`; `newRetryBudget(end, reserve)`; `admit(now, wait)` is `end - now - wait >= reserve`; `keep(d)` raises the reserve to `d`, never lowers it; `minRetryReserve` = 30 s (data-model floor).
- `chain.go` `leftovers(ctx, check)`: one `newRetryBudget(end, minRetryReserve)` per check, `end` = `ctx.Deadline()` (the destroy context `dctx`, T023; none: zero time, no wait admitted), passed to every retained `readRetained`.
- `chain.go` `readRetained(ctx, in, into, b *retryBudget) error` (data-model's fixed signature): backoff and clock come from `laneRunner.stateReadBackoff` and `stateReadClock` (set once in `chain()` from `ChainOptions`, nil: `defaultStateReadBackoff`, `wallClock{}`). Each attempt calls `b.keep(attempt duration + r.listTook)`; before a wait, `b.admit(clk.Now(), wait)`; a refusal returns `*waitRefused` (`… blocked waiting-for=<instance>: …`), takes no wait and prints no retry line.
- `chain.go` `baseline`: `r.listTook` = the baseline listing's duration on the same clock (data-model: "estimated from the slowest listing so far"; the baseline is the only listing before the check).
- Report: `blocked` when refused waits are the report's only errors (the check's own listing errors and every other error keep `fail`), leftovers listed or not; the instances after a refused one are still read and the final listing still runs. The chain's `leftErr` stays a plain error (exit 1, summary `fail`): not a `*Blocked`, which `ExitCode` would rank above a joined destroy failure.
- `runner.go`: comment only. The probe's leftover check (`runner.go` `check.Check(dctx, entries)`) reads no retained state, so there is no retry to share there (grep, 2026-10-16).

## Learnings

Class: guidance.
- A budget whose only state is its end time makes "one budget per check" untestable by sharing alone (a new budget with the same end is an equivalent mutant); a reserve raised by the slowest read gives it state across instances, pinned with a slow call on the fake clock.
- An outcome precedence (`blocked` only when alone) needs a mixed-error row, or `refused > 0` passes.
