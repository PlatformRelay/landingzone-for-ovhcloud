## What the test pins (for T004)

- `judgeGoDeps` reads the registry, the Taskfile and the creators' `tasks.md`. For each behavioural check: a Taskfile target → every line of its block but the header, `desc:` and comments is read (so a YAML block scalar is read; a leading `- ` or `cmd:` is dropped; quotes honoured, an unquoted `#` ends the line, `&`, `;`, `|` end an invocation, a redirection and its target are skipped); each `go -C tools test|run|build` in command position is listed with `go list -deps -f '{{.Dir}}' [-test for go test] [-tags …] <packages>` in `tools/`, the packages being every word that is neither a flag nor a known flag's value (`./…` or an import path); each tools-module directory outside `tools/vendor` must be covered (`covered`, 005 T111) by the check's scope or inputs. A go run names one package (the rest are program arguments). A go command of another form, and every go word the test does not read as an invocation (inside a quoted YAML scalar, an argument as in `echo go …` or `env go …`, a redirection target), fails loudly instead of being skipped.
- No target: an entry target (`verify:toolchain`, `test:offline-boundary`; Taskfile.yml header, `trustedTargets` in `tools/cmd/lz-offline/main.go:315`) is skipped; an open creator → planned (logged); a ticked creator → failure naming the check. Creator status: bare id → spec 001's `tasks.md`, `NNN/Tnnn` → spec NNN's, parsed with `checks.ParseTasks`; an id not listed is open (as `creatorDone` in `foundation_ci.go`).
- Cases 3 and 4 run `judgeGoDeps` on a fixture tree (a check with a target, `test:planned` with an open creator, `test:orphan` with a ticked creator and no target, `verify:toolchain` with no target). They pass at T003 by design: the judgement lives in the test, T004 only edits the registry. That they can fail is shown by mutants (*Iterations* 3).

## Learnings

- class: sensor. A test that parses shell commands out of YAML must read every command form (block scalars, quoted scalars, import-path packages, redirections) or fail loud on any `go` word it did not read; a positive-list parser passes vacuously on the forms it skips. Count the tool words seen against the invocations read.
