## What changed

- `deadline.go`: `destroyBudget(run) = max(DefaultDeadline, run)` (data-model's fixed signature; `run <= 0` gives `DefaultDeadline` through `max`). `destroyBudgetSpent(dctx, budget)`: nil while the context lives, else an error naming the budget and the cause, and that what was not destroyed or checked stays for `--cleanup`.
- `chain.go`, `runner.go`: `budget := destroyBudget(deadline)`; `destroyContext(ctx, budget, …)` (still `context.WithoutCancel(ctx)`: detached from the run's cancellation, unchanged). One `dctx` serves the destroys, the trap (chain) and the leftover check, as before. After the leftover check, `destroyBudgetSpent(dctx, budget)` joins into `destroyErr`.
- Seam (tests only, nil in production): `childEnv.started func(ctx, args)`, called by `childEnv.command` before each child is made; set from `Runner.childStarted` (`runner.go`) and `ChainOptions.childStarted` → `laneRunner.childStarted` → `prepare`'s `childEnv` (`chain.go`, `apply.go`). Every tofu child of both cores goes through `childEnv.command` (verified by reading `runner.go` `tofuCmd` and `apply.go` `tofuStreams`, 2026-10-16).
- Not changed: `destroy_budget_seconds` (data-model *Live run record*). `run.json` is written only by `plan`, `apply` and `destroy` (`chain.go` `runSummary`, verified 2026-10-16), none of which has a destroy-on-exit; the chain and the probe core write `summary.json`. Deferred to stage B as a data-model wording question (where the budget is recorded), not added here.

## New tests (this task)

## Learnings

Class: guidance.
- To show which context a child process ran under, observe it where the child is made (one nil-in-production hook on the shared command builder) and compare deadlines exactly against a call that must share the context.
- To pin "fail on `ctx.Err()`", end the context from a seam while every call still answers (`context.WithoutCancel` in the fake), or the test passes on the error a cancelled call returns.
