- `UPDATE_AUTOMERGE`: any `automerge` key, at any depth, whose value is not `false`; any `extends` (presets are not read offline and may auto-merge).
- `UPDATE_RUNTIME_GROUP`: no group, or an empty `groupName`, for `mise.toml`; the labels in force for `mise.toml` (last unnarrowed rule setting labels) lack `needs-entry-revision`; a rule that may apply to some of its dependencies and comes after the group's rule and sets another group, or after the labels' rule and sets labels without the label.

Until then such a pull request passes CI.
- `SCHEMA_VERSION`: a pinned version without its snapshot; a snapshot of a version no lock pins.
- `SCHEMA_RECORD`: each snapshot's `ovh-<v>.command.txt` missing, or its `provider:` not `…/ovh/ovh <v>`, or its `sha256:` not the snapshot's digest.
- Readings of Renovate (believed, UNVERIFIED: no Renovate source or docs read, as R8 says): `packageRules` apply in order and a later match overrides `groupName` and `labels`; `ignorePaths` drops a file when the entry is a substring of its path or a minimatch glob matching it ; `matchFileNames` globs match dotfiles. A pattern using brace sets, classes, extglobs, negation or a `/regex/` is read as matching wherever a match would take updates away (an `ignorePaths` entry, a disabling rule, an override): fail closed. A rule with `enabled: false` is refused even when a later rule re-enables (stricter than Renovate, believed). Finding order is deterministic (keys sorted). A reading that is wrong in the permissive direction is the risk; each is chosen to fail closed.
- Configuration: `.github/renovate.json` is the base fixture's shape (groups `runtime-tools` labelled `needs-entry-revision`, `provider-ovh` with `tests/fixtures/provider-schema/**`, `host-tools`, `go-modules`; the `LZ_OFFLINE_IMAGE` regex manager; `automerge: false`) plus `ignorePaths: ["**/fixtures/**"]`, so Renovate does not bump the fixture pin files (`tests/check/fixtures/**`, `tests/fixtures/**`, `tools/cmd/lz-offline/fixtures`). ## Learnings

Class: guidance.
- A fail-closed reading of another tool's configuration needs a rule for each way that tool can take updates away, not only the obvious key: walk every key (switches nested in managers, update types and rules), treat every pattern the reading cannot evaluate (brace sets, `/regex/`) as matching where a match removes coverage, and judge overrides on both sides of the rule that set the value. Two review rounds each found a new fail-open of this kind.
- An extraction pattern in configuration (a regex manager's match string) is judged by running it on the file it reads, not by searching it for a name.
