## Decision (task, 2026-10-19)

The check cannot ask git which files are tracked inside the entry (the snapshot carries no `.git`), so "every tracked file" is not judgeable there. Options: (A) supply a tracked-file list to the check: a committed inventory goes stale and is a generator by another name (the same reasoning as the R1 rejection of a committed repository-map inventory), and a host-side `git ls-files` is outside the entry; (B, chosen, the coordinator's preferred fix) judge what the snapshot holds and print what was skipped and why; FR-018 is narrowed to "every file the offline snapshot admits" citing this task. `.gitignore` is no longer read: inside the entry it is absent anyway (not an admitted name), so the scan now judges the same files on the host and in the entry under admitted names, and an ignored or negated pattern can no longer hide a file the snapshot carries.

What is not judged, counted in `ADR_SCAN_UNJUDGED=<n> outside_snapshot=<a> skipped_names=<b> run_record=<c> not_regular=<d> binary=<e>` (a skipped directory counts once):
- `outside_snapshot`: a top-level name outside `checks.EntryAdmitted` (on the host: `.git`, `.gitignore`, `.sonarcloud.properties`, local directories; inside the entry: none exist);
- `skipped_names`: a name `checks.EntrySkipped` names below an admitted one (`.terraform`, `.cache`, `.env*`, …), which the snapshot leaves out;
- `run_record`: `pipelines/github/foundation-runs.json`, never read, so it stays out of `docs:check`'s digest (`ci:foundation` compares digests; T041 round 2; the registry assertion `main_test.go:707` is unchanged);
- `not_regular`: a link or other non-regular entry (the snapshot refuses a link, so inside the entry there is none);
- `binary`: a file holding a NUL byte. The scan now reads every judged file even when no ADR is Superseded, so this count does not depend on the ADR set.
