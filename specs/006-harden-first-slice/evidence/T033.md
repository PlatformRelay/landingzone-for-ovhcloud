## Design

`lz-pack prepare -root <dir> -toolchain <dir> -crane <file> -archive <pin name>=<file> …` calls `bundle.Prepare`. The network fetch stays host-side (research R6 *Note*): the command is handed the fetched files. It ports `prepare.py` step for step, with these readings (T030's readings for `PrepareOptions` kept: Archives keyed by pin-table name, `prepare.py`'s toolchain layout, `proof/go-files.sha256`):

1. `Root` must be a real directory and `prepared.json` absent; `bundle/` is reserved as an empty private directory and `staging/` made, both with an exclusive `Mkdir`, so an existing one, even empty, is refused and never merged into. Everything is built under `staging/`; the receipt `prepared.json` (`prepare.py`'s, now listing the provider among the packages) is written with `O_EXCL`, and then `staging/` is renamed over the reservation with `rename(2)` itself, which replaces only an empty directory, so a bundle filled meanwhile is never replaced (round 1). On any refusal `staging/`, the reservation and a receipt written for a refused publish are removed; `staging/`'s directories get owner access back first (projected ones can be read-only) through an `os.Root` opened on it, so a directory swapped for a link changes nothing outside it (round 1), and that root is used only if the directory it opened is the one `Lstat` saw as a real `staging/` (same device and inode), so a link swapped in for `staging/` or a directory above it between the check and the open is refused (round 2).
2. The archives must be exactly the pinned artefacts: each name in `checks.Artifacts` (tools' release archives) or `checks.Packages` (everything else), each a single-link regular file in a real directory with its pinned digest (`VerifyArchive`), every pinned artefact given. What is unpacked or copied is the very bytes that were verified (`readVerified`), not a second read of the path. Every input file (archives, `tofu`, `terramate`, the proof, the launcher) is read by `readInput`: the path must be absolute and clean, every component is opened from `/` with `O_NOFOLLOW` (a directory link anywhere above the file is refused by the kernel, not followed), the file is opened `O_NOFOLLOW|O_NONBLOCK` and judged by the opened descriptor (single-link regular), and at most 256 MiB is read (rounds 1 and 2). Each Go file is copied through the same reader (round 2).
3. The Go tree must hold exactly the files its proof lists, each a single-link regular file with its listed digest; each listed file is copied without following a link and checked again, with the source's owner bits only. `tofu` and `terramate` are copied from the toolchain (single-link regular files, which `prepare.py` did not require); `task` and `tflint` are taken from their verified release archives (one bounded member each; a second `task` member is refused, where `prepare.py` took the last).
4. crane runs as `crane export --platform=linux/amd64 <checks.Image> -` with its own environment (`PATH`, `HOME`, `DOCKER_CONFIG`, `XDG_CACHE_HOME` in a private directory), at most 120 s, 256 MiB of output and 1 MiB of diagnostics; a byte limit ends the command.
5. `Project` (and the image and package projections built on it) streams the tar: at most 50,000 members, 256 MiB expanded, names and link targets of at most 4,096 bytes; a name is normalised and refused if absolute, empty or holding `..`; a duplicate is refused; nothing is written through or over a link (every ancestor checked); a symlink must resolve inside the root by `Admit`'s rule (now one function, `linkInside`, shared with `walk`); a PAX global header (`g`) is counted as a member and skipped, as Python's `tarfile` did (round 1); its payload is not counted in the expanded bytes (Go's reader reports it with size 0) but Go's reader refuses one over 1 MiB (verified 2026-10-18: `/usr/local/go/src/archive/tar/reader.go:101-113`, `format.go:149` `maxSpecialFileSize = 1 << 20`); any other member type is refused, **hard links included, even inside the root** (deferred to here by T030: `prepare.py` refused them, and `lz-pack` refuses a second link to a file, so a bundle holding one could not be packed); links are created after every other member; directory modes are set last, deepest first. Writes go through an `os.Root` opened on the destination, a second layer under these checks. Image `dev/` is left out; a package's `.PKGINFO`, `.melange.yaml` and `.SIGN.*` are skipped and any other top-level dot member (an install script) refuses the package.
The bounds are package variables so tests can lower them (round 1).
6. Projected modes are the image's own bits masked to `0o755`, plus owner read (`prepare.py`'s projection; a CI runner may extract the packed image as another user, so group and other bits of the image are kept). Every file and directory the port writes itself is `0o600` or `0o700`, set exactly whatever the umask. The Go tree is copied with the source's owner bits only (`Perm()&0o700`), where `prepare.py` kept all of `S_IMODE`: the qualified toolchain is owner-only already (believed: the host probe's Go files equal r4-e2's, modes included), and the Go tree is the bundle's own, not the image's, so the reason for keeping the image's group and other bits does not apply (round 1 note, rejected).
7. The mount points the sandbox binds over are made private directories if absent (an existing non-directory is refused); the one provider row is mirrored to `mirror/registry.opentofu.org/ovh/ovh/<name>`; `tofurc` is `prepare.py`'s (filesystem mirror `/mirror`, `include` the provider, no `direct`); `resources.json` holds `checks.Pinned()`, the inventory (`bundle.Inventory`, the walk `Admit` uses) and the launcher's digest.

### The pin table (`checks.Packages`)

Data-model: "One Go table, `checks.Packages` …, extended where `prepare.py:20-68` holds pins it lacks: per artefact `name`, `version`, `url`, `sha256`, `kind` (`archive|apk|provider|image`) … `resources.json` keeps its present shape". Done as:

- `checks.Packages` is now `map[string]checks.Package{Version, URL, SHA256, Kind}` keyed by file name, rows `git-2.56.0-r0.apk` and `libpcre2-8-0-10.49-r1.apk` (`apk`, Wolfi URLs from `prepare.py`'s `PACKAGE_URL`) and, new, `terraform-provider-ovh_2.21.0_linux_amd64.zip` (`provider`, URL and digest from `prepare.py`'s `PROVIDER_URL`/`PROVIDER_SHA`). These were the pins only `prepare.py` held. `prepare.py`'s copies of the go/tofu/terramate archive digests equal `checks.Artifacts` (verified 2026-10-16 by reading both); its `TASK_SHA`/`TFLINT_SHA` equal `checks.Artifacts` too, and their release URLs, comments in `prepare.py`, are now the comment over `checks.Artifacts`.
- Reading (believed, open to review): `archive` and `image` rows are not added. The tools' archive pins already live in `checks.Artifacts` and the image in `checks.Image`, both read by `AdmitPins`; T030's fixed tests put the tool pins in `checks.Artifacts` (`setFixturePin`, the `tool-pin-differs` row). Copying them into `checks.Packages` would make a second table inside `checks`, which FR-014 forbids. The kind set used is therefore `apk|provider`.
- `resources.json` keeps its shape: `checks.Prepared.Packages` is still name → digest (`PackagePins`), and `AdmitPins` compares it exactly with `PackagePins()`.
- Consequence (verified 2026-10-16 by reading `AdmitPins`): every bundle `prepare.py` wrote (r4-e2 among them) records two packages, so an entry built from this tree refuses it with `PIN_PACKAGE`. **The bundle must be re-prepared with `lz-pack prepare` before the next entry is built.** The installed r4-e2 entry is not affected: `verify:toolchain` and the bundle admission run the entry's own compiled code (`Taskfile.yml:3-5`; `RuntimePrepared` and `VerifyRuntime` are called only from `tools/cmd/lz-offline`). The `toolchain.go` comment says so.

# t033-006-image.py: every directory of the rootfs, and every file and link the
# packages' data does not provide, sorted top-down, with the rootfs's modes.
provided = set()
for apk in apks:
    with gzip.open(apk) as stream, tarfile.open(fileobj=stream, mode='r|') as archive:
        for member in archive:
            name = member.name.rstrip('/')
            if '/' not in name and name.startswith('.'):
                continue
            if not member.isdir():
                provided.add(name)
with tarfile.open(out, 'x', format=tarfile.PAX_FORMAT) as archive:
    for parent, directories, files in os.walk(rootfs):
        directories.sort()
        relative = os.path.relpath(parent, rootfs)
        for name in sorted(directories + files):
            member = name if relative == '.' else relative + '/' + name
            if member not in provided:
                add(archive, os.path.join(parent, name), member)  # lstat mode; dir, symlink or file

## Learnings

Class: sensor. A file-safety guard that checks a path and then opens it is a TOCTOU at every component, not only the last: open each component with `O_NOFOLLOW` from `/` (or compare the opened descriptor's identity with the checked one) and route every read of the inputs through that one reader; a mutant on the guard needs a test with a linked ancestor, not only a linked file. A mutant that makes a test hang needs a test timeout in the mutation runner, or it reads as survived.
