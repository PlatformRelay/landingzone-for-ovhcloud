## Decision (task, 2026-10-19)

A name that does not exist cannot be a scope or input entry (`walkScope` fails on a missing path, and a missing input failing the digest is a guard kept). Options: (A) a `presence` list in the registry: a path absent adds nothing to the digest, a present one adds its path and the `Digest` of what it holds, so it appears in the digest the moment it is created, empty or not, file or directory, and later edits to it are bound too; (B, rejected) let a missing input count as absent: it weakens the existing missing-input guard for every check; (C, rejected) digest the root listing: it would include `.git`, `.local` and every host-only name, and change on every commit. Chosen: A. `CheckDigest` appends the presence digest only when the list is non-empty, so other checks' digests are unchanged; `ParseRegistry` holds presence paths to the same clean-relative rule; `presenceDigest` refuses a link at or above the path (also a dangling one) instead of reading it as absent.

Which names: the admitted names absent from the checkout (`profiles`, `policies`, `catalog`, `examples`, `bin`, `lz-offline`, `probe.sh`, `included.yml`), for `docs:check` and for `test:traceability`; for `test:traceability` also `LICENSE`, `NOTICE`, `AGENTS.md`, `terramate.tm.hcl` (the README walk lists every non-hidden top-level name by kind, so a file turned directory would be walked; review round 1) and `.github/renovate.json5` (update-lane probe). Binding a present file or an absent name that only ever appears as a file over-approximates (the walk reads kinds, not contents; strong leg, round 1): safe, and cheaper than a kind-only digest. The list is written by hand and held by a derived test: every `checks.EntryAdmitted` name a check reads must be covered by its scope, inputs or presence (`admittedCovered`), so a new admitted name fails `test:traceability` until the registry follows. The tests themselves read nothing of the tree for this rule but the registry and the run record's directory (review round 1: the first version stat'ed `docs:check`'s entries, `LICENSE` and `.specify` among them, from inside `test:traceability`).

`ADR_SCAN_UNJUDGED` (from T052): its `outside_snapshot` and `skipped_names` counts read names outside the admitted set; they stay outside the digest. They feed one output line, never a finding or the exit status, so they do not decide the verdict the digest binds; on the host they are `.git`, `.local` and other local names, which change with every commit; inside the entry (where the foundation targets run) they are absent (`outside_snapshot=0 skipped_names=0`, gate run below). `run_record` is a name comparison, not a read. `binary` counts files under admitted names, which the inputs cover.

The run record: no foundation target's registry reads cover `pipelines/github/foundation-runs.json` (new `recordOutsideFoundation` over every target of `foundation-source.json`); the docs:check assertion (`main_test.go:719`, formerly `:707`) is unchanged. `pipelines` is covered file by file: every file below it except the record must be covered (`uncoveredFiles`).

## Learnings

- Class: sensor. A read-set pin runs inside the check whose reads it pins: any stat or walk it makes to build a fixture or judge a rule is a read of `test:traceability` too. Lay fixtures from the registry alone, ask the tree only what the rule needs, and re-trace the check after the change (round 1).
- Class: tooling. `strace` around the entry plus `t053-006-reads.py` / `t053-006-cover.py` (outside the repository) gives an `uncovered: N` line per check against the registry; a stat that fails (`ENOENT`) is a presence read, not noise, when the path is under an admitted name (`.github/renovate.json5`).
