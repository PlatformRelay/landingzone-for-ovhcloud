## Task text (tasks.md)

T026 Let the foundation CI check resolve spec-scoped creators in tools/internal/checks/foundation_ci.go and foundation_ci_test.go. Requirements: FR-010; ADRs: 0007, 0008. Depends on: T023. Verify: `task test:foundation-ci`: a test written first shows a target whose registry creator is a spec-scoped key (`005/T055`) of a ticked task in another spec is refused today as `CHECK_NOT_RUNNABLE` (behavioural red), then accepted; an open spec-scoped creator, an unknown spec prefix and a missing task id are still refused; bare spec 001 creators behave as before. Found 2026-10-06 when `test:live-lane` (creator 005/T055, closed) could not join the foundation workflow.

## Design choice: admitted, not required

A closed spec-scoped creator **admits** its argument-free check as a target; it does not make it **required** (`CHECK_OMITTED` stays for spec 001's own checks and T023's). Reason (verified 2026-10-06 against `harness/checks.yaml` and spec 005's ticks): requiring them would make `test:slice` (creator `005/T004`, closed) required today, and `test:slice` is red by design until 005/T012 and not deferrable — the foundation check would go red, and the only ways out would be widening `deferrable` or putting a red target in CI. The task text asks for "accepted", not "required". Counterpoint for the owner: once spec 005's checks are green, requiring them (a scoped `required` set, or a per-spec opt-in) would stop a closed 005 check silently dropping out of CI; not done here (scope, and it is a CI-policy decision).

## Learnings

- class `guidance`: a check that resolves cross-spec keys must also refuse a call that omits the base spec, or its "required" half silently disarms (review found it, not the task text).
- class `guidance`: a usage-gate mutant survives when the input error path exits with the same code — assert the `usage:` prefix, not only exit 2.
- class `guidance`: before making another spec's closed checks *required* by a CI judge, list which of them are red by design (`test:slice` until 005/T012); "admit, don't require" kept the judge green without widening `deferrable`.
