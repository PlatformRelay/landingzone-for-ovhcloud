# T003 — Trusted preparation and offline entry

Status: GREEN locally, 2026-10-04. Requirements: FR-001/C001.1–2; FR-002/C002.1–4.
ADRs: 0007, 0011, 0021. Depends on T002 (test sources in this branch).

## What exists

- `tools/cmd/lz-offline/main.go` — the host entry. It admits the prepared resource bundle
  against a build-time manifest digest, snapshots an explicit allowlist of candidate
  inputs (no-follow, single-link, bounded: 16 MiB per file, 128 MiB total, 10 000 entries,
  depth 64), then starts `bwrap` with new user/pid/ipc/uts/net namespaces, all
  capabilities dropped, a cleared environment, a read-only prepared root, and the
  tools on sealed (`--remount-ro`) tmpfs mount points. Child output is capped at 8 MiB
  and 120 s; the private scratch copy is removed before output is published.
- `tools/internal/checks/offline.go` — the in-sandbox gate. Before Task reads the
  candidate Taskfile it requires a network namespace different from the host's, no
  interface other than `lo`, a read-only root and admission file, and matching
  pinned identities; it then checks the actual `go`, `tofu` and `terramate` versions.
- `tools/internal/checks/toolchain.go` — capture admission: pinned versions, artifact
  digests, image digest and an isolation gate, all checked before invocation.
- `tools/cmd/lz-offline/prepare.py` — builds the resource bundle (image rootfs, pinned
  archives, provider mirror, mirror-only `tofurc`). Host paths come from `LZ_PREP_ROOT`,
  `LZ_TOOLCHAIN_ROOT`, `LZ_CRANE` and `LZ_TASK`.
- `Taskfile.yml` targets `verify:toolchain` and `test:offline-boundary`;
  `harness/capabilities.yaml`; the ovh 2.21.0 provider fixture and lock file.

## Defects found by the first real run (fixed here)

1. The entry asked bwrap to create `/tools/go` and `/tcb/*` on the read-only prepared
   root (`bwrap: Can't mkdir /tools/go: Read-only file system`). Fixed: `/tcb` and
   `/tools` are tmpfs mount points, sealed read-only before the child starts.
2. T002's "isolation-off" positive control ran through the subject entry, so it could
   only pass against the permissive stub. It now runs the probe directly on the host,
   which is what an isolation-off control has to be; the isolated calibration and the
   10 subject cases are unchanged.
3. The boundary suite ran under plain `go test ./...` and failed with `HARNESS_SETUP`.
   It is now behind the `offlineboundary` build tag; the external run still fails hard on
   missing setup.

## Known gaps (not closed by this task)

- The Task binary placed at `/tcb/task` is copied by `prepare.py` without a pinned
  version or digest check at preparation time. Its bytes are bound by the resource
  manifest at runtime, but the input itself is not pinned in `mise.toml`.
- Preparation and the T002 suite are still driven by hand; T023 adds CI.
- Earlier preparation and build rounds (r1–r7, runtime build r1–r2) and their reviews are
  kept as private records outside the repository.
