# T003 — Trusted preparation and offline entry

Status: GREEN locally, 2026-10-04. Requirements: FR-001/C001.1–2; FR-002/C002.1–4.
ADRs: 0007, 0011, 0021. Depends on T002 (test sources in this branch).

## What exists

- `tools/cmd/lz-offline/main.go` — the host entry. It admits the prepared resource bundle
  against a build-time manifest digest, snapshots an explicit allowlist of candidate
  inputs into private host scratch (no-follow, single-link, regular files only; 16 MiB
  per file, 128 MiB total, 10 000 entries counted before exclusions, depth 64, one
  120 s deadline over admission, snapshot and child), then starts `bwrap` with new
  user/pid/ipc/uts/net namespaces, all capabilities dropped and a cleared environment.
  The prepared root, tools, mirror, admission file and the snapshot (`/run/lz/src`) are
  read-only; every writable area (`/tmp`, `/run`, `/home`, `/candidate`) is a private,
  size-bounded tmpfs, so the candidate never writes to host storage and cannot obstruct
  host cleanup. Child output is capped at 8 MiB and published only after cleanup.
- Inside the sandbox, `checks.VerifyRuntime` runs before anything else. `RuntimePrepared`
  requires a network namespace different from the host's, no interface but `lo`, the
  exact mount topology (`ValidateMounts`), an environment containing only launcher-set
  variables (`ValidateEnvironment`) and the pinned identities; only then does it issue
  the `Isolation` value that `Capture` requires. Code outside `checks` cannot construct
  one. The pinned `go`, `tofu`, `terramate` and `task` versions are then executed and
  compared.
- `verify:toolchain` and `test:offline-boundary` run trusted code only: version checks,
  a mirror-only `tofu init -backend=false -lockfile=readonly` of the provider fixture
  embedded in the entry binary, and the strict `ENETUNREACH` probes. The candidate's
  Taskfile is never read for them. Other targets copy the snapshot into `/candidate`
  and run the pinned Task binary on the candidate Taskfile.
- `tools/cmd/lz-offline/prepare.py` builds the resource bundle (image rootfs, pinned
  archives, official Task 3.53.1 archive checked against its published SHA256, provider
  mirror, mirror-only `tofurc`). Host paths come from `LZ_PREP_ROOT`,
  `LZ_TOOLCHAIN_ROOT`, `LZ_CRANE` and `LZ_TASK`.

## Defects found and fixed in this task

1. First real run: the entry asked bwrap to create mount points on the read-only root
   (`bwrap: Can't mkdir /tools/go`). `/tcb` and `/tools` are now tmpfs mount points,
   sealed read-only before the child starts.
2. T002's isolation-off positive control ran through the subject entry, so it could
   only pass against the permissive stub; it now runs the probe directly on the host.
3. The boundary suite ran under plain `go test ./...`; it is behind the
   `offlineboundary` build tag.
4. Independent review, seven findings, all addressed: host-backed writable `/candidate`
   (now bounded tmpfs over a read-only snapshot); caller-supplied isolation string in
   production admission (now an unexported `Isolation` value); runtime gate checked two
   mounts and no environment (now full topology and environment); candidate-controlled
   cleanup obstruction (the candidate no longer writes host storage); qualification
   inferred from candidate Task targets (now trusted code); unpinned Task (now the
   official archive, pinned and version-checked); uncounted excluded entries and no
   snapshot deadline (now counted and covered by the deadline).
5. The environment gate refused bwrap's own `PWD`; it now admits exactly `/candidate`.
6. Second review round, four findings, all addressed: a host tmpfs bound at a scratch
   path passed the type and size check (the entry now records the host's mount devices
   and the gate requires a fresh tmpfs mounted at its root); the deadline could not
   interrupt a stalled filesystem call (admission and snapshot now run under a supervisor
   that returns at the deadline); the local-config sensor depended on the host-marker
   write (now independent, with a positive control); three environment cases tripped
   duplicate-name rejection before their value check (they now replace values, and
   duplicates have their own case).
7. Third review round: APPROVE with two minors, both addressed. The snapshot no longer
   creates parent directories, so a supervised read that resumes after cleanup cannot
   recreate scratch; `/dev` gets the same private-tmpfs provenance check as scratch.
