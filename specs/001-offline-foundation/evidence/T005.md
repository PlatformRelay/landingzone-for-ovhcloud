# T005 — Observation schema and JSON/JUnit adapters

Status: GREEN locally, 2026-10-04. Requirements: FR-003 (C003.1–C003.4), SC-002.
ADRs: 0008, 0019. Depends on T004 (captured streams and RED tests).

## What exists

- `tools/internal/report` — `Evaluate(stream, exitCode)` reads a complete `tofu test -json`
  stream and the exit status of the tofu process that produced it, and returns one
  observation. Tofu's own exit status and summary are inputs, not the verdict. Evaluation has
  three stages:
  1. **Structure** — every line is JSON (a partial last line is `TRUNCATED_STREAM`, any other
     bad line `MALFORMED_STREAM`); known events carry valid payloads (`INVALID_PAYLOAD`: missing
     fields, unknown statuses, negative counts, duplicate run names, an empty `test_cleanup`);
     one version, one abstract, files before their runs, exactly one summary and nothing known
     after it (`LIFECYCLE_ORDER`, `MISSING_VERSION`, `MISSING_SUMMARY`).
  2. **Reconciliation** — every discovered run is reported exactly once and nothing else is;
     each file's status and the summary's counts and status agree with the reported runs
     (`RUN_MISMATCH`).
  3. **Clause guards**, each decided once from the observed runs and events: `ZERO_TESTS`,
     `SKIPPED_RUN` (C003.3); `TESTS_FAILED`, `ERROR_DIAGNOSTIC` (C003.1); `CLEANUP_FAILED`
     (C003.4); `NONZERO_EXIT` and `EMPTY_STREAM` (C003.2).

  Every diagnostic is kept with tofu's complete object (`range`, `snippet`, `difference`,
  `address`, …) and the file and run it followed; failed cleanup resources are kept verbatim.
  Unknown event types and lines without a type are ignored, so a newer tofu adding events does
  not fail a valid stream.
- `schemas/check-report.schema.json` — the observation's JSON schema. A test keeps its
  properties, required fields and reason enum identical to the Go types.
- `tools/cmd/json2junit` — renders the same observation as JUnit XML: one test case per tofu
  run plus an `observation` case that carries every diagnostic and cleanup failure in
  `system-out`, and fails with the reasons when the observation fails. Faults tofu reports as
  success therefore still fail the JUnit view; it exits 1 on a failing observation. Usage:
  capture the stream, then pass that process's exit status (`-exit "$status"`).
- `task test:reports` runs both packages.

## How it was run

| Check | Command | Result |
|---|---|---|
| Unit | `GOPROXY=off go -C tools test ./...` | PASS — see below |
| Through the entry | `lz-offline --candidate <checkout> -- task test:reports` | PASS — pinned Go 1.27.1, no network |

Report tests: the captured passing stream and a synthetic baseline pass; six unusual valid
streams pass (unknown event, typeless log line, CRLF, no final newline, two test files, a
1 MiB warning); diagnostics keep their raw fields and run context, cleanup details are kept and
a warning on a passing run survives; the five captured fault streams fail with their own
reason; 33 isolated controls each fail with exactly the expected reason set, and a check
requires that every one of the 14 reasons has a control where it is the only reason. Schema
tests keep the schema and Go types identical. json2junit tests: runs rendered, four fault
streams fail with reasons and upstream text, warnings on a passing run rendered, malformed
input fails.

### Mutation sensitivity (scratch copies)

Each of the 31 individual `e.fail(Reason…)` call sites in `report.go` was neutralised in
turn: 31/31 turned the suite red. Removing the observation verdict from the JUnit view and its
exit status turned the four fault cases and the malformed case red.

## Review history

- First review (REQUEST_CHANGES, five majors, one minor): runs were not reconciled with
  discovery or the summary; summaries had no lifecycle checks; payloads were not validated;
  diagnostic fields, context, cleanup details and passing-run warnings were dropped; several
  guards were redundant, so removing them left the suite green; the documented `$?` pipeline
  read the wrong exit status. All addressed by the three-stage design above, the isolated
  controls and per-site mutation, and the corrected usage.
- T004's rejection test originally required only "fail with some reason"; it now requires each
  case's exact reason set.

## Known gaps

- The JUnit view runs only on captured fixtures here; wiring it into CI is T023.
- The schema covers the report observation only. Check registry, trace and evidence fields
  arrive with T006/T007.
- Isolated controls are synthetic events in tofu 1.13.0's shapes; the captured streams remain
  the evidence of genuine tool output.
