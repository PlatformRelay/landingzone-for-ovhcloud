# T005 — Observation schema and JSON/JUnit adapters

Status: GREEN locally, 2026-10-04. Requirements: FR-003 (C003.1–C003.4), SC-002.
ADRs: 0008, 0019. Depends on T004 (captured streams and RED tests).

## What exists

- `tools/internal/report` — `Evaluate(stream, exitCode)` reads a complete `tofu test -json`
  stream and returns one observation. Tofu's own exit status and summary are inputs, not the
  verdict: the observation passes only when none of these clauses finds a reason.

  | Reason | Clause | Rule |
  |---|---|---|
  | `EMPTY_STREAM`, `TRUNCATED_STREAM`, `MALFORMED_STREAM` | C003.2 | non-empty, newline-terminated, every line JSON |
  | `MISSING_VERSION`, `MISSING_SUMMARY`, `COUNT_MISMATCH` | C003.2 | version and summary present; discovered runs equal passed+failed+errored+skipped |
  | `NONZERO_EXIT` | C003.2 | the tofu process exited 0 |
  | `ZERO_TESTS`, `SKIPPED_RUN` | C003.3 | at least one run discovered; no run skipped |
  | `TESTS_FAILED`, `ERROR_DIAGNOSTIC` | C003.1 | summary pass with no failures or errors; no error diagnostic |
  | `CLEANUP_FAILED` | C003.4 | no `test_cleanup` failed resources |

  Every upstream diagnostic and run is kept in the observation. Unknown event types are
  ignored, so a newer tofu adding events does not fail a valid stream.
- `schemas/check-report.schema.json` — the observation's JSON schema. A test keeps its
  properties, required fields and reason enum identical to the Go types.
- `tools/cmd/json2junit` — renders the same observation as JUnit XML: one test case per tofu
  run plus an `observation` case that fails with the reasons and diagnostics when the
  observation fails, so faults tofu reports as success still fail the JUnit view. It exits 1
  on a failing observation.
- `task test:reports` runs both packages.

### Mutation sensitivity (scratch copies)

Each of the 12 `fail(Reason…)` rules was removed in turn: every removal turned its own
rejection case red (12/12 killed). Removing the observation verdict from the JUnit view and
its exit status turned the four fault cases and the malformed case red.

T004's rejection test originally required only "fail with some reason"; the cleanup stream
also carries an error diagnostic, so deleting the cleanup rule would have stayed green. The
test now requires each case's own reason and adds derived missing-version, error-diagnostic
and count-mismatch cases.
