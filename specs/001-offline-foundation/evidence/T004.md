# T004 — Pinned tofu report fixtures and report tests

Status: RED recorded, 2026-10-04. Requirements: FR-003 (C003.1–C003.4), SC-002.
ADRs: 0008, 0011. Depends on T003 (capture admission and isolation).

## Fixtures

Provider-free modules in `tests/fixtures/tofu/modules/`, one per case. Streams in
`tests/fixtures/tofu/streams/` were captured with `tests/fixtures/tofu/capture.sh`, which
runs `lz-offline --candidate <checkout> -- task capture:tofu-<case>` against the installed
entry (`<external-task-root>/003-runtime-r2`). The entry verifies pins and isolation before
any Task target runs, and its stdout is the pinned `tofu test -json` stream. Each
`<case>.meta.json` records the command, tofu version, entry exit status and the stream and
module digests.

| Case | Module | tofu 1.13.0 exit | tofu's own summary | Why it is a fixture |
|---|---|---|---|---|
| pass | one passing assertion | 0 | pass, 1 passed | valid control |
| fail | one failing assertion | 1 | fail | failure with an upstream diagnostic (C003.1) |
| zero | no test files | 0 | **pass**, 0 tests | zero tests reported as success (C003.3) |
| skip | erroring run, then a skipped run | 1 | error, 1 skipped | skipped required run (C003.3) |
| cleanup | `terraform_data` whose destroy provisioner fails | 0 | **pass**, 1 passed | cleanup fault reported as success (C003.4) |
| truncated | derived: `pass.jsonl` cut mid final line | — | none | killed run (C003.2) |

The tests derive four more cases from the passing stream: crash exit status 11, missing
summary, empty stream and non-JSON output. These are synthetic and labelled as such.

Two observations shape the adapter: tofu exits 0 and reports `pass` for zero tests and
for a cleanup failure, so neither its exit status nor its summary can be the verdict.

## RED against the permissive stub

`tools/internal/report/report.go` is a compiling stub whose `Evaluate` always returns
pass. `go -C tools test ./internal/report -count=1`:

- PASS: valid passing stream; valid stream with an unknown event type.
- Behavioural RED: counts and tool version not reported; failing stream loses its verdict
  and diagnostic; all nine rejection cases (fail, skip, zero, cleanup, truncated,
  crash-exit, missing-summary, empty, malformed) accepted.

No fixture is fabricated tool output: every stream except the derived ones is the pinned
binary's actual output, and the derived ones are produced from it by a recorded rule.

## Entry change needed for capture

The entry relays the child's stdout and stderr separately under one shared 8 MiB budget,
so the captured stream is not interleaved with Task or tofu stderr. It admits any plain
Task target name (lowercase, digits, `:`, `-`, `_`; at most 64 characters), and the snapshot
allowlist includes `tests/`. Unit tests cover both. The T003 boundary suite and
`verify:toolchain` still pass through the rebuilt entry.
