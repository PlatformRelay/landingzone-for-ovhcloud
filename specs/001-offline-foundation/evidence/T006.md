# T006 — Trace and DoD tests

Status: RED recorded, 2026-10-04. Requirements: FR-004 (C004.1–C004.4), SC-003.
ADRs: 0008, 0019. Depends on T005.

## What the tests define

`tools/internal/checks/traceability_test.go` fixes the contract T007 implements. The stub in
`traceability.go` holds the types and the rule list; its functions return zero values.

- **Parsing** — `ParseSpec` reads `- **FR-nnn**`/`- **SC-nnn**` definitions only, not
  mentions in prose. `ParseTasks` reads each `- [ ] Tnnn` entry: paths from the title (a token
  with `/` or a file extension, brace sets kept literal), requirement ids before `ADRs:`
  (clause lists such as `C002.1–C002.4` ignored), ADR ids, Verify, a docs-only exemption
  (`Verify: exempt — docs-only; <reason>`), `Aggregate ADR rationale:` and Evidence. Zero
  discovered tasks is an error.
- **Trace rules** (C004.1, C004.2, C004.4), each with a control in which it is the only rule
  reported:
  `UNKNOWN_REQUIREMENT`, `UNMAPPED_REQUIREMENT`, `UNREGISTERED_REQUIREMENT`,
  `UNCHECKED_REQUIREMENT`, `UNMAPPED_TASK`, `DUPLICATE_TASK`, `UNKNOWN_ADR`, `UNRELATED_ADR`
  (an ADR not relevant to any of the task's requirements, per the registry),
  `BLANKET_ADR_LIST` (the spec-wide ADR set without a rationale), `INCOMPLETE_RATIONALE`
  (rationale and ADR list differ, or a rationale is blank), `UNKNOWN_CREATOR`,
  `MISSING_PATHS`, `MISSING_VERIFY`, `MISSING_EVIDENCE`, `INVALID_EXEMPTION` (a non-Markdown
  path or no reason). A focused trace, a justified phase aggregate and a docs-only exemption
  are accepted together; a spec-wide list on a focused task reports both blanket and unrelated.
- **Registry** — `harness/checks.yaml` is JSON-compatible YAML decoded strictly: unknown
  fields, duplicate keys, duplicate check ids, unknown kinds, a wrong schema version, trailing
  documents, no checks, and empty, absolute or escaping scopes are refused. Block-style YAML is
  refused: the tools module has no YAML dependency and the sandbox has no module download.
- **DoD** (C004.3, C009.2) — statuses `pass`, `fail`, `blocked`, `not-run`,
  `review-required`, `exempt`. A check is selected when its scope contains the path or lies
  under it. Only evidence that names the check, reports `pass` with discovered tests and no
  failures, and carries the current SHA-256 digest of the check's scope passes. Missing
  evidence and a missing scope are `not-run`; a stale or forged digest is `not-run`
  (`STALE_EVIDENCE`); evidence for another check, zero discovery, a pass with failures, an
  unknown or self-declared `exempt` status fail; an outstanding expert review is
  `review-required`; docs checks are `exempt`. A path with no checks does not pass.
  Freshness is a content digest, not a git revision, because the sandbox snapshot has no
  `.git`. The digest covers relative paths and contents, ignores files outside the scope and
  refuses symlinks.

## How it was run

| Check | Command | Result |
|---|---|---|
| Format, vet | `gofmt -l tools`; `go -C tools vet ./internal/checks` | clean |
| RED | `GOPROXY=off go -C tools test ./internal/checks -run 'TestTraceability\|TestDoD' -count=1 -v` | compiles; 7 of 9 tests and 36 of 36 subtests fail behaviourally |

The two tests that pass on the stub are `TestTraceabilityAccepted` (a checker that finds
nothing accepts a valid trace) and `TestTraceabilityRulesIsolated` (a check on the controls
themselves). Neither counts as evidence until the rejection controls pass too.
