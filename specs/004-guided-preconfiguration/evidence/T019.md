## Choices made here (not fixed by the spec set)

- Signatures (plan.md and data-model fix none): `Diff(current, generated []byte) ([]string, error)` and `Notes(a Answers) []string`. `current` is nil when `stacks/deployments.yaml` is absent (T020 passes nil on a missing file); any non-nil bytes that do not decode, an empty file included, return `*AnswersError{CURRENT_MANIFEST_INVALID, "stacks/deployments.yaml: <decoder error>"}` and no line, so T020 prints it with `ExplainError` (source `configure`, T018). A refusal of the generated bytes returns the decoder's `*stacks.ManifestError` unwrapped (source `generated`); T020 passes Export's output, which the decoder already accepted.
- Line form: data-model gives the line and the mark as two columns; one line carries both, `<±> row <id> (<stage> <tenant>/<env>/<region>): <mark>`, with only the dimensions the row has (`(bootstrap)`, `(tenant-state demo)`). Slots and `external` entries are not shown (the answers write neither; a hand-edited slot row still differs by id).
- `diff: none` is printed when no row is added or removed; otherwise the count line, then the warning line when a row is removed, its count in data-model's literal form (`(1 removed rows)` too).
- Notes read the answers through `derive`, so the defaults Export applies (state ref `STATE`, ref `<TENANT>_<ENV>`, mode `reference`) are the ones named. Each line starts `note: `. Wording follows data-model's *Note* column; three adjustments: the `account.env` note lists the full variable names the task names (`account.env needs LZ_PROJECT_ID_STATE, … (names only; this command never reads the file).`), the state ref first, then each environment's ref once, in answers order; the one-project note says "except the state ref under KD-1" (the state ref is an answer); the mode note names `<tenant>/<env> <mode>` per environment, and "no environment" when there is none (trigger "always").
