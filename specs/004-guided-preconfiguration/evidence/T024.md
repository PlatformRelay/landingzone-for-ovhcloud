## Choices made here (not fixed by the spec set)

- (a) Bound: `MaxCurrentManifestBytes` = 1 MiB (the committed manifest is 2.3 KiB; the answers file's 64 KiB would be tight for a large tenant list). The refusals (symlink as last component, directory, FIFO or other non-regular file, a path under a regular file, more than 1 MiB) reuse `CURRENT_MANIFEST_INVALID` rather than new codes, so the code list of FR-004 and data-model stays as it is; the catalogue sentence now names all four causes and the `Next:` says `stacks:check` names a *decoding* problem (contracts/checks.md table and data-model amended to match; spec.md FR-005 is not edited, its "does not decode" stays true and not exhaustive). The detail is `stacks/deployments.yaml` alone, also for a manifest that does not decode: the decoder's error can quote a value (`stacks/manifest.go`, `UNSUPPORTED_VERSION: apiVersion %q`), verified by the test's precondition. A parent directory that is a symlink (`stacks/` itself) is followed, as for the answers file ("parent directories are the caller's", `ReadAnswers`).
- (b) The tool-defect line is `configure: defect: <CODE> could not be explained. This is a defect of the tool, not of your answers. Next: Report it with the answers file; meanwhile edit `stacks/deployments.yaml` by hand.`, exit 1, without the detail; the sentence and action are the catalogue's tool-defect entry's (one constant, `toolDefectBlame`). A distinct exit status was not added (FR-004: exit 1 for refusals). The `configure: error:` line stays for an error that neither is nor wraps a refusal.
- (c) The ratchet allows, by name, `stacks.DecodeManifest`, `Manifest`, `ManifestError`, `Instance` and `checks.DecodeStrict`, and any `Code*` or `Manifest*` constant parsed from stacks' non-test files (so a new `Code*` constant the catalogue must list does not also need a ratchet edit). A dot import of either package is refused. It sees selectors only: a method called on a returned value (`m.Something()`) is outside it (*Harness gaps*).
- (d) `keyWalker.value` turns a `*json.UnmarshalTypeError` from `json.Decoder.Token` (a number beyond float64) into `INVALID_VALUE` at the value's path, `(document)` at the top level, before the strict decode; the refusal order comment says so.
- (e) `configure:export` takes `ROOT` (default `..`, shell-quoted); the registry row is `task configure:export ROOT="$(mktemp -d)" -- "$PWD/tests/fixtures/answers/sandbox.yaml"` (the answers path absolute, because a relative one is read under `ROOT`). `stacks/deployments.yaml` left the row's inputs: under a temporary root the export no longer reads it. The temporary directory is left in `/tmp` (believed acceptable for a hand-run row; nothing runs it automatically).
