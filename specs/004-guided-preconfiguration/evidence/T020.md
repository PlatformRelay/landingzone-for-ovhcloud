## Choices made here (not fixed by the spec set)

- Signature: `run(args []string, out io.Writer, ops stagingOps) int`; `stagingOps` holds the four operations a test replaces to inject a failure (temporary write, file `fsync`, rename inside the opened `.local/configure`, fsync of that directory's handle); `main` passes the real ones. One output stream, stdout, as `lz-stacks` does. A usage error prints the usage line alone (the `flag` package's own output is discarded).
- The answers path is joined to `-root` when relative (contracts *Commands*); `ReadAnswers` refuses a symlinked last component (T016).
- A missing `stacks/deployments.yaml` is nil to `Diff` (T019's rule); bytes that do not decode come back from `Diff` as `CURRENT_MANIFEST_INVALID` under the `configure` source (T018's rule: never the decoder's error through `ExplainError`). FR-005 says the diff "is skipped"; FR-004 makes every refusal one line and exit 1, and the catalogue's next action is "Fix it first", so the command refuses (one line, exit 1) for `check` and `export`, and prints no notes (believed the intended reading; the review is asked to judge it).
- **Uncoded I/O error (T016/T018 gap).** An error `ExplainError` has no source for (a `ReadAnswers` failure other than missing, symlink, non-regular or oversized, e.g. EACCES or EINVAL; a read error of `stacks/deployments.yaml` other than absence) prints one line `configure: error: <error>` (control characters quoted) and exits 1. It is never printed as a catalogue line, so it never blames the answers' content. A catalogue entry for it would be a contract change (contracts/checks.md, FR-004): proposed under *Decision request*, not made.
- Export prints nothing but the refusal line when the staging write fails (no diff, notes or `configure: ok`): a success line before a `STAGING_*` line would contradict it. On success it prints the check's output (diff, notes, `configure: ok`), then `wrote .local/configure/deployments.yaml` and four `next:` lines (copy, reconcile, generate, check).
- `.local` is created 0700 too (the spec gives its mode for `.local/configure` only). An existing `.local/configure` is tightened when it has any group or other bit (data-model step 2); one without them (0500) is left, and the write then fails as `STAGING_WRITE`.
- Symlinks are refused by `Lstat` before anything is written (data-model step 1). Then (round-1 fix) the repository root, `.local` and `.local/configure` are each opened as an `os.Root` (Go 1.24+; `Rename` and the rest since 1.25; the module pins 1.27), and after each open the name must still be a directory, not a symlink, and `os.SameFile` with the handle opened (`openDir`, `sameDir`): a link swapped in after the check is `STAGING_SYMLINK`, and `os.Root` refuses a link that leaves its parent in any case. Every later step, the `Chmod` (through the directory's handle), the temporary file, the rename and the directory `fsync`, works on the opened directory, never on a path, so a later swap cannot redirect a write. Residual: a swap after the open changes nothing written (the handles stay on the checked directories).
- The temporary file is `.deployments.yaml.tmp-<random>` (`crypto/rand.Text`), created `O_EXCL`, mode 0600, in the opened `.local/configure`; on any failure before the rename it is removed, and a failed removal is named in the `STAGING_WRITE` detail (round-1 fix). Residual: an export killed between the create and the rename (SIGKILL, power loss) leaves that file, 0600 in the 0700 directory and never the copy source; no later run removes it (round-2 note, kept as a known residual).
- `filepath.Abs` of `-root` calls `os.Getwd`, which consults `$PWD` (believed, Go standard library) and uses it only when it names the current directory; the command makes no direct environment read, which is what the source pin checks (round-2 note).

1. Locality: yes, the command's two files, two Taskfile targets plus one package added to `test:configure`, two registry inputs per row, one docs pin.
2. Change surface: ~240 lines of command, ~560 of tests for nine cases and two pins; proportionate to G31's five mutant kinds.

5. Coupling: `lz-configure` imports `configure` only, in-module.
6. Abstraction: `stagingOps` is the one seam, four functions, used by tests only.
7. Debt for green: none.
8. Legibility: the package comment states both verbs, the outputs and the exit codes; `stage` follows data-model's four steps in order.

Easier: an operator gets a checked manifest in staging with one command. Harder: a new output line of `check` changes `cfgExpected`'s order only if it is printed outside the package's `Diff`/`Notes`.
