# Research and decisions: Answers file to deployments.yaml
Refreshed: 2026-10-25 (D127). Read against `main` at `46f5115`.

## R1 Where the code lives
- **Chosen:** `tools/internal/configure` (decode, derive, gate, messages, diff, notes) and
  `tools/cmd/lz-configure` (two verbs: `check`, `export`), in the one tools module.
- **Rejected:** a verb of `lz-stacks`. `lz-stacks` is the generator: its input is the trust boundary
  of every stack (`manifest.go:12-14`). Mixing a convenience input into it widens what a review of
  that boundary must read.
- **Rejected:** a shell or Gum script. The decoder is Go; a script would call it through a binary
  and re-parse its output.
- ADR-0023 names `task configure`. This spec uses `configure:check` and `configure:export`, so the
  read-only and the writing verb are separate targets; `task configure` stays free for D-US4.

## R2 What the answers file saves (the D127 counterpoint, measured)
Leaf values counted with comments removed (each JSON scalar is one value):

| File | Values | Of which instance rows |
| --- | --- | --- |
| `stacks/deployments.yaml` (one tenant) | 41 | 21 |
| `tests/fixtures/manifests/sandbox-two-tenants/deployments.yaml` | 67 | 38 |
| sandbox answers (planned fixture) | 11 | 0 |
| two-tenant answers (planned fixture) | 15 | 0 |

The sandbox answers are `apiVersion`, `kind`, `name`, `org`, `forge`, `state_region`,
`shared_state_project`, and one tenant, environment, region and CIDR. A second tenant adds four.
The rest is derived or defaulted (data-model *Derivation*).

What it does not save: the decisions behind the values (org, forge, region, CIDR) stay the
operator's; the account file still needs one id per ref, written by hand; reconcile still refuses
removals and renames; a fluent maintainer saves little time. The value of the spec for the second
operator is P3, UNVERIFIED until T022.

## R3 Derive rows by rule, not per answer
- **Chosen:** every row follows from the tenants tree (data-model *Derivation*), the rule both
  committed manifests already follow.
- **Rejected:** an answers field per row. It would move the hardest part of the manifest into the
  answers file unchanged.
- Consequence: layouts outside the rule (slots, a region without runtime, custom ids, tenant scope)
  are not expressible; they stay hand-edited (spec *Out of scope*).

## R4 The gate: decoder in-process, `stacks:check` after the copy
- **Chosen:** call `stacks.DecodeManifest` on the generated bytes before any output (FR-003). The
  operator then copies the staging file and runs `stacks:reconcile`, `stacks:generate` and
  `stacks:check`, which judge the candidate tree.
- **Rejected:** run `task stacks:check` from the command. It judges `stacks/` in the candidate
  (`tools/cmd/lz-stacks/main.go` header), not a staging file, and needs the pinned Terramate.
- Value-equality, not `Manifest` equality, is the round-trip test: `Manifest` keeps no CIDR, VLAN id
  or toggle (`manifest.go:107-135`), and Terramate reads those from the file
  (`stacks/_lz/globals.tm.hcl:5`).

## R5 Plain messages
- **Chosen:** one catalogue entry per code (contracts/checks.md *Message catalogue*), keyed by code,
  with a plain sentence and a next action. The decoder's detail already names the tenant,
  environment and region, so the command does not re-implement the cross-row rules to find the
  place. A completeness test lists the decoder's `Code*` constants by parsing
  `tools/internal/stacks/manifest.go`, so a new code without an entry is red.
- **Rejected:** answers-level copies of the cross-row rules (duplicate names, VLANs, shared state).
  They would drift from the decoder.
- Reachable from the derivation: `DUPLICATE_NAME`, `DUPLICATE_VLAN`, `SHARED_STATE_PROJECT`,
  `INVALID_VALUE` (a derived id over 63 characters). The others are unreachable by construction;
  their entries say so and ask for a report.

## R6 Format of the answers file
- **Chosen:** JSON-compatible flow YAML, decoded strictly like the manifest; no new dependency.
- **Rejected for now:** block YAML through a vendored library (005 T034's dependency decision).
- Counterpoint kept: newcomers expect block YAML. The starting file in the how-to is commented line
  by line.

## R7 Where the export lands
- **Default:** `.local/configure/deployments.yaml`, as ADR-0023 *Reviewable output* says. Open owner
  choice in spec *Clarifications*: an in-place write of `stacks/deployments.yaml` behind a flag.
- `.local/` is outside the offline entry's snapshot (`tools/internal/checks/offline.go:43-45`), so
  `configure:check` and `configure:export` on an operator's file run host-side. Both are
  credential-free and network-free by FR-008, like `stacks:reconcile`.

## Kept from the earlier research (still holds, deferred)
Gum offers prompt commands for shell scripts and Huh offers Go forms
([Gum](https://github.com/charmbracelet/gum), [Huh](https://github.com/charmbracelet/huh), inspected
2026-10-01). Neither establishes safe persistence or authorization. A session is application state,
not an executable command, and is revalidated on resume. ADR-0003 selects a scalar naming interface;
the answers file passes `org` through and invents no naming input. These inform D-US4 and D-US5.
