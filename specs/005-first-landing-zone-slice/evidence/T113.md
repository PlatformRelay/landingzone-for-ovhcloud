## Choices

1. **Where the record is read.** The runner owns the run directory, so it reads `observations.json` and hands the bytes to the check; the check owns the record's format, so it parses it and validates the ids. `Recorded` runs on `--cleanup` only (a run hands `Undo` what its own `Observe` saw). Missing file → `Recorded(nil)` (the storage-iam check prints `LZ-LIVE undo no observations.json: deleting by name only (lzprobe-p9-write-<run id>)`); unreadable file or a `Recorded` error → the undo step fails without `Undo` and the root is kept (`keep = true`), so a malformed record never degrades to a silent name-only undo; the operator fixes or removes it and runs `--cleanup` again.
2. **Id format.** `DELETE /v2/iam/policy/{policyId}` takes a `uuid` (kb/api/v2/iam.json, read 2026-10-14: `policyId` `dataType uuid`; `iam.policy.Response.id` `uuid`; verified as schema). The check admits lower-case canonical uuids only, as `live.APIChecker`'s gate does (`apicheck.go:72`); any other `policy_id` refuses the whole record before a request (the gate would also refuse it, so this is defence in depth that keeps the name-path deletes from running on a bad record).
3. **Where the policy's creation time comes from.** The P25 policy is created by the probe root's apply; the check does not see the apply. Options: (a) publish `ovh_iam_policy.p25`'s creation time in `iam_check` (an OpenTofu change to `tests/live/probes/storage-iam/main.tf`, outside the task's named paths, and new `envKeys`); (b) the sandbox admin lists `lzprobe-p25-<run id>` on `GET /v2/iam/policy` (`iam.policy.Response.createdAt`, kb/api/v2/iam.json) just before the read. Chosen (b): inside the named paths, through the existing gated `ListPolicies` call. Its cost: one more admin call per run before the bucket-A read, and the age compares the local clock with OVHcloud's (skew UNVERIFIED; recorded in the note's wording on the run sheet). An age the listing cannot tell (not listed, refused, no `createdAt`) is said in the note and is no finding: the age is context, not an observation.
4. **`createdAt` parsing** is tested on T087's captured v2 policy listing (`tests/fixtures/ovhcloud/captured/20261007T133803Z-aeee/listings/ovh_iam_policy.json`, captured from the sandbox; e.g. `2026-10-01T20:02:44.305461Z`), not a hand-written timestamp. `APIAnswer.CreatedAt` is a map by id rather than a field of `APIPolicy`, so the positional `APIPolicy{…}` literals of existing tests stay valid.
5. **Wording.** The note: `the P25 policy was created <n> s before the read; a refusal is also what a P25 policy not yet in effect would answer, so a refusal does not show the tag condition was evaluated (IAM propagation delay UNVERIFIED)`. A bucket-A finding whose observed answer is a refusal ends with `; a refusal is also what a P25 policy not yet in effect would answer`; an allowed bucket A does not (the policy was in effect).
