- `lz-check deps` (`dependencies.go`): `STAGE_RESOURCE` — any `resource` block in a stage-layer directory (stage root, subdirectory, hidden directory a stage calls, override file; `data` stays allowed; test configuration is test layer). `STAGE_COMPONENT_CALLS` — over every module block of every directory of `stages/tenant-state` (not its tests): a non-relative source (external module, or this repository's address, whose fetched revision is not scanned), a `count`/`for_each`, a call to anything other than the root of `components/state-backend` (a subdirectory of it would skip its naming, protection and policies; round-2 fix) or the stage's own directories, and any target called by more than one module block (so the component, and every stage directory on the way to it, is instantiated at most once). Blocks with the same name in the same directory (an override file merging into the call) count once. (Round-1 fix: the first version counted component calls only, so a stage subdirectory called twice gave two buckets unseen, and admitted repository-address sources.) Scope of (b) is tenant-state only, as decided; another stage calling a component twice stays allowed (row "other stage calls a component twice").
- Envelope pin: `task capture:tenant-state-plan` runs the stage's own unit tests (`tofu test -json -verbose`, mocked provider, mirror-only init) on a scratch copy inside the entry and prints the `test_plan` message of run `published_outputs_match_the_schema`; `capture-tenant-state.sh` stores it with a sidecar (toolchain, entry exit, fixture digest, one digest over every file of the stage, the component and its three modules a plan can read — configuration, `modules/naming/kinds.yaml`, lock files; not Markdown, state files, hidden directories, or module tests; round-1 fix: first version hashed `*.tf`/`*.tftest.hcl` only). `TestOutputsTenantStateStagePlan` reads the plan's root `output_changes` as `tofu output -json` entries (`after` value, `after_sensitive` marker, unknown refused), builds the envelope, validates it under `tenant-state.schema.json`, requires exactly the schema's five published names and no credential string in it, and refuses a stale capture.

## Learnings
- tooling: `tofu test -json -verbose` (1.13.0) emits each plan run's full JSON plan as a `test_plan` message; `output_changes` holds the root outputs only, while `planned_values.outputs` mixes in child-module outputs under bare names (a child `access_key_id` shows `sensitive: false`). Read root outputs from `output_changes`.
- sensor: a stage's real (mocked) plan can be captured through the entry and fed to the envelope builder; every later stage task can pin its schema the same way (`capture:<stage>-plan` + sidecar digest over every file the plan reads).
- guidance: a "one call" rule must count instances per target (callers per directory, (dir, name) keys for override files), require relative sources, and admit only the component root — counting component calls alone misses a helper called twice and a component subdirectory (review r1, r2).
- guidance: call a surviving mutant "equivalent" only after a row shows both versions agree on the input it changes; `component-dir-exact` was not (r2).
- guidance: a staleness digest hashes every file the tool reads (`file()` data such as `kinds.yaml`, lock files), not just configuration by extension (r1).
