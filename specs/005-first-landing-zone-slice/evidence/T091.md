## Task text (tasks.md)
T091 [US5] Stop a chain before any apply when its baseline listing fails, and refuse to destroy a producer whose consumer is still applied, in tools/internal/live/chain.go, test first in tools/internal/live/chain_test.go
- Requirements: FR-009, FR-011; ADRs: 0004, 0008. Depends on: T047.
- Verify: `task test:live-lane`: a chain whose baseline listing errors or is unparseable exits 2 (`blocked`) with no tofu apply and no OVHcloud write (T046's `listing-error` and `listing-unparseable` rows changed to expect no apply, said in the evidence); `destroy -- <producer>` while any consumer of it has a record (applied) is refused before any tofu call with a code naming the consumer, while `destroy -- all` and the chain's reverse-order destroy are unchanged; mutants per clause. Rationale (coordinator 2026-10-08): a run that can only fail must not spend credit, and destroying a producer under an applied consumer orphans the consumer's resources.

## Readings (believed unless marked verified)
1. **Blocked baseline**: a baseline whose listing reports any error (an HTTP error or an unparseable listing; both land in `Report.Errors`, leftovers.go `Check`) ends the chain with `*Blocked{Phase: "baseline"}` (exit 2, contracts/checks.md "2 blocked (missing prerequisite …)") after `baseline.json` and `listings-before/` are written (the record says why). Nothing has been applied, so there is nothing to destroy and no reconciliation to run: the chain returns before the destroy-on-exit and the final listing; the summary (summary.json, the `fail` line, the cost reminder) still ends the run (runLane's defer). "No OVHcloud write" is pinned as: no tofu call at all (tofu is the lane's only resource writer, and init of an S3 backend would touch the state bucket), no object-store put, and every request to the lane's API fake a GET (the OAuth2 token POST aside).
2. **Consumer** = any manifest row with an edge (data or authority) to the producer: destroying either kind of producer orphans the consumer (its input or the identity it runs under is gone). Data-only would be narrower than the rationale. No ephemeral stage is a producer of either kind in today's stage table (stages.go), so the sandbox manifest never meets the refusal; the tests add an edge to the harness manifest.
3. **Applied** = the consumer has a record (`stacks.ReadRecords`, the same records selection reads). A record that does not decode is an error (fail closed, before any tofu call).
4. **Locks**: `destroy -- <producer>` takes the run locks of the producer and of every consumer before reading the records, so a concurrent apply of a consumer cannot slip in between the check and the destroy. For today's manifest the set is unchanged (`tenant-demo`).
5. **Unchanged**: `destroy -- all` is refused by its first retained instance (exit 3 `retained`) before anything else; the chain's destroy-on-exit calls `destroyStack`, which carries no consumer check, so it keeps destroying in reverse run order and continues after a failed destroy (decision 4) even when a consumer's destroy failed and its record stays.
6. Exit and condition: `consumer-applied` (exit 3, a refusal of the run like `producer-selected`); the message names every applied consumer and says to destroy it first.
