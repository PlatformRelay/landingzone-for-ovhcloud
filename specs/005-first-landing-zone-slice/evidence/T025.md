## Decision request (for the coordinator; not blocking T025, blocking for T026's G7 part)
1. `RETAINED_UNPROTECTED` scope for `modules/cloud-project`. The rule (T014) requires a literal `prevent_destroy` on **every** resource of a retained package and refuses `removed` blocks. In this module that also covers `ovh_cloud_project_alerting` (optional) and `ovh_iam_resource_tags`: switching `budget_alert.enabled` from true to false then fails the plan (destroy of a protected instance), and so would a tag-target change (URN is ForceNew). Options: A (Rec.) T026 extends the rule with a per-package resource-type list — for `modules/cloud-project` only `ovh_cloud_project` must carry it (alert and tags stay removable); B put every resource under `prevent_destroy` (alert can then never be switched off by configuration); C move the alert into its own module (plan.md's tree changes).
Note for 1: `ovh_iam_resource_tags` destroy removes only the configured keys and never the project (iam_resource_tags.md *Notes*, verified), so the tags need no `prevent_destroy`; an alert is a separate API object (`/cloud/project/{p}/alerting`). Related proposals (gaps 6, 7): the same T026 scan pins exactly one `ovh_cloud_project` and a literal `deletion_protection = true`.
2. Mode switch adopt → reference. With `count` on the mode, switching an adopted project to reference plans its destroy; `prevent_destroy` fails that plan (safe), but the documented exit needs `removed { from = …ovh_cloud_project.this  lifecycle { destroy = false } }` in the stack or a `tofu state rm`, and `RETAINED_UNPROTECTED` refuses `removed` blocks in the module. Options: A (Rec.) the switch is an operator runbook step (state rm through the live lane, T039's sheet), nothing in code; B allow a `removed` block with `destroy = false` (only) in retained packages.

## Learnings
- tooling: OpenTofu has no `override_during`; `override_resource` values already apply on plan, which makes computed attributes (URN) comparable in plan-only tests of retained resources.
- tooling: `mock_data` for a single nested attribute needs every attribute of the object.
- guidance: a rejection run whose input the provider also refuses (null required attribute, provider enum) proves nothing about the module's own check; pick an input only the module refuses (blank string, zero), and count the rest as equivalent mutants.
- guidance: pin an import target address through `try(…this[0].x, null)` so a moved address (for_each, rename) fails by assertion, not by an evaluation error.
