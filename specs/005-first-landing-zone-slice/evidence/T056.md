## Learnings
- sensor: guard and leak assertions belong in the harness's `run`, so every run — setup, interrupted and refused ones — is judged on its own calls; a check over the whole test history lets an earlier run's plan satisfy a "same run" rule (review r1).
- sensor: a fake of a generated root must require the root's inputs that have no default (here `tenants`), or an implementation that skips the adapter passes (review r1).
- sensor: when a guarded set has several addresses, give each its own destructive row; a row changing all of them passes a set that names only one (review r2).
- guidance: a fake flag parser must accept every spelling the real tool accepts for the dangerous value (`-lock=0`, `TF_CLI_ARGS*`), not only the canonical one (review r2).
- tooling: `mutate.py` copies only `tools/`; tests reading `stacks/`, `schemas/`, `tests/` need a scratch with all four (`t056-mutate.py`, target test checked per mutant).
