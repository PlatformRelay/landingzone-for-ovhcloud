## Reading of "refused identically"

`live.Protect` must stay unchanged, and its control `admit-unknown-action-unretained` admits an unknown action on an address no retained entry covers. So the decoder cannot refuse an unknown action document-wide. Reading taken: the document-level refusals (not JSON, wrong type anywhere in the read fields, no `format_version` 1.x, no `planned_values`, `errored`) are made once, in `planjson.Decode` (sentinels `ErrNotAPlan`, `ErrErrored`), and both callers refuse them; an unknown or missing action is refused by each caller on the change it judges — a covered address for `Protect` (unchanged, its `harmless` allow-list), a managed `ovh_cloud_project_storage` for `PlannedBucketNames` (new, `planjson.KnownActions`). Intended behaviour change for stacks: an `errored` plan, a document that is not a plan (the state, no `format_version`/`planned_values`) and an unknown or missing action on a bucket are now errors (before: names read regardless). `Protect` reads exactly the fields it read before, with the same Go types: `mode`, `type` and the typed `after` are read in a second, separate typed pass whose error is returned only by `Change.Resource` (review round 1: typed into the main struct they made a wrong-typed `mode` refuse documents `Protect` used to admit; review round 2: a raw-field reading changed duplicate-key and skipped-`after` semantics for stacks, so the second pass decodes them exactly as the pre-task stacks struct did — verified against the 79a9317 function, below), and the main struct's `after` is a `json.RawMessage`, which accepts any JSON value. Remaining accepted difference (stricter only, stacks): duplicate `after` keys on a bucket (the old `map` merged them, the raw value keeps the last); OpenTofu marshals from Go structs and cannot emit duplicate keys (believed).

Action vocabulary (`no-op`, `create`, `read`, `update`, `delete`, `forget`): as observed with the pinned OpenTofu 1.13.0 in T063's captures (verified there, 2026-10-06); that this is OpenTofu's complete vocabulary is UNVERIFIED (no OpenTofu JSON-format doc in the local mirror). Fail-closed either way.

## Learnings

Class: guidance, sensor. (1) Moving a guard's decoding into a shared typed struct changes what the guard refuses through fields it never read: keep fields the guard does not read out of the strict pass (here a second typed pass whose error only the other caller sees). (2) "Behaviour unchanged" for a reader includes Go `encoding/json` edge semantics (duplicate keys last-wins, `null` into a string is a no-op, a type error does not stop the decode): pin them by running the pre-task function verbatim on the odd documents. (3) A package that moves into a guard's path must join the `checks.yaml` inputs of every check that runs the guard, not only the one whose tests it adds (gap 1). (4) Mutants that delete a spelling must edit every occurrence (doc comments too), or they survive by design.
