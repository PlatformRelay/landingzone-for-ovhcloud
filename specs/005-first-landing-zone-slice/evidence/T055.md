## Interface added (for T057, T059, T047)

- `Runner` gains `Retained []Retained` (judged by `live.Protect` when `Protect` is nil — production never sets the hook), `Grace` (0: `DefaultGrace` = 2 min, believed), `PlanOnly`. Children: `exec.CommandContext` with `Cancel` = forward the stop signal (the received SIGINT/SIGTERM; SIGINT at the deadline and on SIGHUP), `WaitDelay` = grace (then kill), `Setpgid`, and after a stopped child returns its whole process group is killed (plugins). Every `init` is `init -input=false -lockfile=readonly` (probe roots need a committed `.terraform.lock.hcl`); the saved `.tfplan` is removed when its stack is done. Signals after the destroy-on-exit started are ignored (destroy runs to its own deadline; a kill leaves the probe files for `--cleanup`). The returned error's text is redacted, its chain kept (exit 3 survives).
- `NewRunID`, `RunIDPattern`, `ProbeRoot` (reads `probe.env`, `LZ_PROBE_ROOT`, written 0600 by `files.go` beside `passphrase.env` and deleted with it). Cleanup runs `init` then `destroy`, never plan/apply. A passing run also removes `<id>.tfstate.backup` and the empty run directory.
- `env.go`: `childEnviron(home, vars)` shared by `Command` and the run core (one allowlist).
- `protect.go`: refuses `format_version` not `1.x` and any `deposed` object of a covered address (whatever its actions).
- `lz-live probe --reviewed-sha <sha> <root> [--plan-only] [--deadline <dur>]` | `--cleanup <run-id> [--deadline <dur>]` (flags in any order). After the guard (deviation from `Bind`'s order, review r1: the account must be known to find `account.env`, so `GET /auth/details` runs first, against the API of the credential's own endpoint — `ovh-eu` or `ovh-ca` only — before `Bind` compares endpoint, org and account): probe root resolved (symlinks) and refused (exit 3, condition `checkout`) unless directly under `<checkout>/tests/live/probes/` (also the root read back from `probe.env` on cleanup); `sandbox.env` → credential; `GET /auth/details` → account; `accounts/<account>/account.env` → `live.Bind` (a probe reads no manifest: its org is compared with the binding's own); `LoadExemption`; projects from every `LZ_PROJECT_ID_*` with URN `urn:v1:<eu|ca>:resource:publicCloudProject:<id>`; run record `<checkout>/.local/live/<run-id>/`; authority bootstrap (admin), prefix `lzprobe-`; first stdout line `LZ-LIVE run <run-id> start probe|cleanup <root>`.
- `task live:probe -- <args>` builds `.local/bin/lz-live` from the checkout and runs `lz-live probe <args>` from the checkout root (not from `tools/`, where `go -C tools run` would put the working directory and the guard would refuse).

## Learnings

- sensor: a mutant run's `-run` filter must cover every target test; "SURVIVED" from a test that never ran is a harness result (T055 run 1: `TestProtect` missing).
- sensor: counting signals cannot prove "delivered once": two SIGINTs sent together coalesce. Pin the cause (the child's process group) instead.
- sensor: when production reads the process HOME (`os.UserHomeDir`), a test injecting another home must also set the process HOME, or a "caller's HOME leaks" mutant passes.
- sensor: a fake terminal that never fails hides how a hung-up terminal breaks children: os/exec closes the pipe on the writer's error and the child dies of SIGPIPE. A run's terminal needs a "dead terminal" control.
- sensor: "files kept until cleanup succeeds" needs the case where cleanup cannot succeed (nothing to destroy): a rule that keeps secrets for a recovery path must also say when there is nothing to recover.
- tooling: `t055-mutants.py` (T054's 74 ported + T055's, both packages, scratch copy) and `t055-gates.sh`.
