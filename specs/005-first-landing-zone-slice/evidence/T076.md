## Readings (for the coordinator to validate)

- **Cleanup reads the identity from the root's retained state** with `tofu output -json` (all outputs) and looks up `companion_env`; a root that published nothing (its apply failed before) has no companion, and the cleanup destroys the root only. The start path keeps `tofu output -json companion_env`. That `output -json` prints `{}` for a state without outputs is believed (tofu behaviour), UNVERIFIED for 1.13.
- **The credential file goes on every way out**, a failed run included (T075 pins it); a cleanup re-creates it from the root's state, binds again, and removes it after the destroys. So no probe secret lies on disk between a failed run and its cleanup.
- **"Every published identity"** = every `<prefix>CLIENT_ID`/`<prefix>client_id` in `companion_env` with its `<prefix>CLIENT_SECRET`/`client_secret` (storage-iam: `OVH_CLIENT_*` and `TF_VAR_p25_client_*`). The default pair is required; half a pair, or an empty half, fails the run before any companion child (the root is still destroyed). The S3 keys (`AWS_*`) are not an OVHcloud API identity and are not bound (they are scoped by the bucket policy storage-iam creates).
- **Binding uses the values read back from `companion.env`**, i.e. what the companion gets, and happens on the start and on the cleanup.
- **On a cleanup a failed companion destroy or binding still lets the root's destroy run** (as T075 decided for the start: the identity must not outlive the run); the companion's leftovers are then the leftover check's.
- **One guard for plan-only**: `Execute` runs the companion only when not plan-only; `Probe` builds the companion stage whenever `companion/` exists.
