## Choices

1. **Hand-over trigger** (verified 2026-10-12, read `bootstrap.go:586-617`): printed when `admin` is `unchanged` and `recordAdmin` writes ids `account.env` did not already hold — the run that adopts an admin it did not create. R13 says "the first `bootstrap:account` run … prints"; a re-run with the ids recorded stays quiet, and a `--fresh-account` run that creates the admin (`ran`) never prints it, since no other config owns that admin. If the owner loses the first run's output, removing `LZ_ADMIN_CLIENT_ID` from `account.env` makes the next run print it again (stated here, not printed). Accepted false positive (strong review leg r1, verified by reading `createAdmin`): a `--fresh-account` run that created the admin but failed to write `account.env` makes the next run print the hand-over; its "if a one-off config created it … after tofu state list shows" wording keeps that advisory, and no cheaper trigger tells the two cases apart (both leave no ids recorded).
2. **Hand-over names** (believed): the runner cannot know the one-off config's directory or addresses. The lines name `~/.config/ovh-lz/bootstrap/` and the addresses `ovh_me_api_oauth2_client.lz_sandbox_admin` and `ovh_iam_policy.lz_sandbox_admin` (those T044 found there, evidence/T044.md row 5) as a hint, and tell the owner to confirm them with `tofu state list` first and to skip the step when no such config exists. Nothing secret: fixed text only.
3. **State-object keys and bucket** (verified, read `credentials.go:76-116`, `observe.go:696-716`): the check reads `in.StateBucket`/`in.StateKey` with the applied stack's own S3 keys (the authority's state file — `accounts/<a>/state.env` for the bootstrap-authority stacks, the tenant's for tenant stacks), as the L7 collector does; the task's "account bucket with state.env's S3 keys" is that case for the account stacks. Stacks without the `s3` backend are skipped. `lz-live apply` is unchanged (task names the chain only).
4. **Seam**: `ChainOptions.S3HTTP` (nil: the default client), set by `lz-live` from `deps.S3HTTP` like the state store's.

8. Legibility: yes; the check is one function with one comment.
