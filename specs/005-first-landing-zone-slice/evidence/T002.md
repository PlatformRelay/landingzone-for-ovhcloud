## What changed

- `traceability.go`: `scope(spec, reg)` gives each trace only its own keys (spec 001 / empty spec: unprefixed; spec NNN: `NNN/…`, prefix stripped). Every check stays registered, so running another spec's check is `UNRELATED_CHECK`, not `UNKNOWN_CHECK`; another spec's creator is not judged. `SpecChecks` counts a spec's checks (own creator or own requirement). `ParseRegistry` refuses keys no spec can own (`REGISTRY_KEY`: malformed id, `001/` prefix), which settles T001's open nit on `001/` keys. `ParseSpec` also reads `- **FR-0NN Name** —`. The go-test grammar accepts flags before the packages (`go test -tags offlinetools ./internal/checks -run …`, spec 005 T003/T052…): flags, packages, flags; same flag allow-list and value rules.
- `main.go`: `Trace.Spec` = leading three digits of the directory's base name; an unnumbered directory exits 2 `SPEC_NUMBER` instead of tracing as spec 001; `checks=` is the per-spec count.
- `Taskfile.yml`: `check:specs` loops over `CLI_ARGS`, default `specs/001-offline-foundation specs/005-first-landing-zone-slice`, so the argument-free CI run (`ci:foundation` target list) traces both specs.
- `harness/checks.yaml`: 19 `005/` requirements; ADR lists = union of the ADRs listed by the spec 005 tasks naming the requirement, excluding the aggregate exit task T051, plus ADR-0010 on FR-002 (cited by the spec). New planned checks, requirements taken from the V-check table in `contracts/checks.md`: `test:unit` (V001+V002), `test:slice` (V002), `test:outputs` (V004), `test:stacks` (V005+V006), `stacks:check`, `stacks:reconcile`, `stacks:generate` (V005), `test:stack-plans`, `stacks:order` (V006), `test:exchange` (V012), `test:bootstrap` (V008), `test:live-lane` (V007), `live:probe` (probe contracts), `bootstrap:account` (V009), `live:chain` (V010).
