1. **`test:live-lane` reads far more than its inputs name.** Traced (Choice 1): `stacks`, `stages`, `components`, `modules`, `schemas/outputs`, `mise.toml`, `tests/fixtures/{outputs,tofu-probes}`, `tests/live/{chain,probes}` besides the `tests/fixtures/ovhcloud` added here; its `lz-check unit` commands read `tests/live/probes/*` and the modules they call. Only `tests/fixtures/ovhcloud` was in this task's dispatch. Proposed task: widen `test:live-lane`'s inputs to that list, with a row in `TestRegistryInputsCoverReads`.
2. **The CLI pin's lists are hand-copied from a trace.** A test that starts reading a new tree is not caught until someone traces again; the `test:outputs` row reads `stagePlans` and is the exception. A standing sensor would be a scripted trace in a host target; not proposed now (strace in the entry conflicts with the 120 s limit).
3. **Go import closure not in inputs** (the strong review leg, round 1, verified 2026-10-14 with `go list -test -deps`): `test:outputs` and `test:stack-plans` compile `tools/internal/stacks` with `tools/internal/checks`, `planjson` and `report`, which their inputs only partly name. Selection is unaffected (every `tools/` change selects the full suite, `SHARED_TOOL`, T109); only the digest misses such a change. The same holds for other checks (e.g. `test:stacks` omits `report`); this task traced reads outside `tools/`. Proposed task: derive each Go check's `tools/` inputs from `go list -deps` and pin them.
4. **`test:traceability` does not name the registry in its inputs**, although `TestSpecsRealTree` (pre-existing) and now `TestRegistryInputsCoverReads` read it; a registry edit selects the full suite (`SHARED_TOOL`), so only its digest misses the change. ## Learnings

- Class: tooling. `strace -f -s 4096` on the entry run lists what a target reads (attribute by path: the sandbox's pid namespace hides the process tree; strings are cut at 32 bytes without `-s`); `test:live-lane` exceeds the 120 s limit under strace, trace its Go tests on the host. Scripts: `~/.local/share/ovh-lz/review/t111-trace.sh`, `t111-reads.py`.
- Class: guidance. A registry pin must not read trees its own check does not name; put it beside the data it checks, under the check it pins, and read the existing list (`stagePlans`) instead of recomputing it.
