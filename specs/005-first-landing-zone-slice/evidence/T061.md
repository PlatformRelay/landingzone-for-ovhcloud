## Design (verified by reading, 2026-10-07)
- One KD-3 binding path, shared by both sides: `stacks.BoundAccount.Binding(ref)` (unknown endpoint or unresolved/empty ref → `unbound-project`), `stacks.InstanceBinding(m, id, acct)` (the producer's own manifest tenant/environment, never one an artefact or output names), `stacks.ExpectationOf(m, id, acct)` (instance id, stage, and the binding for a `project` producer). A producer is a manifest row or a `spec.external` entry (review round 1); `Manifest.Row(id)` is rows only (consumers, publishing). The throw-away had three copies of the tenant/environment lookup and a second, binding-less `ValidateEnvelope` call in the publisher; both gone.
- Artefact bucket: one naming rule, `stateBucket(org, tenant, stage)` in `manifest.go`, used by the decoder for `StateBucket` and by `ArtifactBucket` (the local-state bootstrap → account bucket) (review round 1, Opus note).
- Adapter: consumer row → per data edge `producerInput` (expectation, bucket, `Get`; `fs.ErrNotExist` → `ErrBlocked` naming the producer; `ValidateEnvelope`; `{"<stage_snake>": env.Values}` from the validated envelope, not a second lenient decode) → `resolvedInput` → `writeInputs` only after every check. `writeInputs` refuses a non-empty `Dir`, writes the set (0600) into a private temporary sibling and renames it into place, so `Dir` holds the whole set or nothing and never an earlier run's file (review round 1).
- Publisher: `Manifest.Row` (an unknown or `spec.external` instance is refused, named) → `ExpectationOf` → `BuildEnvelope` (sensitive entries dropped, unmarked/secret-named refused) → `ValidateEnvelope` with the producer's expectation → for `runtime`, `scope.project_id` = `InstanceBinding` id → bucket → the one `Put` → sha256 of the written bytes.
- `BoundAccountFromEnv`: `OVH_ENDPOINT` required; keys iterated sorted (deterministic first refusal); ref `^[A-Z][A-Z0-9_]*$`, id `^[0-9a-f]{32}$`; refusals name the variable, never the value. It fails closed on any malformed `LZ_PROJECT_ID_*`, used or not (T060 reading 9 pins this; Opus note accepted, see *Review*).
- `WriteRecord`: id must match the manifest instance-id pattern `^[a-z][a-z0-9-]{2,62}$` (schemas/deployments.schema.json) before anything is written.
- Multi-environment tenant (decision 1, option A): `account-governance`'s resolved input refuses a tenant without exactly one environment with the new reason `tenant-environments` (`stacks.ReasonTenantEnvironments`); a `project` of such a tenant still resolves its own environment. data-model *Resolved-reference input* states it as a known slice limit; step 4 now reads "sha256 of each consumed `outputs.json` (FR-009)" (decision 2).
- No new import edge: `internal/live` → `internal/stacks` exists since T060. `TestAuthoringFlowReachesNoCredentialCode` (stacks may not name `OVH_` strings) held and caught one refusal text in round 1 (iteration 6).

## Learnings
Class: sensor.
1. A throw-away from a test task is a starting point, not reviewed code: review it as new (three copies of the binding lookup and a second binding-less validate call were in it).
2. "Producer" in a manifest includes `spec.external` entries; anything resolving an edge's producer must search both, and anything that applies or publishes must search rows only.
3. A writer that must leave "all or nothing" writes into a temporary sibling and renames, and refuses a non-empty target: per-file cleanup cannot undo an overwrite.
4. `TestAuthoringFlowReachesNoCredentialCode` forbids `OVH_`-named strings anywhere in `internal/stacks`, refusal texts included: name "the API endpoint", not the variable.
5. Host runs of `-tags offlinetools` exchange tests need `LZ_TOFU`/`LZ_TERRAMATE` pointing at the pinned mise installs (PATH has older tofu/terramate); `t060-run.sh` sets them.
6. An emptiness check before a rename onto a directory is an equivalent mutant (the rename refuses anyway): keep it for the message, do not count it as a guard.
