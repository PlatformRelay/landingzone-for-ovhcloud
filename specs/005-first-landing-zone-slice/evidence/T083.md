## Task text (tasks.md)

T083 Write read-only API-client leftover-listing tests in tools/internal/live/leftovers_api_test.go. Requirements: FR-011, FR-013; ADRs: 0008, 0024. Depends on: T009, T055. Verify: `go -C tools test ./internal/live -run TestLeftoversAPI -count=1`: the leftover check lists every matrix kind through lz-live's own signed API client (the credential the run already binds), GET only — any other method is refused before a request; pagination followed; a listing error, a non-2xx status and a truncated body are reported as errors, never as zero leftovers; no `ovhcloud` process is started. Today the check shells out to `ovhcloud api get`, which ovhcloud 0.15.0 does not have (P18 refuted, evidence/T009.md): behavioural red.

## Harness gaps

- Entry wiring: `tools/cmd/lz-live/probe.go` still builds the check with `Ovhcloud: LookPath("ovhcloud")`
  and no `API`/`Cred`; T083's file is in `internal/live`, so no control here sees the entry. T084
  wires it; a `cmd/lz-live` row (fake API via `deps.API`, fake `ovhcloud` on PATH) is proposed for T084.
- v1 pagination: whether v1 listings answer `X-Pagination-Cursor-Next` is UNVERIFIED; the fake
  applies the v2 protocol to every path. T084's captured listings qualify it.
- Which credential: no row pins that the entry hands the check the credential the run binds. For a
  probe that is the authority credential (`sandbox.env`, bound by `live.Bind` in probe.go, also
  `Runner.Creds`), not the probe/companion credential, whose file runner.go removes before the
  check runs. Proposed T084 row: `lz-live probe` against the fake API (`deps.API`) — the token
  request of the leftover listing carries the `sandbox.env` client id (review r1, Opus W2).
- Listed ids in child paths (review r2, Opus note): ids and URNs from listings become path segments
  (identity URNs hold `/`); no row pins escaping. Proposed T084 row: an id holding `/` or `?` is
  escaped or refused, never re-routes the GET.
- A cursor that never ends (review r2, Opus note): `lister.all` (T055) follows next cursors until
  the context ends; only the fake's 500-call cap turns it into an error in tests. Proposed T084
  row: the same next cursor repeated, or a page bound, gives an error naming the listing.
- An answer over the client's size limit: no row (the limit is T084's choice). A silently cut
  answer usually fails to parse, but not always (a complete value followed by whitespace still
  parses once cut): T084 should treat an answer over the limit as an error, with a row.
- "Signed" in the task text: the run binds an OAuth2 client-credentials service account, so the
  client authenticates with the bearer token of that grant (binding.go), not an AK/AS signature
  (research R12/R13). Read as such; no root key is involved.

## Learnings

- class `sensor`: an "X is never started" assertion on a direct call can be vacuous when the code
  path needs runner state to start X; put it at the run level and also catch a bare-name start
  (the fake logs into its working directory).
- class `sensor`: fault bodies should be well-formed empty listings (so an implementation that
  ignores the failure reports zero leftovers) and some should echo the credential (so a body in an
  error is caught); a truncated answer must hold a complete JSON value (so a one-value decoder
  passes it and is caught).
- class `sensor`: a "nothing configured" row must make any request fail the test (failing
  transport), or a fallback to a default endpoint sends the test credential to the real API.
