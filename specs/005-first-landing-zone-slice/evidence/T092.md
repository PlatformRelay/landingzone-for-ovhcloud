## Readings (sources read 2026-10-08)
1. ADR-0013 *Writing rules* and *Anti-rot gates*: `references:` is a list of repository `path` plus that file's full git blob id, or `references: []`; `last_verified:` is the commit the reviewer checked against, informational only; a page is stale when a recorded blob id differs from the path's blob at HEAD or the path is gone.
2. `verified_against: { tofu, ovh }` (also ADR-0013) is **not** in this task's Verify line; it is left out (gap 1).
3. Blob ids are computed natively (`sha1("blob <size>\0" + content)`, the git object format; the repository is `sha1`, verified `git rev-parse --show-object-format`, no `.gitattributes`), so the check needs no git and no `.git` inside the entry or CI. It hashes the file on disk: on a clean checkout (CI, the entry's candidate) that equals `git rev-parse HEAD:<path>`; on a dirty tree it is stricter (an uncommitted edit already reads stale). Vectors pinned from git itself: `git hash-object` of `hello\n` = `ce013625030ba8dba906f756967f9e9ca394464a`, of the empty file = `e69de29bb2d1d6434b8b29ae775ad8c2e48c5391` (verified on the host, 2026-10-08).
4. Link, anchor, `task`-target and 32-hex logic ported from `~/.local/share/ovh-lz/review/t050-doccheck.py` (T050 gap 1). Its `lz-live` flag rule is page-specific and is not ported. Additions over the script: links and headings inside fenced code are ignored, inline code spans hold no links, reference-style links (`[x]: path`) are judged, duplicate headings get GitHub's `-1` suffix, `<a id|name>` anchors count, a leading `/` is the repository root, a link leaving the repository is broken.
5. Rule scope (reading of "ADRs excepted, they are history"): ADRs are exempt from the header **and** from the `task`-target rule — they name designed-but-unbuilt targets (`task new:module`, `task snap:update`, `task deploy`; verified by a pre-scan, `~/.local/share/ovh-lz/review/t092-scan.py`, 2026-10-08). Links, anchors and the 32-hex rule apply to ADRs too; they pass today unchanged.
6. `task` targets: a namespaced target (`task live:plan`) is judged anywhere; a bare one (`task lint`) only inside code (a span or a fenced block), since "this task covers" is English. A target followed by `:`, `<` or `{` is a placeholder (`task capture:<stage>-plan`) and not judged.

## Learnings
- class `tooling`: the offline entry admits an input allowlist, not the repository: any check that reads files (docs links, references) sees only `Taskfile.yml`, `mise.toml`, `.github`, `pipelines`, `tools`, `tests`, `harness`, `specs`, `docs`, `modules`, … — run a new file-reading check through the entry before trusting a host run (decision request 1).
- class `guidance`: a page now goes stale when a referenced file changes: tasks editing `tools/cmd/lz-live/{main,lane}.go`, `tools/internal/live/{apply,bootstrap,chain,observe}.go`, `stacks/deployments.yaml`, `mise.toml`, `tests/live/probes/README.md`, `tools/cmd/lz-offline/main.go` or `specs/004-guided-preconfiguration/spec.md` must re-check the page that cites them and update its blob id (`git hash-object <path>`) and `last_verified` in the same change, or `docs:check` (a CI target) goes red.
- class `sensor`: the CI source gained `docs:check`; `ci:foundation` needs `foundation-runs.json` re-recorded for 16 targets (as after T026).
- class `guidance`: a Markdown scanner reviewed against CommonMark found 12 false-pass forms over two rounds (titles, fence length/kind, footnotes, encoded fragments, symlinked directories, slug collisions): write the CommonMark edge controls up front for any future Markdown rule.
