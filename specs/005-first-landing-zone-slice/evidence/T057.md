## Learnings
- sensor: a fake must fail where the real tool fails — T056's fake answered `state list` without a state file with exit 0, so every first run of a correct-looking implementation would have failed live (Opus r1; checked against the host's tofu). When a fake models a CLI, probe the real binary for its error cases, not only its happy path.
- sensor: match a tool's error per diagnostic (split on `Error:`), whitespace collapsed and case folded; substring checks over a whole stderr combine unrelated diagnostics (r2).
- guidance: "delete what this run created" needs the run's own plan as evidence (the plan created the address, the state did not hold it, exactly one new object appeared); a before/after listing alone attributes another run's object (r1, r2).
- guidance: a refusal's recovery text must be checked against every later phase's own refusals (the `org` advice ran into identify's `org` refusal; the passphrase advice ignored the remote states).
- tooling: `t056-mutate.py` takes the worktree itself as `<impl>`; merge every round's mutants into one final-tree run (`t057-mutants-final.py`) so rewritten lines are not counted as killed from an earlier tree.
