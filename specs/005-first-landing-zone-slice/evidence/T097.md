## Is any other action needed to delete a bucket that holds objects?

- `DELETE /cloud/project/{serviceName}/region/{regionName}/storage/{name}` requires
  `publicCloudProject:apiovh:region/storage/delete` (`kb/api/v1/cloud.json:58859`, action at
  `:58903`); already allowed. Verified 2026-10-10.
- Listing a bucket's objects, `GET …/storage/{name}/object`, requires
  `publicCloudProject:apiovh:region/storage/object/get` (`cloud.json:59465`, action at `:59557`); the
  same action guards `GET …/object/{key}`. This is the action the live 403 names. Verified 2026-10-10.
- Removing objects: `POST …/storage/{name}/bulkDeleteObjects` requires
  `region/storage/bulkDeleteObjects` (`cloud.json:59095`), already allowed;
  `DELETE …/object/{key}` requires `region/storage/object/delete` (`:59618`) and
  `DELETE …/object/{key}/version/{versionId}` requires `region/storage/object/version/delete`
  (`:60282`), neither allowed. Verified 2026-10-10.
- The provider "will try to remove all objects it contains beforehand"
  (`kb/mirror/terraform-provider-ovh/docs/resources/cloud_project_storage.md:10`). Which call it uses
  (bulk, per object or per version) is not in the docs and the provider source is not in the kb:
  **UNVERIFIED**. The companion's P9 bucket holds no object when it is destroyed (the tenant writes
  none; `companion/main.tf`), so run 10 shows only that the provider lists objects before the
  delete, not how it removes them.
- Conclusion: only `region/storage/object/get` is supported by evidence. `object/delete` and
  `object/version/delete` are not added (R6: added only on an observed denial); the next live
  storage-iam run on an empty bucket proves the grant, and a runtime bucket that holds objects is
  the case that would show a further denial (P14).
- Side effect (review note, verified 2026-10-10 in the kb): the grant holds on the project URN
  (KD-1), so a tenant deployer can now list object keys and read object metadata (key, size, etag,
  versionId, dates; no content: `cloud.StorageObjectList`/`cloud.StorageObject`,
  `cloud.json:68782,68540`) in every bucket of the shared project, state buckets and other tenants'
  buckets included. R6 now says so. Accepting it is the coordinator's/owner's call alongside KD-1;
  the alternative (no grant) leaves tenants unable to destroy their own buckets.
