T052 Write host-guard, child-environment and account-binding tests in tools/internal/live/{guard,env,binding}_test.go with fake git and API fixtures in tools/internal/live/testdata/. Requirements: FR-010, FR-011, SC-005; ADRs: 0008, 0009, 0019. Depends on: 001/T009. The fake API enforces each credential's policy actions (research R13 *Account binding*): `GET /me` answers 403 without `account:apiovh:me/get`, `GET /auth/details` needs no IAM action; an admin-class, a platform-deployer-class and a tenant-deployer-class credential, each holding exactly its policy from research R6, all bind; a binding implementation that calls `GET /me` is behavioural red for both deployer classes. ## Interface the tests pin (for T053)

- `live.Host{Dir, ReviewedSHA, LiveEnv, OfflineMarker, Getenv, Git}` with `Check() error`; every host fact injected (production fills `/tcb`, `~/.config/ovh-lz/live.env`, `os.Getenv`, `git`). A refusal is `*live.Refusal{Condition, Detail}`; `live.ExitCode(err)` is 0 / 3 (`RefusalExit`) / 1. Conditions: `offline`, `live-env`, `checkout`, `worktree`, `dirty`, `head`, `origin` (guard); `account`, `endpoint`, `org` (binding). Each refusal row fails exactly one condition and asserts that condition (the symlink-to-linked-worktree row accepts `checkout` or `worktree`).
- `live.Guarded(verb)`: true for exactly `bootstrap probe plan apply destroy chain`; false for `reconcile`, `generate`, `stacks:*`, empty, `help`, `Plan`. `live.Run(verb, host, next)`: for a guarded verb the guard completes (all git calls done) before `next` (the credential loader) runs, and a refusal never runs `next`; an unguarded verb runs `next` without touching git, even on a host the guard would refuse.
- Canonicalisation: the working directory is symlink-resolved and compared with `LZ_OWNER_CHECKOUT` as written (spec FR-011: "canonical (symlink-resolved) checkout equals the owner's main checkout named in live.env"). Row `symlink-at-owner-path`: the owner path has become a symlink to another clean clone → refused `checkout`, so T053 must not canonicalise the `live.env` value as well. `main checkout via symlink` (a symlink to the owner checkout) is admitted.
- Git commands the fake models (research R11): `rev-parse` with `--git-dir`, `--absolute-git-dir`, `--git-common-dir`, `--path-format=absolute`, `HEAD`, `--verify`; `status` with `--porcelain[=v1]`/`-s`, `--ignored`, `-uno`/`--untracked-files=…`, `-z`; `merge-base --is-ancestor <sha|HEAD> origin/main`; global `-C`, `-c`, `--no-pager`, `--no-optional-locks`. Anything else exits 128, which must read as a refusal (row `git-fails`: no scenario, every call exits 128 → refused with any git-backed condition): T053 using another command (e.g. `rev-list`) extends the fake in its own diff, recorded there. Fake output modelled on host git 2.53.0 (verified 2026-10-06 with `~/.local/share/ovh-lz/review/t052-gitprobe.sh` in temp repos: main checkout prints `.git`/`.git`, linked worktree and a symlink to it print absolute `…/.git/worktrees/wt` and `…/.git`, ignored files appear only with `--ignored`, `-uno` drops `??`, `merge-base --is-ancestor` exits 0/1/128). The fake also models `status.showUntrackedFiles=no` from the user's git config (scenario `show_untracked_config`): plain `status --porcelain` then hides `??` lines, `--untracked-files=…` shows them (verified with host git 2.53.0, `t052-gitprobe2.sh`, 2026-10-06); row `dirty-untracked-hidden-by-config` therefore forces T053 to pass an explicit untracked mode (or neutralise the user's config). `merge-base` exits 1 for a known non-ancestor (scenario `known`), 128 for an unknown name.
- `live.Command(authority, creds, name, args...) *exec.Cmd`: the child's environment holds PATH, HOME (non-empty) and exactly the authority's `creds` values; every child key is PATH, HOME, PWD (os/exec), a `TF_*` key lz-live sets itself, or one of the authority's (an allowlist, so a prefix-filtered copy of the caller's environment fails); no value of the caller's environment reaches it under any name (15 ambient variables, all valued `ambient-*`: `OVH_ENDPOINT`, `OVH_CLIENT_ID`, `OVH_CLIENT_SECRET`, `OVH_APPLICATION_KEY/SECRET`, `OVH_CONSUMER_KEY`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`, `AWS_PROFILE`, `TF_CLI_ARGS`, `TF_VAR_state_passphrase`, `OS_PASSWORD`, `SSH_AUTH_SOCK`, a canary). Checked on a real child process (the test binary), for all three authorities.
- `live.API{TokenURL, BaseURL, HTTP}` with `Account(ctx, Credential) (string, error)`; `live.Bind(ctx, api, Credential, Binding, manifestOrg) error`. OAuth2 client-credentials token (form or basic auth, POST, nothing in the query) then `GET <base>/auth/details` with the bearer token. Refusals: account ≠ `account.env` (admin of another account; tenant deployer against another binding) → `account`; manifest `org` ≠ bound → `org`; credential endpoint ≠ bound (data-model: "account id, endpoint or org disagrees") → `endpoint`; a rejected credential → any non-nil error. No binding path ever calls `GET /me`, not even as a fallback after its 403 (`assertNoMe` on every bind and refusal row).
- Fake API (`newFakeAPI`): enforces each credential's policy from `testdata/api/credentials.json` — `GET /me` needs `account:apiovh:me/get` (`kb/api/v1/me.json`, `iamActions` required: verified 2026-10-06), `GET /auth/details` needs none (`kb/api/v1/auth.json`: no `iamActions`; verified), other routes 404. Token flow per the OVHcloud guide `account-information/authenticate-api-with-service-account.mdx` (kb mirror; verified). `auth-details.json` follows the `auth.Details` model of `kb/api/v1/auth.json` (all seven fields, `method` from `auth.MethodEnum`); it is schema-derived, not captured (T009 captures are owner work) — believed faithful, UNVERIFIED live (P26).
- Not pinned: refusal order between conditions on a host failing several; whether the guard runs from a subdirectory of the checkout; short or upper-case `--reviewed-sha`; `GIT_DIR`/`GIT_*` scrubbing for the guard's own git calls (see *Harness gaps*); root AK/AS/CK binding (`--fresh-account`, T056/T057); the authority/credential mismatch refusal of FR-010 ("refuses a mismatch", run-core scope).

## Learnings

- sensor: a "built from scratch" claim needs an allowlist assertion over the child's keys plus an ambient variable with no expected prefix; checking listed keys and values only lets a prefix-filtered copy of the caller's environment pass (subagent RV1).
- sensor: "a binding that calls X is red" needs an assertion that X is never called; a 403 alone lets a fallback implementation pass (both legs).
- sensor: a fake git must model the user's git config where it changes the answer (`status.showUntrackedFiles=no`); otherwise the guard's plain `status --porcelain` passes the fake and fails on a real host.
- tooling: the test binary doubles as fake executables (symlink named `git`, `lz-fake-child` argv) via `TestMain`, so fakes need no shell and survive a child environment built from scratch.
