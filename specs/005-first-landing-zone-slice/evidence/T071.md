## Task text (tasks.md)

T071 Write separate-clone guard tests in tools/internal/live/guard_test.go with fake git fixtures in tools/internal/live/testdata/. Requirements: FR-011, SC-005; ADRs: 0008, 0009. Depends on: T053. ## Interface the tests pin (for T072)

- **Agent worktree root comes from `live.env`**: new key `LZ_AGENT_WORKTREE_ROOT` beside `LZ_OWNER_CHECKOUT` (`testdata/live.env`). Missing, empty or relative → refused (`live-env` or `agent-root`); the root is resolved (symlinks, `..`) before comparing; the checkout is refused when it equals the root or lies below it by path segment (`worktrees-owner/` beside `worktrees/` is admitted; `/` as root refuses every checkout, review round 1); a root that does not exist on disk is admitted (no agent worktree yet; the `cmd/lz-live` world relies on it). Choice made here, not in the spec (see *Decision request*): `live.env` is the owner's 0600 file the guard already trusts; a constant would hard-code one workstation's layout into the product, a `Host` field would only move the question to `lz-live`. T072 updates data-model (`live.env` keys) and the quickstart.
- **Condition names** (stub constants in `guard.go`, no behaviour): `linked-worktrees` (`CondLinked`), `shared` (`CondShared`), `agent-root` (`CondAgentRoot`); a linked worktree keeps `worktree`. Each row asserts its condition (`assertRefused`), so a mislabelled refusal fails.
- **Order pinned** (review round 1): rows predating D92 keep their single conditions — `linked-worktree` and `symlink-to-linked-worktree` want `worktree` (or `checkout`), `git-fails` the pre-D92 set — so T072 runs the `rev-parse` git-dir/common-dir clause before the D92 git-metadata checks (the agent-root clause may come earlier), as the throw-away does. Deliberate: it keeps one row per condition that fails only that clause.
- **Linked worktrees**: refused on either signal — an entry in `<git dir>/worktrees/` (git does not list an entry without a `gitdir` file: `t071-gitprobe2.sh`), or `git worktree list --porcelain` showing more than one `worktree` line; a `worktrees` that cannot be listed and a failing `worktree list` refuse. An empty `worktrees/` directory is not pinned either way.
- **Shared**: refused when `objects/info/alternates` exists (`clone --shared`/`--reference`), when `core.sharedRepository` is `1`, `2`, `group` or `0660` (`init --shared=group|all|0660` store `1`, `2`, `0660`: `t071-gitprobe.sh`, `t071-gitprobe3.sh`), and when the git dir is not the checkout's own `.git` directory — a gitfile (`clone --separate-git-dir`) or a `.git` symlink to another git dir, for which git prints the resolved git dir (`t071-gitprobe3.sh`); `worktree` also accepted there.
- **Fake git** (modelled on host git 2.53.0, `t071-gitprobe.sh`): `worktree list --porcelain` prints the main worktree (the git dir itself when it is not named `.git`, as git does for a separate git dir), then each `<common dir>/worktrees/*` entry that has a `gitdir` file (marked `prunable` when its directory is gone), then the scenario's `linked_worktrees`; `config [--local] --get <key>` answers from the scenario's `config` (lower-case keys) and exits 1 when unset; `config --list`. The `cmd/lz-live` minimal fake answers one worktree and an unset config key.
- **World** (`newGuardWorld`): `owner/lz-live` (the dedicated clone, `@MAIN@`, the default owner), `owner/landingzone` (`@SHARED@`, with the linked worktree `elsewhere/wt` registered in its `.git/worktrees/wt`), `worktrees/` (agent root) with `worktrees/landingzone/agent-clone`, `worktrees-owner/lz-live`, `sep` + `sep.git`, symlinks `link-main`, `link-wt`, `swapped`, `link-agents`. Each `TestGuardSeparateClone` row builds a fresh world (some rows write into `.git`).

- sensor: rows that write into `.git` need a fresh world each; a shared world lets one row's preparation leak into the next.
- tooling: `t071-mutants.py` installs a throw-away `guard.go` into a scratch copy and also runs the committed stub as a mutant; copy `tests/` and `Taskfile.yml` into the scratch for a whole-package run (protect tests read them).
- sensor: a value-matching clause needs a row per value class the tool accepts (`core.sharedRepository`: 1, 2, a word, an octal mode), or a `== "1"` check passes (review round 2).
- sensor: rows for a path-prefix clause need `/` as the prefix, not only siblings and symlinks (`root + "/"` reads `//`).
