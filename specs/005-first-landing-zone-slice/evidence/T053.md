## What was built

- `guard.go` (G10): order offline marker (refuses unless known absent) → `LZ_OFFLINE` → `live.env` (`ReadCredentialFile`: 0600, regular, own; non-empty `LZ_OWNER_CHECKOUT`, compared as written) → `EvalSymlinks(dir)` = owner → `rev-parse --path-format=absolute --git-dir --git-common-dir --show-toplevel`: git dir = common dir after canonicalisation, work tree = dir (a `core.worktree` in the shared config refuses) → `status --porcelain --untracked-files=all` empty (ignored excepted) → `ls-files -v -z` all `H` (assume-unchanged and skip-worktree entries, which status cannot see, refuse) → `rev-parse --verify HEAD` = `--reviewed-sha` → `merge-base --is-ancestor <sha> refs/remotes/origin/main`. Every git error refuses. New relative to `t052-impl`: the guard's git runs with an environment built from scratch (`PATH`, `HOME`, `LC_ALL=C`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_NO_REPLACE_OBJECTS=1`) and `--no-optional-locks -c core.fsmonitor=false`, and checks reachability against the full ref name (a local branch or tag `origin/main` would shadow the short name).
- `env.go` (G12): as `t052-impl`, plus a `creds` entry cannot replace `PATH`/`HOME`.
- `binding.go` (G13): endpoint and org compared before the credential is sent; token by POST form; `GET /auth/details` only; answers bounded (1 MiB), API bodies never in errors; new: an incomplete binding (empty account, endpoint or org in `account.env`) refuses.
- `files.go`: `ReadEnvFile`, `ReadCredentialFile` (one descriptor opened `O_NONBLOCK`, then `fstat`: refuses non-regular files, any group/other bit and another owner, `CondFileMode`, exit 3; parses from the same descriptor), `AccountDir` (account id one plain segment), `WriteCredentialFile` (keys `[A-Za-z_][A-Za-z0-9_]*`, values without CR/LF/NUL or surrounding whitespace, so a read returns them exactly; path below root without `..`, absolute path or symlinked directory; the root and every existing directory on the path must be 0700 (reported, never silently tightened); missing directories `Mkdir` 0700 + `Chmod` 0700; temp file `Chmod` 0600, sync, rename — a symlink at the target is replaced, not followed).
- `cmd/lz-live`: `lz-live <verb> --reviewed-sha <sha> [args]`; unknown/absent verb or missing SHA → exit 2 without touching git; guard via `live.Run` with `LiveEnv = $HOME/.config/ovh-lz/live.env`, marker `/tcb`, `git` from `PATH`; refusal → 3; an admitted run stops with "not implemented yet" → 1 (verb bodies: T043/T047/T055/T057/T059). No credential is read anywhere yet.
- `Taskfile.yml`: `test:live-lane` = `go -C tools test -count=1 ./internal/live ./cmd/lz-live`. Registry entry unchanged (already registered, creator `005/T055`, scope includes both packages); T055 extends the target.

- sensor: a control row meant to isolate one clause must neutralise the host's defaults (umask 002 made `t.TempDir()` 0775, so the mode clause hid the regular-file clause); pin modes explicitly in fixtures.
- sensor: "the guard asks git" is only as good as git's inputs — scrub `GIT_*`, disable global/system config, replace refs and `core.fsmonitor`, and name refs fully; pinned by logging the fake's environment and argv.
- tooling: `t053-mutants.py` mutates the committed implementation in a scratch copy of `tools/` across both packages (75 mutants); reuse for T055's G2/G8/G9.
