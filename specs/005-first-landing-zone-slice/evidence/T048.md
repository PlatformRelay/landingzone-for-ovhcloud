## Readings (believed unless marked verified)
1. **Interface** (the plan fixes only the files: `observe.go`, `internal/probes/live/chain/`, build tag `live`; as T046 did for `Chain`, the test task fixes the signatures, stubbed in `observe.go`): `Observation{assertion, subject, observed, detail}`, `ObservationSet{run_id, shared_state_project, observations}` (= `observations.json`), `Assessment{assertion, outcome, deviation, detail}`, `Assess(ObservationSet) []Assessment`, `KnownDeviations([]Assessment) []string`, `Trap` (`Add`, `Names`, `Run`), `CanaryOptions` + `ObserveCanary(ctx, CanaryOptions) []Observation`, `Observer`/`ObserveRun{RunID, RunDir, Manifest, Trap}` and `ChainOptions.Observer` (nil: the production collector, T062). T062 may add fields to `ObserveRun`/`CanaryOptions` without touching a test.
2. **Assertions** (the task's list, one name each): `state-bucket-versioned`, `state-object-encrypted`, `state-lock-contention`, `bucket-tags`, `project-tags`, `tenant-iam-write`, `tenant-s3-read`, `outputs-schema`, `deployer-binding` (subjects `platform` and `tenant` both required, P26), `kd1-canary` (subjects `bulkDeleteObjects` and `DELETE` both required). Positive assertions observe `holds`/`violated`, negative ones `denied`/`allowed`; `error` or any other value is a fail (contracts/checks.md: an error is never `pass`). An assertion with no observation, a missing required subject, or a name outside the set is a fail. The test owns its list (a stub's list could be empty).
3. **KD-1 (R20, G15)**: both canary calls denied → `pass` with a note naming KD-1 (R20 "a note that KD-1 did not reproduce"); any allowed with `shared_state_project: true` → `known-deviation` `KD-1`; allowed without the flag → `fail`; an error → `fail` (not a deviation), also when the other call was allowed (review r1: an unobservable call is never folded into a deviation); a missing canary result → `fail`. Every observation counts: a subject observed twice, or a failing subject before a holding one, is judged on all of them.
4. **Canary** (collector clauses of the task): the bootstrap authority (the sandbox admin OAuth2 client) creates `<org>-bkt-canary-<run id, lowercase>` (bucket names are lowercase; R20 name) in the state project and region, then puts one object through a presigned PUT (`POST …/presign` with `method: PUT`, cloud.json `cloud.storage.PresignedURLInput`: the API-only way, the admin has no S3 keys); the canary is registered for the trap, under the bucket's own name (review r2: stated, the rows match it), once its create succeeded and before the tenant's first call, never on a 409 (the name is someone else's bucket); a canary not set up (create or object failed) gives two `error` observations and no tenant call. The tenant deployer then calls `bulkDeleteObjects` and `DELETE` on the canary only: 403 → `denied`; 2xx that did what it asked → `allowed`; anything else (5xx, 409, a 200 bulk answer with every object in `errors`) → `error`. The trap deletes what is left with the admin credential (objects first), is content when the canary is gone, names it when its delete fails; every cleanup runs once.
5. **Chain**: the observer runs once, after the last forward apply and before the destroy-on-exit, only when every apply succeeded; `observations.json` holds the set, redacted, with the manifest's flag; a failed assertion, an incomplete set or a collector error fails the run (exit 1) and the destroy-on-exit still runs; a known deviation leaves the exit code unchanged (0); the trap runs once, after the observer and before the leftover check's first listing (the canary would otherwise be a leftover, `lz-` prefix), whichever way the run ends; a failed trap cleanup fails the run naming it.
6. **summary.json** (coordinator 2026-10-08): `outcome` is `blocked` for a run that ends `*Blocked` (exit 2; T091 gap 6), `pass` or `fail` otherwise; `known_deviations` lists the ids the L7 assessment reported (data-model: "known deviations observed"), e.g. `["KD-1"]`, and the summary line prints them comma-joined or `none`. KD-2 and KD-3 are standing deviations no assertion observes, so they are not listed: the rows pin exactly `[]` or `["KD-1"]`, which excludes listing KD-2/KD-3 always (reading of "KD-1 etc." and data-model "known deviations observed"; review r1 asked for this to be stated, not hedged). A known deviation is reported also when another assertion fails (`fail known-deviations=KD-1`).
7. Chain observation for `chain -- <instance>` (not `all`) is not pinned: V010 is `-- all`; T062 decides (a partial chain cannot satisfy the full set).
