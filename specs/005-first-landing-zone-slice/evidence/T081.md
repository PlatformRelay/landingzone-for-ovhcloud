## Readings (for the coordinator to validate)

- **No new signature.** Black-box on `Probe.Start`/`Probe.Cleanup`; T082 chooses where the refusal sits (`companionEnv`, `identities()` or elsewhere).
- **"In any case"** = each listed name in exact, lower and an alternating case (`oVh_EnDpOiNt`), 8 × 3 rows; `TF_CLI_*` = any name beginning `tf_cli_` in any case: `TF_CLI_ARGS`, `TF_CLI_ARGS_apply`, `TF_CLI_ARGS_destroy`, `TF_CLI_CONFIG_FILE`, `tf_cli_args_plan`, `Tf_Cli_Config_File`, `tF_cLi_aRgS_InIt`, and arbitrary suffixes `TF_CLI_`, `TF_CLI_ANY_FUTURE`, `tf_cli_other`, `Tf_Cli_X` (review r1, codex) — 11 rows.
- **Refused** = as T079's `checkRefused`: non-zero exit (code not pinned), no companion child, destroys exactly `[p]`; plus no file under the config root, run record or stack roots, nothing on the terminal and nothing in the returned error holds the published value (`pairReservedValue`, scanned as a secret by the fake). Whether the refusal comes before or after `Probe.Bind` is **not pinned** (binding the default identity of a refused run is harmless: the root's destroy removes it).
- **Neighbours pass** (negative control, my reading, pinned): a name that only begins or ends like a reserved one (`OVH_ENDPOINT_URL`, `ovh_endpoint_url` (review r1, Opus), `MY_OVH_ENDPOINT`, `TF_VAR_run_id_suffix`, `TF_VAR_project_ids`, `TF_VAR_state_passphrase_hint`, `TF_DATA_DIRECTORY`, `HOMEPAGE`, `XPATH`, `TMPDIRS`, `TF_CLIX`, `MY_TF_CLI_ARGS`, `TF_VAR_tf_cli_args`) is passed to the companion under its own name, and the companion keeps the run's `OVH_ENDPOINT`, `TF_VAR_state_passphrase`, `TF_VAR_run_id`, `TF_VAR_project_id`, `HOME`, `PATH` (equal to the root's first child call) and its per-stack `TF_DATA_DIR`. Rationale: refusing by substring would break legitimate probe roots; the task names the run's names only.
- **`--cleanup`** re-reads `companion_env` from the root's state; one row (`Ovh_Endpoint`) pins the same refusal there (the task text does not name cleanup; T079 set the precedent); it also scans the failed first run's error (refusal joined to the failed root destroy) for the value (review r1, Opus).
- **Task text vs today (verified 2026-10-07, red run):** "today such a name overrides the run's value" holds for `OVH_ENDPOINT`, `TF_VAR_state_passphrase`, `TF_VAR_run_id`, `TF_VAR_project_id` (the companion saw the published value). It does not hold literally for exact `HOME`/`PATH` (`childEnviron` drops them, `env.go`) or exact `TF_DATA_DIR` (`tofuCmd` appends the per-stack value last, os/exec keeps the last); `TMPDIR` and `TF_CLI_*` are not set by the run today, so they pass through to the companion (a published `TF_CLI_ARGS` reached it). Every row is red for the same observable reason regardless: the run exits 0 and the companion runs.
- **Not in the list, not pinned** (proposal for the coordinator): `TF_VAR_state_path` (the run deletes it for the companion; a published one reaches it today), `TF_LOG`/`TF_LOG_PATH` (a published `TF_LOG_PATH` could make the companion's tofu write a trace log, which can carry credentials, to a path of the root's choosing), `TF_PLUGIN_CACHE_DIR`, `TF_WORKSPACE`, `TF_IN_AUTOMATION`, `TF_INPUT`. Rec.: T082 or a follow-up task considers refusing every `TF_*` name other than `TF_VAR_*` and the S3/OVH keys, decided by the coordinator — the task text fixes the list, so this control does not widen it.
