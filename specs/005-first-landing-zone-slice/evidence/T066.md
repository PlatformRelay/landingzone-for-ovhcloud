## Interface the tests pin (for T067)

- **Route 1**: `fixtures` is skipped only under the repository-root `tests/` and `tools/`, at any depth there (`tests/live/fixtures/probe`, `tests/check/fixtures/…`, `tools/cmd/probe/fixtures/…`). Everywhere else a `fixtures` directory is ordinary configuration: `modules/fixtures`, `modules/a/fixtures`, `components/runtime/kube/fixtures/basic`, `components/fixtures/kube`, `stages/platform/fixtures/x`, root `fixtures/x` (`REMOTE_STATE` + `UNCLASSIFIED`), `stacks/fixtures/platform` (`HANDWRITTEN_INSTANCE`). A `tests` or `tools` segment elsewhere does not re-open the skip: `modules/tests/fixtures/x` and `modules/tools/fixtures/x` with a backend are `LIBRARY_BACKEND`.
- **Route 2**: the test/example layer applies to a root `tests/`/`examples/` tree, or to a `tests`/`examples` segment strictly below a package root (`modules/<m>/…`, `components/<singleton>/…`, `components/<family>/<c>/…`, `stages/<s>/…`), also deeper (`modules/object-store/sub/tests/helper`). A package named `tests`/`examples` is library or stage code: `modules/tests`, `modules/examples`, `modules/tests/sub`, `components/runtime/tests`, `components/runtime/examples`, `components/tests/kube` (family named `tests`), `stages/examples`, `stages/tests` → `LIBRARY_*`; `stages/examples` calling a module directly → `LAYER_VIOLATION`; `components/tests` (family without a variant) → `UNCLASSIFIED`.
- **`.tofutest.hcl` / `.tofutest.json`** → `UNSUPPORTED_CONFIG` only, subject the file's directory (as for `.tftest.json`), in `tests/` or beside the module. "Refuse only" is intended: the exact rule set rules out also parsing the file (which would add `LAYER_VIOLATION` for the stage-running row), matching how `.tftest.json` is refused and not parsed (review round 1, Opus).
- **Route 3 stays open**: `live/prod` with the generated header, backend, provider and a stage call is an instance with no finding.
- Not pinned (T067's choice, no FR-003 effect either way): a `tests`/`examples` segment in a directory outside any package root and outside root `tests/`/`examples/` (e.g. `misc/tests/x`, `instances/prod/tests`); a `fixtures` directory below a module's `tests/` (`modules/a/tests/fixtures/x`) — scanned it is a test root, skipped it is invisible; neither gets a purity finding.
