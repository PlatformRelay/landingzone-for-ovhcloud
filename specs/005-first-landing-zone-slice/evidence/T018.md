## What changed
- `tools/internal/stacks/outputs.go` — the T017 stub replaced:
  - `BuildEnvelope`: one JSON object (no duplicate keys, no trailing data), entries decoded typed;
    an entry without a boolean `sensitive` marker refused (`sensitive`, never assumed plain);
    `sensitive: true` dropped (G2); a plain output without a value refused (`malformed`); a plain
    output whose name or any nested key matches the secret pattern refused (`secret-key`). Entries
    are walked in sorted order, so the reported reason is deterministic.
  - `ValidateEnvelope`, in the order T017 pins: one JSON object → envelope schema present →
    header (all six keys present, exact keys only, typed, `apiVersion`/`kind` constants, non-empty
    `instance_id`/`stage`, `source_revision` a git object id, `values` an object) → producer
    (`instance_id`, `stage` = expectation) → deny-list anywhere in `values` (secret-pattern key,
    null, `""`) → stage known to the code and `<stage>.schema.json` present → required fields at
    every depth → strict typed decoding into the stage's Go type (unknown member, wrong type) →
    `runtime.kind = managed-only`, `runtime.slot` a manifest slot name (r1) → KD-3 for `project` (id and URN equal the binding; no binding →
    refused).
  - Typed values per stage (`bootstrapValues` … `runtimeValues`), `stageValues` registry.
  - Refusal details print only names the contract declares (`*` for document keys) and never a
    value or a decoder message.
- **Decoding with `encoding/json/v2` (standard library, Go 1.27.1 per `tools/go.mod`), not v1's
  `DisallowUnknownFields`.** Reason: v1 matches object keys case-insensitively, so `State_Bucket`
  beside `state_bucket`, or `Stage` beside `stage` in the header, passes `DisallowUnknownFields` and
  the later one overrides the real key (a producer could be relabelled). v2 matches exactly, refuses
  duplicate keys at any depth, trailing data and invalid UTF-8; `RejectUnknownMembers(true)` is
  v2's `DisallowUnknownFields`. No module added to `tools/go.mod` (decision 4 holds). Pinned by the
  new `TestOutputsValidateRefusesCaseVariant` and the mutants `values-v1-disallow-unknown` and
  `header-v1-disallow-unknown`.
- `schemas/outputs/{envelope,bootstrap,tenant-state,account-governance,project,project-network,runtime}.schema.json`
  — draft 2020-12, closed objects, required sets as data-model *Per-stage values*, every string
  `minLength: 1` (the code refuses `""`), `const` for `apiVersion`, `kind`, `runtime.kind`, the
  revision `pattern` and (r1) the slot `pattern` `^[a-z][a-z0-9]{0,15}$` (data-model *Manifest*). The envelope schema's description states the rules a schema cannot express
  (secret-pattern keys, null anywhere, sensitive entries, exact keys).
- `tools/internal/stacks/outputs_schema_test.go` (new):
  - `TestOutputsSchemaMatchesTypes` (decision 4): per stage and for the envelope, schema and Go type
    agree on property names, required set (= fields without `omitempty`), types (string/array/
    object, typed `additionalProperties` for maps), `additionalProperties: false` on every struct,
    `minLength` exactly 1 on every non-const string (r1), `const` values, patterns by path (only
    `envelope.source_revision` and `runtime.slot`, each equal to the code's, r1); schema nodes are
    decoded with unknown members rejected, so any keyword the code does not mirror (`maxLength`,
    `minItems`, `enum`, `format` …) fails it (r1); every keyword present must be one the branch
    compares (string: const/pattern/minLength, const strings without minLength; array: items; map:
    additionalProperties; struct: required/properties/additionalProperties; the envelope's raw
    `values`: type only) (r2); the set of stage schema files equals the code's
    stage registry.
  - `TestOutputsValidateRefusesExact` (5 cases: header `Stage`, value key beside / instead of the
    key, nested key; r1: slot `Blue_1`).
  - `TestOutputsBuildEnvelopeRefusesBrokenEntry` (3 cases: no value, non-boolean marker, entry not
    an object).
- `Taskfile.yml` — `test:outputs` description and comment (no longer "red until T018", r2) name the schema agreement (target body unchanged:
  `-run 'TestOutputs'` already selects the new tests).
- `specs/005-first-landing-zone-slice/data-model.md` *Output envelope* rules: null/`""` refused
  anywhere in `values` (decision 3), exact keys once, schema/type agreement.

## Not done here (believed; decisions recorded by the coordinator)

  carries nothing a validator could judge staleness by.
- `runtime` `scope.project_id` against the binding: T060 (decision 2). KD-3 here covers
  `stage = project` only.
- The builder does not refuse null/`""` plain values; the validator does, and T061's publisher is
  expected to validate before publishing (believed, T061 text).
- `ValidateEnvelope` returns the raw `values`; T060's adapter should decode them with the same
  `stageValues` types and `encoding/json/v2`, not v1 (Opus r1 note).

  and are JSON objects; it does not interpret them (decision 4). Agreement is a test-time property
  (`TestOutputsSchemaMatchesTypes`), so a consumer handed a different schema directory still
  enforces the compiled contract.

## Learnings
Class: guidance.
- `encoding/json` v1 matches keys case-insensitively, so `DisallowUnknownFields` admits a case
  variant that overrides the real key; at a trust boundary decode with `encoding/json/v2`
  (stdlib; builds without `GOEXPERIMENT` on Go 1.27.1, verified 2026-10-07; codex read the 1.26.6
  docs as still experimental) and pin it with a case-variant control.
- A schema/type agreement test must decode the schema with unknown keywords rejected and allow, per
  type branch, only the keywords it compares; otherwise a tightened schema passes it silently.
- When a target turns green, check that CI runs it (`LZ_TARGETS`), not just the Taskfile.
