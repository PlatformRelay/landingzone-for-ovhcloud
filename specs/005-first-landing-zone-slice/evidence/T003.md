## Interface the tests pin (for T004)

- `RunUnit(tools StaticTools, dir string) UnitObservation`: `tools.Tofu` absent → `blocked TOOL_ABSENT`, no report. Otherwise mirror-only `init` (`-backend=false -lockfile=readonly`; reuses the `init` clause shape) → on failure `fail INIT_FAILED`, `tofu test` not run, init diagnostics kept. Otherwise `tofu test -json` in the directory, stream and exit status judged by `report.Evaluate` (001/T005); adapter pass → `pass`, else `fail TEST_REPORT_FAILED` with the adapter's reasons and diagnostics in `Report`.
- `RunSlice(tools StaticTools, dirs []string) SliceObservation`: empty or nil list → `fail NO_DISCOVERY`, no entries. Otherwise every directory gets `RunStatic` (lint) and `RunUnit`, in order, without stopping at the first failure; passes only if all do. Discovery from the dependency graph stays T004's (`test:slice`), outside `RunSlice`.
- New import edge `internal/checks` → `internal/report` (Go package, inside `tools/`; `cmd/json2junit` already imports it). No HCL layer rule applies; `test:dependencies` unchanged and green.

## Learnings

- tooling: no Task target runs `TestUnit*`; T004 must add it (e.g. extend `test:static`'s `-run` or have `test:unit` run it), else the controls never run in CI. Until then, run the Verify line through the entry on a scratch copy with one extra target (`~/.local/share/ovh-lz/review/t003-entry.sh <tree>`).
- tooling: a throw-away implementation in a scratch copy (`t003-impl-unit.go`) proves a test task's red is satisfiable and gives reviewers something to mutate; T004 can start from it.
- sensor: a slice/aggregate control needs a member that fails only one of the aggregated clauses, else a clause-ignoring aggregate survives (round 1).
- guidance: pinned tofu 1.13.0 rejects a malformed `.tftest.hcl` at `init`, so "malformed" needs two controls: the file (init) and the stream (non-JSON line, replayed).
