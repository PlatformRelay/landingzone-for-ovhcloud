## Interface the tests pin (for T014; readings, believed unless marked)
The plan fixes the resource types (T014 Verify), not the variables or outputs; these are this task's choice.
- `modules/object-storage`: inputs `project_id`, `region`, `name`, `tags` (`map(string)`, a null value refused), `versioning` (`bool`, default `false`); resource `ovh_cloud_project_storage.this`; outputs `name`, `region`.
- `modules/object-storage-protected`: the same without `versioning` (always `enabled`, not an input); literal `lifecycle { prevent_destroy = true }` (T014; pinned by T026's scan, see *Harness gaps* 1).
- `modules/object-storage-user`: inputs `project_id`, `description` (the naming output for kind `s3_user`; the user has no name or tags), `buckets` (`list(string)` of bucket **names**, at least one, each a valid bucket name: no wildcard, no ARN, no null); resources `ovh_cloud_project_user.this`, `ovh_cloud_project_user_s3_credential.this`, `ovh_cloud_project_user_s3_policy.this`; outputs `user_id`, `access_key_id`, `secret_access_key` (sensitive).
- Readings: (1) "given name/tags" = inputs; the caller (component) calls `modules/naming` and passes `name`/`labels` through, so the tests use naming's contract values as literals (`lz-demo-dev-gra11-bkt-runtime`, `lz-demo-bkt-state`, `lz-bkt-state`, `lz-demo-s3u-state`, the five-label map) rather than calling naming. (2) "`versioning` when requested": `true` sets `status = "enabled"`; `false` requests nothing (the provider computes it) and must not end up `enabled`; "disabled" is not sent (whether OVHcloud accepts `disabled` on a never-versioned bucket is UNVERIFIED). (3) "allows only the given bucket ARNs": the union of `Resource` over the `Allow` statements is exactly `arn:aws:s3:::<b>` and `arn:aws:s3:::<b>/*` per given bucket (form as in `s3-identity-and-access-management.mdx:116-125` and `cloud_project_user_s3_policy.md`, verified 2026-10-07 in the kb mirror); no `NotResource`/`NotAction` in an `Allow`; no wildcard action; every allowed action within the object/listing allowlist (the kb read-write example plus `s3:ListBucketVersions`, `s3:GetObjectVersion`; no bucket configuration, no `s3:DeleteObjectVersion`, review r1); `Deny` statements are free (they only narrow). (4) The policy must allow what an S3 state backend with `use_lockfile` needs: `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject`, `s3:ListBucket` (believed; conditional writes need nothing beyond PutObject/DeleteObject, `s3-conditional-writes.mdx:287`, verified). (5) "the S3 user has `objectstore_operator`" = that role and no other (`role_names` exactly, `role_name` null).
- Schema: attribute names from the pinned ovh 2.21.0 provider schema dumped offline (`~/.local/share/ovh-lz/review/t013-schema.py` over T008's `schema.json`, verified 2026-10-07): storage `service_name`, `region_name`, `name` (required), `tags` (map, optional+computed), `versioning.status` (nested, optional+computed); user `service_name` (required), `description`, `role_name`, `role_names`, `password` (sensitive); credential `user_id`, `access_key_id`, `secret_access_key` (sensitive); policy `user_id`, `policy` (required).

ADR-0011 says lock files are not committed for library modules → *Decision request* 1.
- Mocked provider values: on plan an unset optional+computed nested attribute (`versioning`) is unknown; on apply the mock fills it with a random string (`{"status":"yN3lorhux"}`), so "not requested" is asserted as `!= "enabled"` on apply.
- `issensitive()`/`nonsensitive()` work in assertions on 1.10.3 and 1.13.0.
- `~/.local/share/ovh-lz/review/t011-split.py` drops `mock_provider` blocks (every split run then fails `Invalid provider configuration`); `t013-split.py` keeps every non-run top-level block.

## Learnings
- tooling: `prevent_destroy` cannot be asserted by `tofu test`; a module with it needs plan-only tests (an apply run passes, exits 0 and leaves `errored_test.tfstate` in the module directory) and a static lifecycle scan (T025/T026).
- tooling: `t011-split.py` drops `mock_provider`; use `~/.local/share/ovh-lz/review/t013-split.py` for provider modules.
- tooling: a provider-using module needs a committed `.terraform.lock.hcl` for the entry's `-lockfile=readonly` init (decision 1).
- guidance: on a stub, a clause pinned negatively (e.g. "not enabled when not requested") passes; pair it with a positive assertion in the same run so the run is red, and prove the clause with its mutant.
- guidance: a security allow-scope test pins a ceiling (allowlist / exact set), not only a floor; and every guard applies to every fixture, or an implementation conditioned on the fixture escapes (review r1).
