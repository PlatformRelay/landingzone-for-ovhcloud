## Design (decided here)

1. **The reads move out of the companion's check blocks into a lz-live check.** A refused read in
   a check-scoped data source is an OpenTofu warning (T010 run 14: the run printed `pass` over a
   403 on bucket A). Instead of teaching lz-live which warnings count (a name convention over
   diagnostics nobody has captured), the storage-iam root gets a `live.ProbeCheck` like
   state-backend's (T096): every observation has an expected answer, and Observe fails the run when
   one differs. Warnings stay warnings. The companion keeps P1–P3 and P9 usage; its three check
   blocks, the P25 provider alias and its two variables go, and `companion_env` no longer carries
   the P25 identity (the check binds it itself, below).
2. **Five observations** (package `tools/internal/probes/live/storageiam`), in order:
   `p25-read-bucket-a` (P25 identity, GET storage A: allowed), `p25-read-bucket-b` (P25, GET
   storage B: refused), `p26-get-me` (tenant, GET /me: refused), `p9-iam-write` (tenant,
   POST /v2/iam/policy: refused), `p3-state-object` (the P1 S3 key, GetObject of the companion's
   state: encrypted). Refused = 403 whose named IAM actions are empty or include the step's action
   (`region/storage/get`, `account:apiovh:me/get`, `account:apiovh:iam/policy/create`); a 403
   naming another action is not the observed denial. The refused actions are read from the API's
   403 body (`details.unauthorizedActionsByIAM`, kb manage-and-operate/iam/troubleshooting.mdx:21-31;
   and the `message` "missing IAM permissions: …" T010 rows 10/14 show), keeping only
   action-shaped tokens.
3. **Unlike state-backend, a finding fails the run** (the task: refused bucket A → outcome
   `fail`, the action named). Observe prints `LZ-LIVE finding <step>: expected …, observed …
   <status> <actions>` and returns that as its error; expected denials are passes.
4. **The IAM write never leaves a policy behind.** The write is a harmless policy (name
   `lzprobe-p9-write-<run-id>`, the tenant identity, the project URN, allow
   `region/storage/get`, which the tenant already holds, `expiredAt` one hour ahead). Undo, with the
   sandbox admin's credential, lists `/v2/iam/policy`, deletes every policy of that name, and lists
   again; a failed Undo keeps the root for `--cleanup` (T096 rule). The leftover check also matches
   `lzprobe-` policies (README leftover matrix). An accepted write is a finding: the run fails.
5. **"Admin side" for the state object** = lz-live's run core, not the companion child: it reads
   the object with the P1 S3 key the root (applied under the admin credential) published; the
   admin OAuth2 identity holds no S3 key (T096 design 4). "Not plaintext" = the OpenTofu
   encryption envelope (`encrypted_data`, no `resources`; one rule shared with the chain's
   observe.go, capture p4-encryption.txt), the client-side encryption the companion enforces (P3).
   The `x-amz-server-side-encryption` answer header is recorded when present (SSE-OMK, kb
   storage-and-backup/object-storage/s3-encrypt-your-objects-with-sse-c.mdx:143-160); whether
   OVHcloud returns it on a GET, and whether the probe bucket has default SSE, is UNVERIFIED — the
   probe bucket is created without an encryption option, so the envelope is the evidence.
6. **A gated API checker** `live.APIChecker` beside `live.S3Checker`: a closed set of five named
   operations (GetStorage, GetMe, CreatePolicy, ListPolicies, DeletePolicy), each with its method
   and path fixed, path parameters checked by shape, no redirect, answers capped; of an answer it
   keeps the status, the action-shaped tokens of a refusal, a created policy's uuid and a listing's
   (id, name) pairs; no error carries answer text.
7. **Identities bound before use** (G13): the check binds the tenant and the P25 identity through
   lz-live's Bind before its first call with each.
