## Readings (believed unless marked verified)
1. **"Six stacks"**: the manifest's six; account-bootstrap is `bootstrap:account`'s (T058 decision 1, accepted 2026-10-08), so the fake account starts as that run leaves it (account-bootstrap applied, its state present) and the chain applies the other five in run order. The chain reads account-bootstrap's state (init + `show -json`, nothing else) for the leftover check; the harness admits exactly those two calls in that root for destroy-capable runs.
2. **Destroy = a saved plan**: `plan -destroy -out=<file>` with the stack's inputs, `show -json` of that file through `Protect`, `apply <file>` (contracts/checks.md: every applying verb plans to a file, passes it through protect.go and applies only that file). Never `tofu destroy -auto-approve` (the run core's probe destroy still does: a divergence T047 settles, gap 2). OpenTofu asks a destroy plan for the root's required variables (believed), so the fake requires them as for any plan.
3. **Destroy set**: after a complete run every ephemeral stack of the target; after an apply failure, SIGINT, SIGTERM or the deadline only those whose apply started (the run core's rule, R12), in reverse run order, continuing after a refused or failed destroy (exit non-zero), never a retained instance. A destroyed stack's record is removed, so the next selection picks it again ("no record → selected", FR-009); a refused destroy keeps it.
4. **Inventory**: one line per `apply_complete` event (P24) in `<run-dir>/inventory.jsonl`, appended while the apply still runs (the interrupted row reads it while the child blocks).
5. **Leftover check inputs**: the captured listings through the `Lister` seam; projects = the distinct `LZ_PROJECT_ID_*` of account.env (KD-1: one); prefix `<org>-`; the run id; retained ids from each retained instance's state (`tofu show -json`, nested modules included) by the attribute the provider documents as the listing's id (storage `name`, user `id`, S3 credential `access_key_id`, S3 policy `user_id`, OAuth2 client `client_id`, IAM policy `id`, identity group `name`, alert `id`, network/subnet `id`, resource tags the keys of `tags`; verified by reading the kb provider docs 2026-10-08; state shapes UNVERIFIED until a live state is captured, T010/T049); the admin exemption through `LoadExemption` (sandbox.env client id, account.env `LZ_ADMIN_POLICY_ID`).
6. **Stopping a child**: SIGINT forwarded as SIGINT, SIGTERM as SIGTERM or SIGINT, the deadline as SIGINT (run core); the destroy runs with its own time after the deadline.
7. **Locks**: `account` and `tenant-demo` (stacks.RunLocks of the acted and the ephemeral set) taken before the first call and held over every tofu call, destroys and state reads included; the listings are not required to run under them.
8. **Exit codes**: apply failure, interruption, deadline, leftover or listing error → non-zero (1 where pinned); a destroy plan the guard refuses → 3 (`retained`), also joined with other errors. The terminal ends with `LZ-LIVE summary <run-id> pass|fail …` and the cost reminder (contracts/checks.md).
9. **Captured world**: T087's capture with the project id, account and admin client id substituted by the lane's; the retained instances' resources added as they exist after a chain (shapes of the captured listings; subnet, S3 credential, S3 policy and alert remain uncaptured kinds, provenance.json); T087's seeds renamed from `lzprobe-` to `lz-seed-`; a seed known through the inventory (subnet, S3 credential, S3 policy) is created by the stack of its kind.
10. **Not here**: the L7 assertions between apply and destroy (T048: a failed assertion still destroys, T049), the `lz-live chain|destroy` entry and Taskfile targets (T047), `chain -- <instance>`.
11. **Unpinned on purpose** (review r1): whether a destroyed stack's envelope is withdrawn, and whether `destroy -- <producer>` is refused while a consumer is applied (runtime does not consume project-network, data-model *Stage table*, so the sandbox has no such pair among ephemeral stacks).
