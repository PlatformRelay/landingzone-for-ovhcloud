## Bounds and their sources (verified 2026-10-11 in the kb)

- API schema: `POST /cloud/project/{serviceName}/network/private` takes
  `cloud.ProjectNetworkPrivateCreation`, whose `vlanId` (`long`, optional) reads "Vland id, between
  0 and 4095. 0 value means no vlan." (`kb/api/v1/cloud.json`, model
  `cloud.ProjectNetworkPrivateCreation`). The regional-network models
  (`cloud.network.CreateNetwork`) say 1..4095; not the endpoint the provider resource uses.
- Control Panel: "you will be able to manually choose a VLAN ID number between 0 and 4 000"
  (`kb/mirror/ovhcloud-docs/docs/en/guides/public-cloud/network-services/vrack.mdx:402`), and "up
  to 4 000 VLANs within one vRack" (`:359`).
- Provider: `ovh_cloud_project_network_private.vlan_id` "Changing this value recreates the
  resource. Defaults to 0." (`cloud_project_network_private.md:27`) — the default every network
  fell back to.
- Chosen: **0..4000**, the narrower of API and Control Panel. Whether the API really refuses
  4001..4095 is **UNVERIFIED** (no live call). 0 is admitted (API: "no vlan"; it still occupies the
  one-network-per-id slot, as the live 400 shows: the leftover held VLAN 0).
- One private network per VLAN id per project: believed from the live 400 (one observation, the
  message names no region); the decoder checks per environment, which owns one project
  (`DUPLICATE_NAME` refuses one project ref on two environments, T034).

## Design

- `modules/private-network`, `components/network/island`: `vlan_id` has no default,
  `nullable = false`, validation 0..4000 and whole.
- `stages/project-network`: `network.vlan_id` is `optional(number)` without a default plus a
  validation (`try(…, false)`), so a row without it, or with null, is refused by validation
  (`expect_failures`-testable) rather than by type conversion.
- Manifest decoder (`tools/internal/stacks/manifest.go`): numbers get a range rule like strings
  get a pattern (`manifestRanges`, fail closed for a number without one); `vlan_id` outside 0..4000
  is `INVALID_VALUE`; two region networks of one environment with one id is the new
  `DUPLICATE_VLAN` (values group, document order), detail naming both regions and the project ref.
  A region without a network row is not counted (empty CIDR; `cidr` is required and patterned when
  the row exists). The stage takes the id from the manifest row as is: deterministic, no derivation
  from list position (LZ-NET-001). The schema gains `minimum: 0, maximum: 4000`; the agreement test
  now mirrors `minimum`/`maximum` against `manifestRanges` (a keyword it previously refused).
- Probes (after review round 1): each probe lists the project's private networks
  (`data.ovh_cloud_project_network_privates.existing`; `GET /cloud/project/{sn}/network/private`
  needs `network/private/get`, `cloud.json`, which the tenant allowlist holds) and takes the first
  id of its own range — network 2000..2999, storage-iam 3000..3999, disjoint, inside 0..4000 —
  starting at base + the run id's hex suffix mod 1000 and wrapping, that no network holds; once
  its own network exists (matched by name) it keeps that network's id (round 2: otherwise a freed
  earlier id would move it, and `vlan_id` forces a replacement). A leftover or an applied
  concurrent run is skipped; two plans racing before either applies may pick one id, and a
  leftover of the same run id is taken for its own: the API then refuses the create (the 400
  above), so no two networks share one. A precondition refuses the plan when the whole range is
  taken. First version (round 0): a pure
  `base + suffix % 1000`, ~1/1000 collision between two runs of one probe (codex r1 major).
- `stacks/deployments.yaml` keeps demo/dev/GRA11 on VLAN 0 (no generated stack changes); the
  growth fixture's second regions move to VLAN 1 (it had two networks of one environment on 0).

## Learnings
- class: guidance — "never collide" over a bounded id space needs live state (list and pick a free
  id) plus stability for the resource's own id; a pure hash of a run id cannot be injective.
- class: tooling — `override_data` values cannot call functions (`range()`): exhaustion cases need
  literal data or stay agent-review.
- class: sensor — a required variable's *omission* cannot be an `expect_failures` run (`No value for
  required variable` is not checkable): check "no default" statically (Go `hclsyntax`), or use
  `optional(T)` + validation for object attributes so omission is refused by validation.
