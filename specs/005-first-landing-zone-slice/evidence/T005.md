## Task text (tasks.md)

T005 Write purity-rule tests in tools/internal/checks/dependencies_test.go and tests/check/fixtures/dependencies/. Requirements: FR-003; ADRs: 0002, 0004. Depends on: 001/T009. Verify: `go -C tools test ./internal/checks -run TestDependencies -count=1`: a generated stack with backend+provider calling a stage, a stage calling a component, a component calling a module and naming are accepted; a `backend` block or `provider` configuration block in a module/component/stage, `terraform_remote_state` in any directory, and a non-generated `.tf` under `stacks/` are behavioural red (currently unreported). Existing `mayUse` controls stay unchanged.

## Interface the tests pin (for T006)

- Rule ids (T006 Verify): `LIBRARY_BACKEND`, `LIBRARY_PROVIDER_CONFIG`, `REMOTE_STATE`, `HANDWRITTEN_INSTANCE`, added to `DependencyRules` (sorted list pinned by `TestDependenciesRulesListed`). Each finding's `Subject` is the offending directory, as for every other rule.
- `LIBRARY_BACKEND`: a `backend` or `cloud` block inside a `terraform` block of any configuration file in a library (module, naming, component, singleton component, nested subdirectory) or stage directory, generated or not.
- `LIBRARY_PROVIDER_CONFIG`: a top-level `provider` block (empty, aliased or configured) in any configuration file of a library or stage, including override and generated files. Not: `required_providers`, `configuration_aliases`, the `providers` meta-argument of a `module` call, or `provider`/`mock_provider` in `*.tftest.hcl`.
- `REMOTE_STATE`: `data "terraform_remote_state"` in any classified directory (library, stage, generated stack, example, test root, module test helper), also nested in a `check` block.
- `HANDWRITTEN_INSTANCE`: any configuration file under `stacks/` whose first line is not the Terramate generated header, judged per file (a generated sibling does not exempt it) and whatever layer the directory would otherwise get (a `tests/` or `examples/` segment under `stacks/` does not exempt it). A stack directory with no generated file must report it; it may also report `UNCLASSIFIED` (classification of a wholly hand-written stack directory is left to T006).
- `*.tofu` / `*.tofu.json` (`TestDependenciesTofuFiles`): either `UNSUPPORTED_CONFIG` (as `.tf.json`) or the same purity rule a `.tf` file would get; T006 chooses. `.tofu.json` is `UNSUPPORTED_CONFIG`.
- Allowed and pinned by the positive fixture: examples and `tests/` roots (live probe roots, module test helpers) may configure backend and provider; `stacks/_lz/*.tm.hcl` and `stacks/deployments.yaml` are not configuration files.
- `mayUse` pinned unchanged (`TestDependenciesLayerMatrixUnchanged`); no existing control edited (the diff removes one line, the `RulesListed` want list, which T006 Verify requires to grow).

## Learnings

- sensor: OpenTofu reads `*.tofu` beside `*.tf`; any check that routes configuration by extension needs a `.tofu` control (verified with pinned tofu 1.13.0).
- sensor: `classify` gives `tests`/`examples` path segments priority anywhere in a path, so a rule scoped by tree (`stacks/`) needs controls with those segments inside the tree.
- tooling: `mutate.py` copies only `tools/`, so tests reading `../../../tests/check/fixtures` see no fixtures and every mutant "dies"; mutate a scratch copy holding `tools/` and `tests/` in place (`t005-mutants.py`).
- tooling: a test task whose controls assert strings needs no stub; the throw-away implementation is `~/.local/share/ovh-lz/review/t005-impl-dependencies.go`.
