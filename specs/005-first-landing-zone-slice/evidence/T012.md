## Readings (believed, beyond what T011 pins)
- `""` in any coordinate, optional ones included, is refused as an empty segment (T011 gap 2): absent is `null`; `""` would otherwise give a doubled separator or an empty `lz:tenant`. Pinned by `template.tftest.hcl` from review r1.
- `org`, `kind`, `role`, `instance`, `managed_in`, `labels`, `template` are `nullable = false`.
- Template validations: segments are a duplicate-free subset of the seven coordinates and include `kind` and `role`; every kind abbreviation is non-empty; `case` is `lower` (the only rule implemented); `separator` non-empty. Pinned by `template.tftest.hcl` from review r1.
- The `lz:tenant` value is the `tenant` input unchanged (not lowered): it is the manifest's authorisation key. Refusing a non-lowercase tenant would contradict T011's `case_rule_every_coordinate` (`tenant = "Demo"` accepted), so the README states the caller owns it.
- Mandatory labels are merged last, so an extra label could not override them even without the key refusal (defence in depth for G4).

## Learnings
- tooling: an output precondition `condition = true` (no reference) is refused at init; a mutant removing a rule must keep a reference (`x != null || true`).
- guidance: `map(string)` admits `null` elements; a template-as-data input needs an explicit non-null/non-empty validation on its map values, or a segment drops silently.
- guidance: every validation an implementation task adds beyond the test task's runs needs its own red-first run; split multi-clause validations one rule per block so each mutant is attributable.
