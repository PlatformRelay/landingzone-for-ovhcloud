## Choices

1. **Which READMEs.** The root README.md when it exists, and every regular file named `README.md` below a top-level directory other than `docs/` (whose pages, `docs/adr/README.md` included, keep all their rules and are not counted twice). Skipped: hidden directories (`.git`, `.terraform`, `.specify`, `.local`: not the repository's documentation, or not tracked) and any directory named `fixtures`, `testdata` or **`vendor`**. `vendor` is not in the task's exclusion list: `tools/vendor/` holds four third-party READMEs (`agext/levenshtein`, `hashicorp/hcl/v2` twice, `mitchellh/go-wordwrap`) whose links are upstream's to keep, not "the directory READMEs" of this repository. This is a reading of the task, for the review to judge. On this tree: 22 directory READMEs (verified 2026-10-14: `git ls-files '*README.md'` outside `docs/` lists 29; minus 2 under `tests/check/fixtures`, 4 under `tools/vendor`, and the root one).
2. **Which rules.** On READMEs only `LINK_BROKEN` and `ANCHOR_MISSING`, through the same `link`/`anchorsOf` code as the pages (`body` now takes `bodyRules{ids, targets}`: pages `{true, !adr}` as before, READMEs `{}`); no front matter, pins, 32-hex or task-target rule.
3. **The absent root README.** In the entry's snapshot (and so in CI) there is no README.md. Two directory READMEs link to it (`specs/README.md:5`, `tools/README.md:25`), so judging them there would fail on a file that exists in the repository (first entry run: `LINK_BROKEN specs/README.md: ../README.md does not exist`, iteration 2). A link that resolves to the root README is therefore judged only when that file exists; when it is absent the link is counted and the line says so: `DOCS_OK … root_readme=absent unjudged_root_links=2`. With the root README present (host), those links and their anchors are judged (`TestDocsRejected/link to root readme judged`). Never a silent pass; the decision request below removes the special case.
4. **Registry scope.** `docs:check`'s scope gains the 22 directory READMEs by path (the scope is a path list; directories would select `docs:check` for a change to any file of every module). A file entry still selects `docs:check` for a DoD of the directory holding it (`selects` matches a scope entry below the target, `traceability.go:1017`): `task dod -- modules/naming` now needs fresh `docs:check` evidence, as the README is part of that directory (strong review leg r2; gap 6). The root README is not in the scope: the snapshot has none, and a missing scope entry fails the check's digest there. `TestDocsRegistryScopeREADMEs` (new) reads the committed registry and requires every README `docs:check` reads, root aside, in the scope, so a new README cannot be missed silently. A wider scope changes `docs:check`'s digest, so the foundation run record (`pipelines/github/foundation-runs.json`) is re-captured afterwards by the coordinator, as after any docs change.
5. **How-to *Status*.** Rewritten from evidence/T049.md (status line and run 4, read 2026-10-14): run 20261013T075309Z-443f passed, every assertion `pass` but `kd1-canary` as known deviation KD-1, ephemeral destroy done, leftover check zero; runs 1–3 stopped on the projects' IAM tags (T105); T045 the remaining owner run (tasks.md: T045 open, owner session). ## Learnings

- sensor: a check that reads files the offline entry's snapshot lacks must say so in its OK line and count what it skipped; a host run is the only full run until the snapshot admits the file (here the root README).
- guidance: an exemption added for one input kind must be gated on that kind, with a control that the old kind keeps its rule (review r1 major).
- spec: a scope entry naming a file selects its check for a DoD of every parent directory (`selects`); widening a scope by file paths changes which DoDs need that check's evidence.
