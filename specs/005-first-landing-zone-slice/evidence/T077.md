## Task text (tasks.md)

T077 Write scratch-location and cleanup-binding tests in tools/internal/live/runner_test.go and tools/cmd/lz-live/main_test.go. Requirements: FR-011, FR-013; ADRs: 0008, 0009. Depends on: T074. Verify: `go -C tools test ./internal/live ./cmd/lz-live -count=1`: a `TMPDIR` (or resolved scratch HOME or data directory) inside the checkout is refused before any credential, file or child; a probe run records its project id in the run's `probe.env`, and `--cleanup <run-id>` uses that recorded id even when `account.env` now names another project; a run record without a project id is refused for cleanup. Today the scratch follows `TMPDIR` wherever it points and cleanup reads the current `account.env`: behavioural red. Found in T074 (evidence/T074.md gaps).

## Readings (for the coordinator to validate)

- **No new signature.** The plan fixes none for these clauses, so every control is black-box on existing API (`Runner.Execute`, `Probe.Start`/`Cleanup`, `lz-live probe`); T078 chooses names (the throw-away's `live.ScratchOutside`, `live.ProbeProject`, key `LZ_PROBE_PROJECT_ID` are not pinned).
- **"Inside the checkout" per package.** `lz-live` knows the checkout: a `TMPDIR` resolving anywhere inside it is refused, `.local/` included (gitignored, so the guard's clean-tree check does not see it), the checkout itself, a probe root, and a symlink alias outside that resolves into `.local/tmp`. The runner does not know the checkout (T073 reading): it refuses a `TMPDIR` resolving inside a stack root or the run records' directory (the parent of `Runner.Dir`, `.local/live/` in production). A `TMPDIR` beside them, a path-prefix sibling included (`<checkout>-tmp`, `<stacks>/p-tmp`, `live-tmp`), is admitted and used (children's `HOME` under it).
- **"Data directory"** lives under the scratch HOME (T074 design: `<HOME>/tofu-data/<stack>`), so the `TMPDIR` refusal covers it; no separate knob exists to place it elsewhere. T073's controls still pin "data directory outside the checkout" on the default `TMPDIR`.
- **"Refused" = exit 3** (a `*live.Refusal`), the error/stderr naming `TMPDIR` (tells the owner which variable to change), as the other refusals of `probe.go` (T073 reading). `TMPDIR` reaches lz-live through the process environment (`os.TempDir`, what `os.MkdirTemp("")` reads) and the injected `Getenv`; the controls set both.
- **"Before any credential, file or child"**: no API call (credential unused) and, in a row without `sandbox.env`, still exit 3 naming `TMPDIR` (not exit 1 `sandbox.env`), so the check precedes the credential read; no tofu or ovhcloud call, no leftover listing; the checkout, its `.local/` and the account's probe state unchanged, nothing in `TMPDIR`; in the runner, the run records' tree unchanged (the refusal precedes the run record's creation). Same for `--cleanup` and a fresh-process `Probe.Cleanup` (probe files kept).
- **Probe start order** (review r1, codex major): a probe start refused only inside `Execute` writes and then removes `probe.env`/`passphrase.env` (`Probe.run` removes a stateless run's files), so "no probe file left" cannot see the order. The runner row plants a regular file where the probes' directory goes: any write of a probe file fails first (not exit 3 naming `TMPDIR`). A second, unobstructed row requires the probe state unchanged, which catches a write whose error is ignored before the check (review r2, codex). Together they leave only "write, then delete, then refuse" unobserved (gap).
- **Credential read** (review r1, codex major): `ReadCredentialFile` opens with `O_NONBLOCK`, and a missing `sandbox.env` cannot tell a read from no read, so a check placed right after the read (before its error) passed. The cmd rows watch `sandbox.env` (and, for `--cleanup`, the run's `passphrase.env`) with inotify `IN_OPEN` (`opens_linux_test.go`; a no-op elsewhere): a refused run opens neither; the admitted `prefix-sibling` row shows the watch sees an open.
- **Recorded project** = the run's `TF_VAR_project_id` (lz-live: `LZ_PROJECT_ID_STATE` at start); controls are key-agnostic (some value of `probe.env` equals it). "Uses the recorded id" = every cleanup tofu call's `TF_VAR_project_id` **and** the cleanup's leftover check lists that project (a destroy in p1 with leftovers checked in p9 would pass falsely). Whether a cleanup still needs `LZ_PROJECT_ID_STATE` in `account.env` is not pinned.
- **Record without a project id**: refused = non-zero exit naming the project, no tofu call, state/passphrase/`probe.env` kept. Exit code not pinned (a damaged record is a failure like a missing passphrase, exit 1, not a guard refusal).
- **Ordering with T055's `cleanup-root-outside`** (writes a `probe.env` holding only a root outside the probes): it expects exit 3 naming the probe root, so T078 must confine the recorded root before requiring the recorded project (the throw-away's first version failed that T055 control; iteration 3).

## Learnings

- sensor: "before X is read" needs a read observer: a missing file proves only error precedence, and `O_NONBLOCK` opens defeat FIFO tricks; inotify `IN_OPEN` (watch after the test's own snapshots, drain before its next read, positive control on an admitted run) observes it deterministically on Linux.
- sensor: "before any file" for a step that deletes its files on failure needs two rows: an obstruction (a write fails before the refusal) and an unobstructed run (an ignored write error leaves the file).
- sensor: never match a short word in error text that the test's own temp paths contain (`t.TempDir` names carry the test name): match a phrase such as `project id`.
- spec: the T055 control `cleanup-root-outside` constrains T078's order — confine the recorded root before requiring the recorded project.
- tooling: `t077-impl.py` (throw-away for T078), `t077-scratch.sh`, `t077-sync.sh`, `t077-entry-scratch.sh`, `t077-mutants.py` (22), `t077-gates.sh`, `t077-review*.sh`.
