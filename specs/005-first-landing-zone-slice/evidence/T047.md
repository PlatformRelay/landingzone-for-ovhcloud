1. T046's interface is kept: `Chain(ctx, ChainOptions{ApplyOptions, Deadline, Signals, Lister})`; `destroy -- <instance>` is `Apply` with `VerbDestroy`. Started from the throw-away `t046-impl`, reviewed as new code: the stop signal now forwarded through `laneRunner.stopSignal`, SIGHUP handled as SIGINT (as the run core), inventory read errors reported, projects bound through `stacks.BoundAccount.Binding` (no second URN builder), record removal through files.go (`RemoveRecord`; `TestFilesOnlyWriter`), a chain whose selection is empty still destroys the target's ephemeral stacks and checks leftovers, summary.json written, and every way out of a chain ends with the summary line.
2. **Decision 1 (production lister)**: with `Lister` nil the chain reads sandbox.env, binds that credential to the account (`Bind`: endpoint, org, GET /auth/details) before the baseline listing and before any tofu call, and lists through `ApplyOptions.API` with it (`LeftoverCheck{API, Cred}`, T083/T084's `apiLister`). A refused binding stops the run with exit 3 before any listing or apply (nothing to destroy).
3. **Decision 2 (one destroy discipline)**: the run core's destroy (`Runner.Execute` destroy-on-exit and `--cleanup`, the companion's cleanup included) is `plan -destroy -input=false -out=<run dir>/destroy-<id>.tfplan`, `show -json` of that file through `Runner.Protect`/`live.Protect`, `apply -input=false <file>`; the file is removed afterwards. Applying a saved plan does not prompt (OpenTofu `apply` with a plan file; believed, as the lane's apply already relies on it).
4. **Decision 3 (baseline)**: before the first apply the chain lists every kind and writes, redacted, `<run-dir>/listings-before/<kind>.json` and `<run-dir>/baseline.json` (`run_id`, `listed` ids by provider type, `errors`). The final reconciliation reads `baseline.json` back after its own listing and marks each leftover listed there `before_run: true` (in leftovers.json). It does not change what counts as a leftover (R12's match column: prefix, run id, inventory, parent; T046's seeds model unprefixed resources that appear during a run and are not leftovers). A missing or foreign record, or a baseline listing with errors, is an error of the final report (fail, never pass).
5. **Decision 4**: a destroy whose plan passed the guard but whose apply fails is reported, the destroy goes on with the next stack, the failed stack keeps its record and state, the leftover check runs after the last destroy, exit 1.
6. `lz-live chain` takes `--deadline <dur>` (positive) and one target; `destroy` one target and no `--deadline`. The chain gets no ctx signal handling from main (live.Chain registers SIGINT/SIGTERM/SIGHUP itself); plan/apply/destroy keep `signal.NotifyContext`.
7. `mise.live.toml` holds only `"github:ovh/ovhcloud-cli" = "0.15.0"`; mise reads it only with `MISE_ENV=live` (verified 2026-10-08 with mise 2026.8.2 on a scratch copy: `mise config ls` / `mise ls --local` list it only under `MISE_ENV=live`; `t047-mise.sh`). mise.toml unchanged, so `verify:toolchain` and the image are unchanged.

## Learnings
- sensor: a fake root without its backend's variables hides a production failure (bootstrap's local backend needs `lz_account_dir`): make each fake root require what its generated backend block reads (r1 codex).
- sensor: a test reading a host-only file fails inside the offline entry, whose candidate allow-list is fixed (`lz-offline` main.go:194): split host-only checks and say where each half runs.
- guidance: an end-of-run record (summary.json, summary line) belongs in the outermost defer, after the locks are released, or a release error contradicts it (r1 codex).
- guidance: a guard called with an empty protected set checks only the document's form; say which check is the real guard (r1 Opus).
