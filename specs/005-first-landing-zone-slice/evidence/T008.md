## Learnings

- class `sensor`: hand-written mutants on HCL through `test:unit` in scratch copies work as for Go; per-root controls must exist in every root, not only the first (two survivors).
- class `spec`: `lz-live probe` as built (one root, admin credential, local state) cannot host the observations that need a second identity or a second state writer; T010's Verify line assumes it can (decision request 1).
- class `spec`: a probe root's backend path changes with each run id, and `lz-live` initialises in the root directory without `-reconfigure`: every second run of a root fails `init` (decision request 4); any task that runs a root twice must account for it.
- class `tooling`: the pinned provider schema can be dumped offline from the runtime's filesystem mirror (`t008-schema.sh`); prefer it to the 2.22-era kb docs for attribute names (`ovh_cloud_project.plan` is a block, `ovh_me_api_oauth2_client.description` and `ovh_cloud_project_alerting.email` are required in 2.21.0).
