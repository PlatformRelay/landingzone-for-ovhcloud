## Readings (for the coordinator to validate)

- **No new signature.** The plan fixes none: the control is black-box on `Probe.Start`/`Probe.Cleanup` (as T075/T077) with `Probe.Bind` (an existing field) recording each identity and the number of tofu calls logged before it. `identities()` is not called by the new rows, so T080 may reshape it.
- **"Paired whatever the case"** = a key whose name ends in `client_id` in any case pairs with the key of the **same prefix** ending in `client_secret` in any case (suffix case need not match between the two: `…_Client_Id` + `…_CLIENT_SECRET` is a pair). Bound = `Probe.Bind` receives `{endpoint, id value, its pair's secret}` before the companion's first child call; exactly the default and the published identity are bound (no S3 key bound).
- **Prefix case is not pinned.** `TF_VAR_P25_client_id` + `TF_VAR_p25_client_secret`, and two ids of one prefix in different suffix case with one secret, may be paired or refused; the control only requires that no id reaches the companion unbound (`refused-or-bound/*`). A `TF_VAR_` name is case-sensitive to OpenTofu, so treating prefixes as distinct is defensible; pairing them is also safe if both are bound.
- **"Looks like a credential"** is pinned by its rows only: half a pair in any case, a pair with an empty half, `…_clientid`/`…_clientsecret` (no separator), `…_Client_Key`, `…_CLIENT_TOKEN`, a secret of another prefix. Whether another name holding `client` (e.g. an identity URN published as `TF_VAR_tenant_client_identity`; storage-iam already outputs `tenant_client_identity`, `main.tf`) is refused is **not pinned** — T080's choice (review r1, Opus: the T076 gap's "any key holding CLIENT" would refuse such a name; the throw-away still does, which the control allows). The S3 keys (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`) pass unbound (T076 decision; every row publishes them, mutant S). `token`/`password` names without `client` are not pinned.
- **Refused** = the run fails (non-zero exit; the code is not pinned — today a half pair is a plain error, exit 1), no companion child runs, the root is still destroyed (T075: the identity must not outlive the run), no file under the config root, run record or stack roots, nothing on the terminal and nothing in the returned error (lz-live prints it; review r1) holds a published secret. The same applies on `--cleanup` (which re-reads `companion_env` from the root's state).
- **Every identity**, not only two: one row publishes three (review r1, codex).
- **The companion gets every published key under its own name** (no case normalisation of the names): pinned because a `TF_VAR_` variable name is case-sensitive.

## Learnings

- sensor: a "bind every X" control needs a row with more X than the obvious count (three identities, not two), or a truncating implementation passes (codex r1).
- sensor: a case-insensitivity control needs an irregular case on each side of a pair, not only lower/upper/title (codex r1).
- sensor: an error-leak mutant is equivalent when the run's error is already redacted (`redactedError`); move the redaction in the mutant to make it observable (iteration r1).
- tooling: `t079-mutants.py` (20, mutates the throw-away `runner.go` in a scratch copy), `t079-impl.py` (generates the throw-away from the worktree's `runner.go`), `t079-scratch.sh`, `t079-gates.sh`.
