## Readings (believed unless marked verified)
1. Order and selection semantics are T040's readings 1–9 unchanged; the implementation is the T040 throw-away reviewed as new code, with these changes: a missing manifest and an empty code digest are errors; a symbolic link in a stack's closure is refused (it was skipped silently: a linked file could change without changing the digest); module calls are found by parsing each directory's own `.tf`/`.tofu` files as HCL (`module` blocks, literal `source`), not by a line regex (review r1: a one-line `module "c" { source = "../c" }` was missed, a commented-out source followed); a file that does not parse, a module without a source or with a non-literal one, and a `.tf.json`/`.tofu.json` file in a closure are refused rather than digested blind. A record with data after the JSON object is refused.
2. **`stacks:order` offline inputs.** Published artefacts live in state buckets and the resolved-reference input needs `account.env`; neither is readable by lz-stacks (no credential, `TestAuthoringFlowReachesNoCredentialCode`). Offline, a producer counts as published at the digest its consumers recorded; when they disagree, or none recorded one and the producer has a record of its own, it counts as published at an unknown digest (consumers selected on `input` or `no-record`, never `blocked-on` an applied producer: review r1). A recorded resolved digest counts as current; every run prints `note: published artefacts and resolved references are compared by the live lane, not here`. The live lane (T059) calls `Select` with the real inputs. Records default to `<root>/.local/live/records` (research R21 / data-model *Live run record*); a missing default directory is a first run (every stack `no-record`, consumers `blocked-on` their unpublished producers, as T040's `blocked-first-run`). A `-records` the caller names is relative to the root (under `task` the process runs in `tools/`) and must exist (review r1: a wrong path read as a first run).
3. **Output format** (contracts/checks.md fixes only the content): `order a → {b, c} → d` (one group per topological level, `Levels`), then `selected <id> <reason>[,<reason>…] [blocked-on=<p>[,…]]` per selected stack in run order (`<instance>`: that stack only, or `unselected <id>`), then `note:` lines; exit 0; an id that is not a row, or a malformed record, `fail: …` exit 1; usage exit 2.
4. **Lock names** are `^[a-z][a-z0-9-]*$` (`account`, `tenant-<t>`; tenant names are manifest-validated): `DirLocks` refuses any other name before creating anything. A release is idempotent (first result returned again).
5. `DirLocks` uses `flock(2)` (`syscall.Flock`): Unix only. The tools run on Linux (entry, CI image, workstation); a non-Unix build of `internal/stacks` would fail to compile. Believed acceptable; not pinned.

## Learnings
- tooling: a Task target's `-run` regex decides whether a new test runs at all (`test:exchange` runs only `^(TestAdapter|TestPublish|TestExchange)`): name a new test into the target's prefix and check for `[no tests to run]`.
- guidance: scan OpenTofu module calls with an HCL parser, never a line regex (one-line blocks, comments); fail closed on anything the parser cannot resolve (non-literal source, JSON configuration).
- guidance: an offline report that cannot see an input (artefacts, resolved references) must not state its absence as fact (`blocked-on`); count what the records imply and print a note.
- guidance: before hardening a path check, run the fixed-point tests: generated fixture roots link `stages/`, so "resolved outside the root" is legitimate there.
