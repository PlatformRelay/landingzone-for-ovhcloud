## Task text (tasks.md)

T093 Resolve the pinned OpenTofu in lz-live before any credential is read, in
tools/cmd/lz-live/{probe,lane,bootstrap}.go and tools/internal/live/guard.go, test first in
tools/cmd/lz-live/tofu_test.go
- Requirements: FR-010, FR-011; ADRs: 0008, 0011. Depends on: T087.
- Verify: `task test:live-lane`: `lz-live probe|plan|apply|destroy|chain|bootstrap` resolve tofu
  through `stacks.PinnedTofu` (LZ_TOFU, else /tcb/tofu, else PATH, version equal to mise.toml's
  opentofu pin), where LZ_TOFU may also come from `~/.config/ovh-lz/live.env`; a tofu of another
  version on PATH is refused with exit 2 (`blocked`) naming the pin and LZ_TOFU, before any
  credential file is read, any API call or any tofu call; the resolved binary is the one every
  child tofu call uses; mutants per clause.

## Decisions taken here

1. **Process environment wins over live.env** for LZ_TOFU (dispatch: "LZ_TOFU in the process env
   may override it"). live.env holds no secret; it is already read by the guard.
2. **Every resolution failure is `blocked` (exit 2)**, not only the version mismatch: no tofu at
   all, an LZ_TOFU of the wrong version, a relative LZ_TOFU, a checkout without the pin. The
   earlier `TestBootstrapEntryStateRefusals/no-tofu` expected exit 1; changed (see *Test changes*).
3. **A relative LZ_TOFU is refused**: children run with `cmd.Dir` set to the stack, where a
   relative path names another file.
4. The `/tcb/tofu` candidate is `<OfflineMarker>/tofu` in lz-live (injectable; the guard already
   refuses when the marker exists, so it is unreachable on an admitted host).
