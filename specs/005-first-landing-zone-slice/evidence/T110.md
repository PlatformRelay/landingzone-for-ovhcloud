## Task text

T110 Retry a transient failure of the leftover check's read of a retained instance's state a bounded number of times, in tools/internal/live/chain.go and tools/internal/live/runner.go, test first in tools/internal/live/chain_test.go. Verify: `go -C tools test ./internal/live -run TestChainStateUnreadable -count=1` and `task test:live-lane` through the entry, against a fake tofu: when `init` or `show -json` of a retained instance fails with a transient answer (5xx, `connection reset by peer`, or `connection timed out` as in T049 run 3, which `transientMarks` gains), the state read is retried at most twice, after injectable waits (defaults 10 s and 30 s; a wait that would end after the run deadline is not taken); a read that then succeeds exempts that instance's objects, so the report has neither leftovers nor an error for it; after the last attempt, and at once on a 4xx or any non-transient error, the state error stays in the report and the outcome is `fail` (fail closed, as today); each retry prints one `LZ-LIVE retry` line naming the instance and nothing of tofu's output beyond the redacted error. Rows: transient-then-ok, transient-on-every-attempt, 403-not-retried, deadline-too-close; one killed mutant per clause (no retry, unbounded retry, retry on a 4xx, error dropped after the last attempt). Source: evidence/T049.md run 3 and gap 2.

## Choices

1. **What is retried.** The whole read (`prepare`, `init`, `show -json`, decode), as the companion's destroy retries its whole destroy (T095): a failed `init` leaves nothing to resume from. `into` (the exemption map) is written only after the document decoded, so a failed attempt adds nothing (verified by reading `retainedIDs`, 2026-10-14).
2. **Which deadline.** The leftover check runs under the destroy-on-exit's context (`dctx`, chain.go: its own `deadline` from the end of the applies), which is the deadline the read can still overrun; "the run deadline" in the task is read as that context's deadline, the same rule `destroyCompanion` applies (`time.Until(dl) < wait` → no retry, the error says `no retry: the deadline leaves less than <wait>`).
3. **Which answers.** `transient` unchanged but for the new mark: a 4xx anywhere in the output wins (no retry); a 5xx, the token-endpoint transport mark, `connection reset by peer`, and now `connection timed out` are transient. The source is evidence/T049.md:15 (run 3: reading account-governance's state for the exemption failed with `read tcp ... connection timed out` to Object Storage; verified 2026-10-14, after the strong review leg pointed out that an earlier draft of this line missed it).
4. **What the line prints.** `LZ-LIVE retry state read <instance> in <wait>: transient failure (attempt n of 3): <redacted error>`, where the error is the call's own (`tofu show <instance>: exit status 1`), never `tofuFailure.output`. tofu's stderr still reaches the (redacting) terminal as every lane call's does; the retry line adds nothing of it.
5. **Injection.** `ChainOptions.stateReadBackoff` (unexported, nil → `defaultStateReadBackoff` [10 s 30 s] in runner.go next to `defaultCompanionBackoff`); the chain harness passes `testBackoff` (50 ms, 100 ms) unless a row sets its own; `TestTestRunnersInjectWaits` pins the default and the harness's injected value (T114's guard, extended).
6. **Fake.** `laneStack.ReadFail{Call, Answers}`: the stack's first `init` or state `show -json` calls fail with those answers (a counter file next to the log); every fake tofu call now logs its end time (`laneCall.At`) so a row can check each retry's wait. Rows count the reads after the last destroy (where the leftover check runs), so an applied stack's own `init` is not counted.

## Harness gaps

1. **The deadline rule guards the wait, not what follows it** (the strong review leg, WARNING, confidence 45; verified by reading `chain.go`): with the destroy context's deadline just over a wait away, the wait is taken, and the retried read and the leftover listings after it can run into the deadline, so the report then also carries listing errors. The outcome stays `fail` (fail closed holds); only the report's detail suffers, and only when the destroys used up nearly the whole budget (45 min by default). The task fixes this rule ("a wait that would end after the run deadline is not taken", as `destroyCompanion` does), so a reserve for the read and the listings is a change of the task's rule: proposed as a follow-up, not done here.
2. **No shared retry budget across instances** (strong review leg note): four retained instances each failing transiently can spend up to 4 × 40 s before the listings start, from the same budget. Accepted with gap 1; the same follow-up would cap it.
3. **The new `connection timed out` mark also widens the companion's destroy retry** (`transient` is shared; intended), with no companion-side row for it (strong review leg note).
4. Live proof: no real transient state read has been retried yet; the next chain run (owner) shows it if one occurs. Fakes only, as the live-lane rules require.

## Maintainability

1. Duplication: `readRetained`'s loop repeats `destroyCompanion`'s shape (attempt, transient check, deadline check, line, wait) on a different receiver; a shared helper would have to abstract the call and the line, more code than the two loops. 2. New abstraction: `readTofu` (tofu keeping stderr in a `*tofuFailure`) — one caller pair. 3. Hidden coupling: `transient` now serves two retries; a mark added for one applies to both (intended: the same API). 4. Naming: `readRetained`, `readTofu`, `stateReadBackoff`, `defaultStateReadBackoff`. 5. Dead code: none. 6. Error paths: every exit of the loop returns the error (attempt count appended after a retry); a cancelled context joins its cause. 7. Test readability: one table with named fields. 8. Docs drift: the how-to's leftover paragraph updated; both pages' `chain.go` pins re-checked.

## Learnings

- sensor: a fake's stderr starts with its secret-echo line, so "the answer text is absent from the line" passes a mutant printing the output; pin a printed line's whole shape (iteration 3).
- tooling: `mutate.py` copies `tools/` only; the chain harness needs the checkout (`stacks/`): `~/.local/share/ovh-lz/review/t110-mutate.py` copies the checkout and judges by one test's own lines.
- spec: a "not past the deadline" rule for a retry before further work should reserve time for that work; proposed follow-up: `readRetained` retries only when the destroy context leaves the wait plus a reserve, and a shared budget across retained instances.
