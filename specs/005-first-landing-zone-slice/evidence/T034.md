## Choices made in this task (believed; for coordinator validation)
- **Every string of the manifest has a value rule** (pattern or enum), held once in `manifestRules` and mirrored by the schema; a string without a rule is refused (fail closed). The rules data-model did not state: `org`, tenant and environment names `^[a-z][a-z0-9]{0,15}$` (one naming segment: no `-`, so `a-b`+`c` cannot collide with `a`+`b-c`, and no `/`, `.`, so no name leaves its directory in `stacks/…` or its state key); `metadata.name` `^[a-z][a-z0-9-]{0,62}$`; project refs `^[A-Z][A-Z0-9_]{0,62}$` (the `<REF>` of `LZ_PROJECT_ID_<REF>`); `forge` host + path; `state.region` lower-case letters; `state.endpoint` `https://` host only; `cidr` dotted quad + prefix length (syntax only; semantics stay with project-network, T085); `stage_source.kind` `local | git`. data-model *Rules* now states the name rules.
- **`DUPLICATE_NAME`** (new code, values group): a tenant, an environment of one tenant or a region of one environment named twice. Before, the second entry silently shadowed the first in the membership map.
- **A platform manifest refuses `external` entries** (`PLATFORM_ROWS`): it owns all its producers; otherwise a producer could resolve to an entry nobody plans. data-model amended.
- **JSON type mismatch** (e.g. `"vlan_id": "0"`) is `INVALID_VALUE`, not `MANIFEST_SYNTAX` (decoding group; `*json.UnmarshalTypeError`).
- **`git` stage source decodes** and is exposed as `Manifest.StageSource`; generation refuses it (`STAGE_SOURCE_NOT_IMPLEMENTED`, contracts/checks.md, T038).
- **Reserved stages carry only their name** in the stage table (no scope, producers or backend): data-model and R10 give none and the decoder refuses them before scope matters.
- Producers are resolved from the stage table, not per-stage code: a producer of scope S matches the consumer's dimensions down to S; exactly one match or `UNRESOLVED_PRODUCER` (also for an ambiguous match, unreachable with today's table).
- State bucket names are concatenated (`<org>-bkt-state`, `<org>-<tenant>-bkt-state`) as data-model *Derived instance fields* gives them; equal to `modules/naming`'s default template for these segments (believed; T037/T038 plan the buckets and `NAME_COLLISION` checks planned names).
- Not exposed yet: per-region `network`, `budget_alert`, `quota_guard` (decoded and checked, not on `Manifest`; T033's `Tenants` DeepEqual pins the current shape). T038 adds them when generation needs them.

## Learnings
- sensor · A strict decoder that walks Go maps reports a different fault per run when a document has two; pin "same code over N runs" whenever a refusal code is part of a contract (here `conforms`, fixed for every `DecodeStrict` caller).
- sensor · For a trust boundary, make "every string has a value rule" itself a test (the agreement test walks the schema and fails on a string without pattern or enum), and fail closed in the decoder on a rule-less string.
- tooling · A test that duplicates a whole collection entry to provoke a "named twice" refusal is shadowed by the nested check; vary everything below the repeated name (mutant `duplicate-tenant-allowed` survived until then).
- tooling · Decode schema keywords whose presence matters (`const`) as raw JSON: a `*string` reads `"const": null` as absent.
- spec · Spec-set rules the data-model did not state (name patterns, one project per environment, no `external` in platform scope) were added to data-model in the same change as the code, as proposals for coordinator validation.
