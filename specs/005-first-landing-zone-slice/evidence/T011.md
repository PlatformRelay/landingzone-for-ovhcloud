## Interface the tests pin (for T012; readings for the coordinator)
Inputs (`variables.tf`): `org`, `kind`, `role`, `instance`, `managed_in` required; `tenant`, `environment`,
`region`, `slot`, `name_override` default `null`; `labels` (extra) default `{}`; `template` defaults to
the data-model default template. Outputs: `name`, `labels`, `algorithm_version`. Readings (believed,
from data-model/research; the plan does not fix field names):
1. Every name error (unknown kind, kind without a `kinds.yaml` row, empty required segment, over/under
   limit, charset, ends, doubled punctuation, IP-like, invalid override) fails `output.name` (a
   precondition); a label-set key in the extra labels fails `var.labels` (a validation).
2. Absent coordinates are `null` and omitted; `org` and `role` are required, `""` there is the "empty
   segment". `""` in an optional coordinate is not pinned (gap 2).
3. The template's case rule lowers every coordinate (`GRA11` → `gra11`, `LZ`/`Demo`/`Runtime`/`Blue`);
   an override is never lowered.
4. Every kind of the default template has a `kinds.yaml` row; only a kind with no row is refused
   (research R15 "refuses names for kinds without a row"). Non-bucket limits stay UNVERIFIED, so the
   tests use short `[a-z0-9-]` names for them and test limits on buckets only. T012's Verify text
   ("refused for cloud kinds without a limit") must be read as "without a row", or concrete names for
   every default kind (this task) cannot pass — decision for T012/coordinator if read otherwise.
5. `lz:run-id` is refused in the extra labels like the five mandatory keys (data-model *Label set*:
   "keys in the set above are rejected"), and the naming module does not emit it (the label table's
   source column says "live lane"; data-model.md:175 also says "`none` offline" — decision 2); the
   live lane adds it outside the naming module. Label-set keys are refused in any case (`LZ:Tenant`),
   as the live lane refuses run-controlled names in any case (T082); whether OVHcloud tag keys compare
   case-insensitively is UNVERIFIED.
6. `managed_in` is passed whole (`<forge>//<path>`, derived by the generator, data-model *Derived
   instance fields*); `algorithm_version` is `1`.
7. Bucket rules pinned (verified 2026-10-07, kb): 3–63 characters, lowercase alphanumerics, `.` and
   `-`, alphanumeric at both ends, no doubled punctuation, not an IP address
   (`storage-and-backup/object-storage/s3-limitations.mdx:49-54`;
   `terraform-provider-ovh/docs/resources/cloud_storage_object_bucket.md:58`). Other kinds' name limits:
   no length or charset in the provider docs (`cloud_project_network_private.md:25`,
   `iam_policy.md:86` "must be unique", `me_identity_group.md:21`, `me_api_oauth2_client.md:45`) —
   UNVERIFIED.

## Learnings
- tooling: `tofu test` (1.13) skips the rest of a file after an errored run (`Missing expected failure` counts), so a test task's red on one file hides later runs — prove per-run red on a split copy (`~/.local/share/ovh-lz/review/t011-split.py`).
- tooling: `run.<name>.<output>` is refused in `assert` conditions; cross-run equalities need literal expectations in each run.
- guidance: a rejection run whose flaw a neighbouring rule also refuses (empty segment on a bucket) is not sensitive to its own clause — pin each refusal on a kind where only that rule applies.
- guidance: on a stub, index into an empty output errors instead of failing — use `lookup()`/`tomap()` so the red is an assertion failure.
