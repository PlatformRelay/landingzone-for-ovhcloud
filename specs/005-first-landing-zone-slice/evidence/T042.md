## Readings (believed unless marked verified)
1. **Admin "as expected"** = exactly one IAM policy bound to the client's identity, allowing exactly `account:apiovh:iam/*`, `account:apiovh:me/*`, `publicCloudProject:apiovh:*` on exactly `urn:v1:eu:resource:account:<account>` and `urn:v1:eu:resource:publicCloudProject:*`, with no `except`/`deny` and no permissions group; the client's flow `CLIENT_CREDENTIALS`. Research R13 says "on the account and project URNs"; the captured `lz-sandbox-admin` policy (T087 capture `tests/fixtures/ovhcloud/captured/20261007T133803Z-aeee/listings/ovh_iam_policy.json`, verified 2026-10-08) uses the project wildcard, and T044 needs `admin unchanged` on it, so the wildcard is the expected shape and the fresh run creates the same. A per-project resource list would make the current sandbox `fail` — **coordinator to confirm** (decision 1).
2. **Rejected credential**: without a working credential `identify` cannot learn the account, so the `blocked` (exit 2, naming `--fresh-account`) may come at `identify` or `admin`; the test accepts either and requires that `admin` is never `unchanged`.
3. **Admin missing**: an OAuth2 client with no policy gets 403 on every read in the fake (IAM modelled per action); the throw-away reads that 403 as `blocked` (admin missing). The real API's answer for a policy-less client is UNVERIFIED (believed 403 by the IAM model, `kb/api/v1/me.json` iamActions).
4. **Revoke**: `GET /auth/currentCredential` then `DELETE /me/api/credential/{id}` signed with the root keys (R13; routes and `credentialId` verified in `kb/api/v1/auth.json`, `me.json`, 2026-10-08); it is the last root-key call, after the state phase, and runs on every exit path once the three keys were read (state failure, aborted reference prompt, admin API failure, interrupt via a cancelled context, binding refusal). A failed revocation is `fail` naming the Control Panel step.
5. **Root keys read** right after the guard, before `identify` (identify needs them under `--fresh-account`); three `ReadSecret` calls (AK, AS, CK); never without the flag.
6. **Signing in process** (R19): the fake recomputes `"$1$" + SHA1_HEX(AS+"+"+CK+"+"+METHOD+"+"+URL+"+"+BODY+"+"+TSTAMP)` with URL the full request URL (kb `first-steps.mdx` *First API Usage*, verified 2026-10-08; full-URL reading follows the guide's examples, UNVERIFIED against the live API until T045) and records an issue if an application secret appears anywhere on the wire, or a key outside its header.
7. **"root keys in argv or a child environment"**: the phases T042 covers start no child. Pinned: no recorder named `tofu`, `ovhcloud`, `curl`, `wget` or `openssl` (first on `PATH`) runs; the process environment holds no root key inside the state phase and after the run (a key set, used by an unrecorded child and unset again in between is not observed: gap 1); the state phase is handed only the admin credential. "stdout or stderr": the injected `Stdout`, the process's own `os.Stdout`/`os.Stderr` (swapped for files during each run) and the returned error, which `lz-live` prints to stderr.
8. **"`sandbox.env` is written once"**: one rename into place or close-after-write of `sandbox.env` in the config root per fresh run (inotify; a create alone is not counted, an in-place rewrite is), and an unchanged tree on the second run. After an admin API failure (client created, policy not) `sandbox.env` is not written at all.
9. **Migration**: "moved before anything is written" = no create, rename or close-after-write outside `accounts/<old>/` before `sandbox.env` lands there; "none of its files is read afterwards" = no open in `accounts/<old>/` after that event (inotify, one queue, kernel order). An open is what inotify observes: a descriptor opened before the move and read after it is not seen (gap 5). Reading the old `sandbox.env` before the move (to learn its account through `GET /auth/details`) is allowed.
14. **Orphan admin client** (review r1): after an admin API failure the client exists without its policy; the retry with new root keys must leave `sandbox.env` naming a client bound to exactly one expected policy. Whether the orphan is deleted, reused or reported is not specified and not pinned — **coordinator to decide** (decision 2; proposal: T043 reports the orphan's client id in the `admin` detail so the owner deletes it, since deleting needs the root keys anyway and they are at hand).
10. **Project references**: each missing `LZ_PROJECT_ID_<REF>` is one echo-on prompt naming that variable; the account's projects (from `GET /cloud/project` with the root keys) are shown before the first prompt; an aborted prompt is a `ReadLine` error. Abort after `identify` = the operator aborts the `DEMO_DEV` prompt (journey c).
11. **Passphrase**: `TF_VAR_state_passphrase` of at least 43 characters (32 random bytes encoded), different per account; an existing one is never rewritten; one others can read is refused (`file-mode`), not tightened (data-model: the lane refuses group/world-readable files).
12. **In-repo credential file** = a config root inside the checkout, directly or through a symlink: refused (exit 3) before any API call, prompt or write; the condition name is T043's.
13. **"fake terminal in testdata/"**: the fake terminal and fake API are code in the test file (like `fake_test.go`); `testdata/bootstrap/world.json` holds the fake accounts. The current sandbox is the T087 capture (client and both policies verbatim, anonymised ids), the client's other fields and the fresh account follow the kb schemas (`oauth2.client`, `oauth2.clientSecret`, `auth.Details`, `auth.ApiCredential`, `iam.policy.Response`; `GET /cloud/project` → `string[]`). Generating command for the copied part: `t065-anonymise.py` (T087 provenance); no live call.

## Harness gaps
1. A child started by an absolute path, or through a binary other than `tofu`, `ovhcloud`, `curl`, `wget`, `openssl`, is not recorded; the process environment is checked inside the state phase and after the run, so a key set and unset around an unrecorded child is not seen.
2. The inotify rows (written once, migration order, no read after the move) are Linux-only; elsewhere they are skipped (`fsEventsObservable`). `lz-live` runs on the Linux host.
3. Live facts the fake assumes are UNVERIFIED until T045: full-URL signing, the 403 of a policy-less client, `GET /auth/currentCredential` with root keys, created-client propagation delay.
4. SIGKILL cannot be revoked from; the interrupt case is a cancelled context (SIGINT/SIGTERM handled by the caller, T043).
5. "Read" is observed as an open (inotify `IN_OPEN`); a descriptor kept from before the move is not seen. The HTTP transport is the injected one; an implementation building its own client to a real endpoint is not blocked by the harness (it would fail the call assertions, not leak through them).
6. Repair of a drifted (or replacement of an existing) admin through `--fresh-account` is not tested: the fixture's current-sandbox account has no root keys and the spec does not say whether the run replaces, repairs in place or refuses (decision 3). Without the flag, drift is pinned as `fail` with no account change.
