## Observed tool behaviour (verified 2026-10-07, pinned tofu 1.13.0; probe `~/.local/share/ovh-lz/review/t023-probe/`)
- `override_resource` cannot set a configured (non-computed) attribute: `Non-computed field 'allow' is not allowed to be overridden`. So a test cannot prove that an output is read from the resource rather than recomputed from the same input (harness gap 1).
- The same error on a `mock_resource` default turns that default into a tripwire: a mock default for a non-computed field of a type that is never planned is inert; any planned instance of that type fails the run with `Non-computed field … is not allowed to be overridden` (probe: `ovh_me_identity_user.group`, `ovh_cloud_project_user.description`; absent → pass, present → error).
- An `override_resource` target in a module call that does not exist fails every run (`Module not found`); one in a declared call with no matching instance is silently unused (T021). The component stub therefore declares the three overridden calls with `count = 0` / `for_each = toset([])`.
- `run.<name>.<output>` is not readable in a plan-only run's assertion (`Reference to undeclared resource`), and passed through `variables` it is unknown (`Unknown condition run`). "Leaves the first entry unchanged" is therefore pinned by the same literal `demo` values and keyed addresses in a one-tenant run and a two-tenant run.

## Learnings
- tooling: a `mock_resource` default on a non-computed field is a tripwire: inert while the type is unplanned, an error (`Non-computed field … is not allowed to be overridden`) on any planned instance — a cheap "this type is never planned" sensor inside `tofu test` (tofu 1.13.0).
- tooling: `override_resource` cannot set configured attributes, so output-to-resource binding stays a review item (or a plan-capture check); a target in an undeclared module call errors (`Module not found`), so a stub declares the overridden calls with no instance.
- tooling: `run.<name>` outputs are not usable in plan-only assertions (undeclared, or unknown through `variables`); pin "unchanged" by the same literals in two runs, with the added key sorting first so an index-keyed implementation shifts.
- guidance: a second tenant in a fixture must sort before the first (`alpha` < `demo`), or `count`/index keying passes the "unchanged" check.
