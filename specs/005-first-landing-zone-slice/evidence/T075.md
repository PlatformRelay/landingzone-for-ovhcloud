## Readings (for the coordinator to validate)

- **No new signature.** The plan fixes none, so the control is black-box on `Probe.Start` (as T077). The contract between a probe root and lz-live is two names the tests and the HCL share: a probe root's companion lives in its `companion/` directory, and the root publishes the companion's variables as the sensitive map output `companion_env` (environment variable name → value). The throw-away's internals (`companionStage`, `Redactor.Add`, the record file name) are not pinned.
- **"Under the run directory"** = the run's probe directory `accounts/<account>/state/probes/<run-id>/` under `~/.config/ovh-lz` (where the passphrase already lives; T008 decision 1 option A: "writes 0600 into the probe directory"), never the checkout's run record `.local/live/<run-id>/`, a stack root or the child's HOME. A file in the run record is refused by the control (mutant C2 "in the run record").
- **"That identity alone"**: the companion child's credential variables are exactly the published ones — `OVH_CLIENT_ID`/`OVH_CLIENT_SECRET` of the P9 tenant identity (the default provider configuration), `TF_VAR_p25_client_id`/`_secret` of the P25 identity (an aliased provider: P25 needs a second, tag-conditioned identity, which the P9 identity's unconditional `region/storage/*` would hide; T008), and `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` of the P1 S3 user (the companion's S3 backend). No environment value or argument of any companion child (init, plan, apply, second writer, destroy) contains the admin client id or secret; `OVH_ENDPOINT` (not secret) passes.
- **P26 tenant binding** (review r1, codex major): the identity published for the companion is bound to the run's account through `GET /auth/details` (`live.Bind`, as the sandbox credential, G13) before any companion child; a credential of another account is refused (exit 3) and one the API refuses fails the run (non-zero); either way no companion child runs, the root is still destroyed (identity with it) and no file keeps the secret. Pinned black-box at the `lz-live probe` entry (`TestProbeIdentityBinding`), where the API lives; the internal control does not require a binder (a `Probe` without one binds nothing in the throw-away).
- **P1–P3 second writer** = a second writer of the companion's own state: the companion's backend is `s3` with `use_lockfile` and client-side encryption on storage-iam's new bucket `lzprobe-p1-<run-id>` (so storage-iam also creates the S3 user, credential and bucket-scoped S3 policy, as state-backend does). Started while the companion's apply holds the lock (the fake holds it from the apply's start until a second writer is refused, 10 s at most); it must be a `plan` that takes the lock and does not wait for it (the fake refuses only lock-taking commands — plan, apply, destroy, refresh, import, state rm/mv/push — and none with `-lock=false` or a non-zero `-lock-timeout`, review r1/r2), from a data directory its own `init` prepared (review r2); its lock error goes to the run record; the expected refusal does not fail the run. What the run does when the second writer is *not* refused (P1 refuted) is not pinned (T010 reads the record).
- **P9/P25/P26 observations** are the companion root's content, pinned offline by its `tofu test` (mocked providers): P9 network/subnet/bucket named `lzprobe-p9-<run-id>`; P25 reads bucket A through the P25 identity (`check`) and expects bucket B denied (`check`, refutation message); P26 expects `GET /me` denied (`check` on `data.ovh_me`). The provider authenticates the tenant identity through `GET /auth/details` at configuration (provider docs `index.md:211`, kb, verified 2026-10-07). A denied read inside a `check` block is a warning, not an error: believed (Terraform semantics), UNVERIFIED for OpenTofu 1.13 until T010.
- **Second stage only after a full apply of the root, never on `--plan-only` or `--cleanup`** in the throw-away; neither is pinned (see *Harness gaps*).

- After a failed companion destroy the root is still destroyed (row `companion-destroy-fails`): the identity does not outlive the run, and the companion's leftovers are the leftover check's and the admin's to remove — a design choice recorded here (Opus r2 note).
