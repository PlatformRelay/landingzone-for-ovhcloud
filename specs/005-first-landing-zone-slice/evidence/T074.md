## Design

- **Data directory**: `<scratch HOME>/tofu-data/<stack id>`, set by `session.tofuCmd` on every tofu call (init, plan, show, apply, state list, destroy): per run (each `Execute` makes its own 0700 HOME, `scratchHome`) and per stack (review r1: one directory per run would let a later stack's init replace an earlier stack's backend and module manifest, and that stack's destroy-on-exit would then run on the other root's data), outside the run record, removed with the HOME when the run ends. Outside the checkout as long as the HOME is: `scratchHome` uses `os.MkdirTemp("")`, i.e. `$TMPDIR`, so an owner `TMPDIR` inside the clone would put HOME and data directory there (review r1 minor; true of the HOME since T055; a gap, not "by construction"). A `--cleanup` is a fresh `Execute`, so it initialises its own directory (`initArgs` before `destroy`, unchanged). T008 decision request 4 recommended `.local/live/<run-id>/`; T073's controls forbid the checkout, `.local` included, so the HOME it is. A caller's `TF_DATA_DIR` in `Runner.Vars`/`Creds` is dropped (and the per-stack value is appended last, which `os/exec` lets win).
- **`TF_VAR_run_id`**: set in `Probe.run` (start and cleanup) to `Runner.ID`.
- **`TF_VAR_project_id`**: `LZ_PROJECT_ID_STATE` of `account.env` (T073 reading, accepted by the coordinator); a missing key fails before the run id is minted and before any child, for start and cleanup (a destroy evaluates the root's variables; believed, tofu requires every variable without default).
- **Plan-only roots**: by the name of the resolved root directory (`probeRoot` resolves symlinks; T073 reading, accepted), refused with `*live.Refusal{Condition: "plan-only"}` (exit 3, detail naming `--plan-only`) right after `probeRoot`, before `sandbox.env` is read, before any file and any child. `--cleanup` is not checked: a plan-only run writes no state, so it leaves no `probe.env` to clean up.
- **Probe roots**: `variable "run_id"` validated equal to the state path's directory name (cross-variable validation: accepted by the pinned tofu, lint and `tofu test` through the entry); `variable "project_id"` (no default: a run without it fails init/plan); `data "ovh_cloud_projects"` keeps the listing, a postcondition fails the plan when no project of the account has that id, and `local.project` selects by `service_name == var.project_id` instead of `one()` of all projects. Locals keep their names, so `main.tf` is unchanged (project-import's output description only). Generated into all seven `probe.tf` by `t074-roots.py` (same block, as T008's generated copies).

## Learnings

- sensor: `TF_DATA_DIR` replaces each root's `.terraform` (backend and module manifest), so it must be per run **and per stack**; a per-run control with one stack cannot see the shared-directory defect — give data-directory controls two stacks.
- sensor: a selection fixture over a set must place the wanted element between others in tofu's set order (`tofu console` on `tolist(toset([...]))` shows it), or "first"/"last" mutants survive; a namesake element kills "select by name".
- tooling: `lz-check unit` reports no run names; HCL mutants are judged on a diagnostic only the target run prints (`Missing expected failure … <address>`, its own `error_message`), and a mutant with `condition = true` is an invalid configuration, not a kill.
- tooling: mutation scripts keep the whole baseline log (T073's red baseline could not be attributed from a 4 000-character tail); never run two mutation scripts on one scratch directory at once.
- tooling: `t074-mutants.py` (30 Go), `t074-hcl-mutants.py` (7 HCL via the entry), `t074-roots.py` (probe-root generator), `t074-roots-identical.sh`, `t074-setorder.py`, `t074-flake*.sh`, `t074-gates.sh`.
