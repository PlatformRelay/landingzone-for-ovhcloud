## Design choices

- **`.tofu` → `UNSUPPORTED_CONFIG`** (T005 left the choice to T006). Reasons: fail closed with one finding; OpenTofu lets a `.tofu` file replace a same-named `.tf` file (believed, OpenTofu language docs "files and directories"; the load of `*.tofu` itself verified in T005 with pinned tofu 1.13.0), so parsing both would mean modelling that override to judge the effective file set; the repository has no `.tofu` file and the slice writes `.tf` only. Detail text says "use .tf". `.tofu.json` joins the JSON refusal.
- **Started from** `~/.local/share/ovh-lz/review/t005-impl-dependencies.go`, reviewed as new code. Changes against it: the purity facts are returned by `parse` instead of a closure-captured variable reset per call (side channel); `generated` is read from the header before parsing, so a generated stack file that does not parse is `PARSE_ERROR` only, not also `HANDWRITTEN_INSTANCE` (new control `TestDependenciesGeneratedParseError`, written and run before relying on it; its mutant is killed); `.tofu` gets its own detail text; findings name the role (`a stage declares a state backend`).
- `REMOTE_STATE` and `HANDWRITTEN_INSTANCE` are reported before classification, so they also fire for an `UNCLASSIFIED` directory; `LIBRARY_*` only for `library`/`stage` layers (examples, test roots and stacks may configure backend and provider, pinned by the T005 positive fixture).
- Generated-header check stays a prefix check (`bytes.HasPrefix`), as before T006: a stricter first-line equality buys nothing, since whoever can write a suffix can write the exact header. The rule guards against accidents and review blind spots, not a hostile author.

## Learnings

- sensor: a new rule built on an existing classifier inherits the classifier's exemptions (`fixtures` anywhere, `tests`/`examples` anywhere, header → instance); a security rule's review must probe those inputs, not only the rule's own predicate.
- sensor: a recursive OR-merge (`x = x || f(child)`) needs a control where the child comes after a positive, or an overwrite mutant survives.
- tooling: `t006-mutants.py <wt> <scratch>` copies `tools/` and `tests/` fresh each run; reuse it for later guard tasks.
