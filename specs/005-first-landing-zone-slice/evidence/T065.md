## Decisions taken here

1. **Storage regions.** Every region of `GET …/region` gets its detail asked
   (`GET …/region/<r>`, recorded under listing key `ovh_cloud_project_region`, not a matrix kind);
   storage is listed only where a service name starts with `storage-s3` (UNVERIFIED rule); there a
   404 or any failure stays an error. A detail without `services` (or `null`) is an error: the
   schema says `canBeNull: false`, so absence means the check cannot tell. A DOWN service still
   counts (its listing then fails, closed). Floor: when no region of the listed projects offers
   Object Storage the check fails — every project of the slice holds buckets (state, runtime), and
   the run record shows the sandbox project has at least one region whose storage listing answered,
   so a wrong name rule turns the next run red instead of hiding every bucket. (A first draft
   applied the floor only when the run created or retained a bucket; that leaves a plan-only run
   blind to buckets leaked by an earlier run, so it was made unconditional.) Rejected: treating a 404 as empty (what the dispatch forbids); deriving the S3
   region from the compute region's letters (T031's UNVERIFIED mapping, would ask regions the
   project may not list); listing `storage` (Swift) regions too (the path is S3-only per
   `:58768`; believed to reproduce the 404s).
2. **Tags.** Absent or `null` `tags` = no tags (schema `:2661-2667`), recorded as `{}`; a `tags`
   of another type or a non-object answer stays an error.
3. **Anonymisation** (script `~/.local/share/ovh-lz/review/t065-anonymise.py`, outside the repo):
   generic regexes, consistent mapping — project id → `f000…0001`, account handle →
   `xx000001-ovh`, three UUIDs → `00000000-0000-4000-8000-00000000000{1,2,3}`, `[REDACTED]` client
   id → `EU.0000000000000001`; names kept (resource names, no personal data); the script fails if
   an original value survives. A grep for fragments of the originals over the committed tree finds
   none (verified 2026-10-07).
