## Decisions taken here

1. **Storage regions** (as revised after review round 1). Every region of `GET …/region` gets
   its detail asked (`GET …/region/<r>`, recorded under listing key `ovh_cloud_project_region`, not
   a matrix kind) and its storage asked (`GET …/region/<r>/storage`). A 404 to the storage listing
   is accepted as "no Object Storage here" only when the detail names every service and none starts
   with `storage-s3` (UNVERIFIED rule); a 404 where a `storage-s3` service is listed, an unnamed or
   `null` service, a 404 on a later page, and any other failure are errors. A 200 is always parsed,
   whatever the services say — so a wrong name rule can turn a 404 into an error, never hide a
   bucket. A detail without `services` (or `null`) is an error (`canBeNull: false`). Floor, per
   project: a project in which no region's bucket listing succeeded fails (every project of the
   slice holds buckets; the run record shows the sandbox project had one such region). Round 0
   listed storage only where the rule matched and kept a global floor; both review legs showed a
   region with an unrecognised Object Storage service, or a second project, would then be skipped
   while the check passed (fail-open) — fixed in round 1. Rejected: treating every 404 as empty
   (what the dispatch forbids); deriving the S3 region from the compute region's letters (T031's
   UNVERIFIED mapping).
2. **Tags.** Absent or `null` `tags` = no tags (schema `:2661-2667`), recorded as `{}`; a `tags`
   of another type or a non-object answer stays an error.
3. **Anonymisation** (script `~/.local/share/ovh-lz/review/t065-anonymise.py`, outside the repo):
   generic regexes, consistent mapping — project id → `f000…0001`, account handle →
   `xx000001-ovh`, three UUIDs → `00000000-0000-4000-8000-00000000000{1,2,3}`, `[REDACTED]` client
   id → `EU.0000000000000001`; names kept (resource names, no personal data); the script fails if
   an original value survives. A grep for fragments of the originals over the committed tree finds
   none (verified 2026-10-07).

## Learnings

- class `sensor`: replaying a real run record through the fake API should first reproduce the live
  run's exact errors (here 8 × 404 + 1 × no tags) — that pins the replay's fidelity before the fix.
- class `sensor`: a capability rule decided from an UNVERIFIED name list must only decide whether
  an error is acceptable, never whether to ask: skipping the request turns a wrong rule into a
  silent miss (round 1, both legs).
- class `guidance`: scope a floor ("at least one X") like its premise (per project); a record file
  written only on success is evidence in itself (`storage.json = []` proved a region answered).
- class `tooling`: codex can fail with "model at capacity"; the subagent fallback worked.
