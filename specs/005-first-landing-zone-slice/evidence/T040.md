## Interface (this task's choice; T041 implements it)

- `Select(SelectOptions{Manifest, Code, Resolved, Artifacts, Records}) ([]Selected, error)`; `Selected{ID, Reasons []Reason{Kind, From}, Blocked []string}`, in run order; reason kinds `no-record`, `code`, `input` (From = producer), `resolved`, `consumer` (From = the selected data producer). A row without a current code digest is an error. `Record{code_digest, consumed, resolved}` carries the live lane's JSON names (`live.Record`), so T041 can read `records/<id>.json`; the stacks package must not import `live` (`TestAuthoringFlowReachesNoCredentialCode`).

- `LockStore{TryLock(name) (release, error)}` (non-blocking; wraps `ErrLocked` when held); `DirLocks(dir)` the file-backed store; `RunLocks(m, ids) ([]string, error)`; `HoldRun(store, m, ids) (release, error)`.
- New import edges: none (stub: `errors`; tests: standard library). `test:dependencies` green, no fitness function extended.

## Readings (believed unless marked verified)
1. **Run order** = topological levels over the data and authority edges between rows (level = longest producer chain), ties by stack path. Verified 2026-10-07 with the pinned Terramate 0.17.3 (`list --run-order` on reconciled sandbox and growth roots; probe test in the scratch copy, deleted): growth emits all four `project` stacks before any `project-network`, and orders level 3 by path (`…/gra11/project-network`, `…/gra11/runtime-blue`, …), which neither a lexical-first Kahn order nor row order gives; level-then-path reproduces sandbox, growth, tenant-only and the real tree (throw-away green).
2. **"captured `terramate list --run-order`"** = the pinned binary's output, produced during the test from a copy of the real `stacks/` tree (with `terramate.tm.hcl`) and from reconciled fixture roots, rather than a stored text file: the fixture rule (generated by the pinned tool) holds and the capture cannot drift from the tree.
3. **Code digest closure** = the stack directory (OpenTofu working directories `.terraform/` excluded) plus every directory reached by a local module `source` from it, recursively; a file reached by no closure selects nothing. Pinned per layer: stack file, stack test, stage, component, module, shared module (`naming`: all six), unreached file, working directory.
4. **Blocked**: a selected consumer lists each data producer without a published artefact in `Blocked`; it stays in the selected set (quickstart: "consumers of an unpublished producer show `blocked`"). A consumer whose own producer published is not blocked even if a stack further up is.
5. **Resolved digest per stage**: as T060 reading 4 (governance, project, bootstrap, tenant-state take one; project-network and runtime none). The tests compute it with `Adapt`, the function whose `Inputs.Resolved` the record stores (T061).
6. **Locks**: account and account-tenant stacks take `account` (FR-009); environment and region stacks `tenant-<t>`. Whether an account-tenant stack also takes `tenant-<t>` is left open (only "account first" pinned); proposal for T041: take both, since tenant-state writes the bucket the tenant's runs use. Order: `account`, then `tenant-<t>` sorted. Refusal is immediate (10 s deadline in the test), never a wait. Tenant runs of different tenants run concurrently (per-tenant locks, R21).
7. **Stale lock** (not stated in the spec; coordinator dispatch): a lock is held only while its holder process lives; a holder killed by SIGKILL leaves nothing that refuses the next run.
8. **"refused selection takes no lock"**: an unknown, empty or external id refuses the run before any `TryLock`; a run refused on a later lock releases the locks it had taken, and a tenant-only run of the refused run's tenant is then admitted.
9. **"neither run changes the other's resources"**: each run "applies" (writes one file per instance) only after `HoldRun` admitted it; the refused second run (another process) applies nothing and the first applies only its own tenant's stacks. The lock layer cannot see resources; this is the observable part of the clause.
10. **Lock location** is the caller's (`DirLocks(dir)`); a local lock excludes runs on one workstation only. Cross-workstation run exclusion is **not provided**: the per-key S3 state lock (`use_lockfile`, P1–P3, T010) serialises writes to one state key, not runs over several keys (review r1, codex minor). Believed; for T041/T059.

## Learnings
- tooling: Terramate 0.17.3 `list --run-order` = topological levels (longest chain), ties by path — not a lexical Kahn order; generate the comparison with the pinned binary in the test instead of storing a capture.
- guidance: a lock test needs a same-process second holder as well as a cross-process one, or a per-process (POSIX record) lock passes.
- guidance: a hand-built graph whose path order differs from its id order is the only fixture that tells an id tie-break from a path tie-break.
