## Observed tool behaviour (verified 2026-10-07, pinned tofu 1.13.0)
- `tofu test` assertions see only a child module's outputs, not its resources (`module.project.ovh_cloud_project` → `Unsupported attribute`, probe `t027-probe.sh`). Order arguments, the alert's threshold/email/delay and the alert's and quota's project are therefore not observable from the component or stage tests (gaps 1–2).
- An `override_resource` target without a module key (`module.project.ovh_cloud_project.this[0]`) also applies to the keyed instance of a `count`/`for_each` call; the keyed call is caught instead by the unkeyed `module.project.<output>` / `module.project_factory.<output>` references (assertion), and a renamed call by `Module not found` on the override target.
- A run-level override of the same address as a file-level one warns ("declaration in global file block will be ignored") and wins.
- `[]`/list vs tuple and map vs object compare unequal, so list and map assertions compare `jsonencode(…)` / `tomap(…)`.

## Learnings
- tooling: `tofu test` assertions read only child-module outputs; resource attributes inside a called module are unreachable (`Unsupported attribute`).
- tooling: an unkeyed `override_resource` target also matches a keyed module instance; pin an unkeyed call through `module.<call>.<output>` references, not through the override.
- guidance: compare list/map outputs through `jsonencode`/`tomap`, or a correct list output fails against a tuple literal.
- guidance: tripwire files (one `mock_provider` per file) pin "off" and "reference" at resource level where outputs cannot.
