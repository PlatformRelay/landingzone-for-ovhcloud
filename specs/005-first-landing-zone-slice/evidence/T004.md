## Design notes

- Where the T003 controls run (coordinator requirement): `test:slice`'s first command is `go -C tools test -count=1 -tags offlinetools -run 'TestUnit' ./internal/checks ./cmd/lz-check` (the regex lives in the Taskfile). `test:slice` is registered in `harness/checks.yaml` with creator `005/T004`, whose Verify runs `task test:slice`, so the creator traces (`check:specs` TRACE_OK, verified 2026-10-06). Its scope now also lists `tools/internal/checks/unit_test.go` and `tests/check/fixtures/unit`, and its inputs `tests/fixtures/tofu/streams`, so a change to the controls selects it. Chosen over `test:unit`, whose registry creator is `005/T011` (first Verify that runs it) and which needs a directory argument. Follows the house pattern of `test:dependencies`/`test:foundation-ci` (controls on fixtures, then the repository's own subject).
- Consequence (gap, not hidden): the target stays red until T012, and CI (`foundation-source.json`) lists only spec 001 checks, so CI does not run the tagged controls yet. The untagged lz-check tests (`TestUnitCommandWithoutTools`, `TestUnitSliceDiscovery`) do run in CI through `test:traceability`.
- `tofu -chdir=<dir>` in the contract vs working directory: the runner sets the child's working directory (`runTool`, shared with lint), which is what `-chdir` does; `TestUnitInvocation` pins that both calls run in the directory. Believed equivalent; not a contract deviation in behaviour.
- `RunUnit` reviewed against the throw-away T003 implementation: reuses `checkInit` and `runTool` instead of a second exec path; stderr of `tofu test` is dropped (diagnostics are in the JSON stream, and the adapter judges stream + exit); a tofu that cannot start reports code -1, which the adapter fails (`EMPTY_STREAM`, `NONZERO_EXIT`).
- `slice` scans the graph first; any dependency finding fails it (`SLICE_FAIL DEPENDENCIES`) before a tool runs, like `select`. Per-directory line: `<status> <dir> lint=<pass|fail|blocked> tests= passed= failed= errored= skipped= <reason>`; a directory is `blocked` only when nothing failed.
- `lint`'s directory validation extracted to `moduleDir` and shared with `unit`; lint output unchanged (`TestLintWithoutTools`, `TestLintWithTools` green).

## Learnings

- tooling: a check that is red by design (zero discovery) hides its own controls' exit code; read step 1's `ok` lines until T012 turns `test:slice` green, or add the controls to CI then.
- guidance: `lz-offline` runs `task test:unit -- <dir>` on any repository directory (init in place leaves only gitignored `.terraform/`), so a fixture directory is a cheap positive control for a per-directory target.
- guidance: every directory under `modules/`, `components/<family>/<x>`, `stages/` holding `*.tf` is a slice member, nested ones included; each needs its own `.tftest.hcl` (T012+).
