## Choices

1. **Deadline seam, not a shorter deadline.** A deadline short enough to be cheap would fire before a loaded machine reaches the hanging apply ("applied every stack before the hang" would flake), and `Deadline` is also the destroy-on-exit's budget: a first version counted a 100 ms deadline from the hang and, under the race detector beside the parallel tests, the destroy had no time (`destroys [], want [b a]` in `TestRunnerDeadline` and `TestRunnerInterruptGrace/deadline`; iteration 4). So `Runner.deadlineAt` and `ChainOptions.deadlineAt` (unexported, nil in production) end the run with `errDeadline` when the test closes them (its fake apply hangs); `Deadline` (30 s in tests) still bounds the run and is the destroy's budget. `withDeadline` is the unchanged `context.WithTimeoutCause(ctx, d, errDeadline)` plus, only when `at` is non-nil, a child context the channel cancels with the same cause. `TestWithDeadline` pins: the timer ends the context after d with `errDeadline` and a `Deadline()` value, with and without an (open) `at`; a closed `at` ends it at once with `errDeadline`; a cancelled parent is not reported as the deadline.
2. **Injected waits in every test runner.** `runWorld.runner` (which every probe harness starts from), `fakeRunner` (the fresh lz-live process, extracted from `fakeRun` unchanged) and the chain harness inject a deadline (`testWaitCap` 30 s, under the entry's 120 s child limit), a grace (5 s; a fake tofu stops at once on an interrupt) and a companion backoff (50 ms, 100 ms). `TestTestRunnersInjectWaits` (runner_test.go) fails on any zero (= production default) or a wait above 30 s, and pins the production defaults (45 min, 2 min, [20 s 60 s]); `TestRunnerDefaultDeadline` still runs one run under the default deadline on purpose (it pins that default in summary.json).
3. **Assertions kept, scaled where they are relative to an injected wait.** `TestRunnerInterruptGrace` uses `ignoredGrace` (1 s, was 2 s): "not killed before the grace period" is `took >= ignoredGrace`, and the Ctrl-C row now also checks that the ignoring tofu's plugin is still alive `ignoredGrace/3` after the Ctrl-C (review r1: the lower bound on lz-live's exit also counts the destroys' time, so with a short grace it alone could pass an immediate kill); "killed after it" keeps its 25 s upper bound. The companion-retry backoff is 30/60 ms (was 300/600 ms); "each retry waits at least its backoff" is unchanged. The chain deadline row reaches its deadline at the block (was a 6 s deadline from the start); every assertion of the row is unchanged.
4. **Parallel only where nothing process-wide is touched.** A name-based call-closure over the test files (`~/.local/share/ovh-lz/review/t114-procwide.py`, outside the repo) marks a test unsafe when it can reach `t.Setenv`, `t.Chdir`, the umask, an `os.Stdout`/`os.Stderr` swap, `log.SetOutput` or `signal.Notify` in the test process; 132 tests are safe and call `t.Parallel()`. The lane, chain and bootstrap harnesses set the process environment on purpose (ambient credentials, `TMPDIR`, `HOME`), so those ~43 s stay serial. `notParallel(t)` (files_test.go) now marks `withUmask`, `laneCaptureStd` and the bootstrap harness's stdout swap as process-wide through `t.Setenv`, which panics in a parallel test: a later `t.Parallel` on a test reaching them fails at once instead of racing.

## Harness gaps

1. The chain and lane children's grace is the production `DefaultGrace` (2 min, `chain.go`'s `childEnv`): not injectable, so a future lane fake that ignores SIGINT would wait 2 min, past the entry limit; today `laneStack.Block` stops on SIGINT. The task names deadlines and backoffs; not widened here (strong leg r1 note).
2. `TestTestRunnersInjectWaits`'s chain row reads `chainExec{}.chainDeadline()`, true by construction; it would not notice `h.chain` stop passing it. Checking the options `h.chain` passes would need the chain harness (process-wide env) inside a parallel guard test; accepted (strong leg r1 note).
3. The list of 132 parallel tests came from a name-based closure script outside the repository (`~/.local/share/ovh-lz/review/t114-procwide.py`). In the repository, misuse is caught by `t.Setenv`/`t.Chdir` panicking in a parallel test, now also for the umask and stdout swaps through `notParallel`; a test that reaches a different process-wide state (none known) would not be caught.
4. Deadline wiring end to end: `TestRunnerDeadline` and `TestChainDestroyOnExit/deadline` now reach the deadline through `deadlineAt`, so neither drives `Execute`'s or `Chain`'s timer; the timer is covered by `TestWithDeadline` and the default by `TestRunnerDefaultDeadline` (summary value). A call site passing a wrong duration would pass (strong leg r2 note). A real-timer row with a short `Deadline` would close it; not added after the last round.
5. `-race` ran over the 132 parallel tests (0 reports) but not the serial ones (the whole-package run exceeds 10 min under `-race`), so the chain watcher goroutine's reads of `h.world`/`h.m` are unchecked by the detector; nothing writes them during a run (read).

## Learnings

- sensor: a real deadline in a test is also the destroy-on-exit's budget; shorten when it is reached (a seam), never its length (T114 iteration 4).
- guidance: a lower bound on a whole run's duration also counts everything after the event (here the destroys); check the state at the event itself (the plugin still alive) when the bound is shortened.
- tooling: `go test -race` over the whole `./internal/live` exceeds 10 min (race-built fake children); run it over a named subset (`t114-race-parallel.sh`).
- sensor: `notParallel(t)` (files_test.go) is the marker for any new test helper touching process-wide state; `t.Setenv` and `t.Chdir` mark themselves.
