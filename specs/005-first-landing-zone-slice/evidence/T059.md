## Readings (believed unless marked verified)
1. **Binding (decision 3a)**: `ApplyOptions.API`; each stack's OAuth2 credential is bound with the existing `Bind(ctx, API, cred, Binding(account.env), manifest org)` after it is loaded and before the stack's first tofu call, once per client id and run. `Bind` compares endpoint and org before sending the credential, then `GET /auth/details` (P26). An `account.env` naming another account than its directory is refused by the same call (the directory's credentials answer the directory's account). Producer keys read during selection are S3 keys only (no OAuth2 use, nothing to bind; T058 gap 5 stays).
2. **Lock release (decision 3b)**: one `defer` joins `release()` into the run's error after `HoldRun`, and each stack's saved plan is removed by its own `defer`; every child failure returns through both. Pinned per failing call (init, plan, `show -json`, rendered `show`, `output`) under `apply` and `plan`.
3. **Missing files name their writer (decision 2)**: `sandbox.env` and the account `state.env`, `account.env`, `state-passphrase.env` → `bootstrap:account`; deployer files → `account-governance`; a tenant's S3 files → its tenant-state instance id. The entry blocks on a missing `sandbox.env` before any API request.
4. **Deployer outputs** (review of the throw-away): the throw-away wrote `tenants/<t>/deployer.env` for every key of `account-governance`'s `tenants` output, so a key outside the manifest (or a path such as `../../escape`) wrote a file, and an empty client id or a missing secret was written as is. Now the tenants are exactly the manifest's, every client id and secret non-empty, all checked before the first file is written.
5. **Selection credential errors** (review of the throw-away): the throw-away skipped a producer on any credential error, so a refused producer file (mode, mismatch) read as "nothing published"; now only `*Blocked` (missing file) does, anything else refuses the run.
6. **Children** run through the run core's `childEnv.command` (own process group, SIGINT on cancel, kill after `DefaultGrace`, `killGroup`) instead of `exec.CommandContext`'s immediate kill; the entry cancels on SIGINT/SIGTERM like `bootstrap`. No run deadline and no inventory (gap 2).
7. **Entry**: `lz-live plan|apply --reviewed-sha <sha> <instance|all>` — exactly one target (usage, exit 2, before the guard); account from the sandbox credential (`API.Account`, as `probe`); run dir `.local/live/<run-id>/`, records `.local/live/records/`, locks `accounts/<a>/locks/`, store = spec.state's S3 (shared `stateStore` with `bootstrap`), revision = reviewed SHA, schemas = `schemas/outputs`.
8. **No checks.yaml rows** for `live:plan`/`live:apply`: like `live:probe`, a host check gets its row with the owner task that first runs it (T049 runs `live:chain`); `check:specs` stays green without them.
