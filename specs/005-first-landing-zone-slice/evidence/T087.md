## Decisions taken here

1. **"Skipped for bucket listing" read as "no bucket listing required", not "not asked".** The
   Cold-Archive-only region's storage is still asked; its 404 is accepted, any other failure (a 404
   on a later page, a 500) stays an error, and a 200 is parsed (a container found there is
   reported). Reason: T065's review lesson (both legs, round 1) — a capability rule decided from a
   name list must only decide whether an error is acceptable, never whether to ask, so a wrong rule
   cannot hide a listing; the cost is one GET per Cold Archive region. The literal reading (skip the
   GET) is mutant C7 and is killed by `TestLeftoversCapturedClean` (storage asked once in every
   region) and `TestLeftoversCapturedUnrecognisedStorage/coldarchive-captured`. Counterpoint for the
   coordinator: if the dispatch meant "do not ask", that is a one-line change, but it reopens the
   T065 fail-open class.
2. **Rule shape.** `s3Services` maps the three captured names to "answers a bucket listing":
   standard and high-perf `true`, coldarchive `false`; a `storage-s3*` name not in the map counts as
   a bucket service (fail closed); an unnamed service still makes a 404 an error (T065). The
   function is renamed `withoutObjectStorage` → `withoutBucketService` (it no longer means "no
   Object Storage": RBX-ARCHIVE has Object Storage, but no buckets).
3. **Replay of the new capture.** The region id list and per-region details are served from the
   captured `listings/ovh_cloud_project_region.json` (as the client and group records are); the ten
   bucket-service regions' storage answers are the captured `[]` (derived: no error under the
   reviewed rule, record `[]`); every other storage route answers the fake's default 404 (RBX-ARCHIVE
   captured in `leftovers.json`; the compute regions as in run `…14a6`). `ovh_iam_resource_tags` is
   now `captured` (`[{}]`). The T065 placeholder region `S3-UNNAMED` is gone; its rows moved to GRA
   (bucket region) and CA-EAST-TOR (the run's DOWN region).
4. **Anonymiser** (`~/.local/share/ovh-lz/review/t065-anonymise.py`, outside the repo). No new value
   kind: the region details add `AUTH_<project id>` endpoint suffixes, which the bounded 32-hex rule
   already replaces. Extended anyway with a residual check: after removing every fake, no hex run of
   20+ characters and no UUID, account handle or e-mail may remain, else it exits before writing.
   Control `t087-anon-control.sh` (synthetic values): a project id glued to a hex character after
   `AUTH_` → `an id-like value that is not a fake remains`, exit 1, nothing written; unglued → exit 0.
   Mapping identical to T065's (same originals): project `f0…01`, account `xx000001-ovh`, three UUIDs,
   client `EU.0000000000000001`.
