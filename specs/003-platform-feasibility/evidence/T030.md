## Design notes and deviations

- **The seed.** The ovh provider has no object resource (provider docs resources/, mirror commit
  00cb8b0, verified 2026-10-16: storage resources are the bucket, its lifecycle, replication and
  presign only), so the root cannot write the seed. tasks.md's fallback: the check's first step
  writes it with the bucket's cleanup credential. T029's fixed tests forbid Undo deleting the seed
  (`undoReqs`: "undo deleted the root's seed"), so the seed stays with the bucket: the destroy
  removes it (the provider "will try to remove all objects it contains beforehand",
  resources/cloud_project_storage.md:10; believed for the pinned 2.21.0), and Sweep empties the
  bucket. This deviates from the task text's "and Undo deletes it"; the cleanup policy gains
  s3:PutObject on the seed key only.
- **No versioned deletes.** s3:DeleteObjectVersion is not an accepted S3 policy action
  (tests/fixtures/ovhcloud/s3-policy-actions.json, verified by regex 2026-10-16), so the buckets
  stay unversioned and Undo deletes by key. Sweep's bulk delete drops a listed version "null"
  (deleted by key; whether the API takes "null" is UNVERIFIED).
- **The API checker grows seven operations** (tools/internal/live/apicheck.go: ListRegions,
  ListBuckets, ListObjects, BulkDeleteObjects, DeleteBucket, ListUsers, DeleteUser; paths from
  kb/api/v1/cloud.json, verified 2026-10-16). Sweep uses the established gated client rather
  than raw HTTP. The Sweep operations take a region with dashes (RBX-ARCHIVE, spec 005
  evidence/T087.md); GetStorage keeps its narrower rule. A ListBuckets 404 reuses the leftover
  check's `withoutBucketService`. The names avoid "DeleteStorage", which an existing gate test
  uses as its unknown operation.
- **Observe's error.** A reach is a finding; a blocked or not-run step fails Observe too (C005.1
  not shown, V004 "deny with attributable reasons"), with the record written. The one-direction
  login failure leaves that direction `blocked`, both refused leaves every step `not-run`, as
  T029 fixed.
- **Keystone and Swift.** Request shape from docs.ovhcloud.com pcs-curl-commands-memo.mdx:15-19
  (password method, domain "default", project scope); the Swift account from the catalog's public
  object-store endpoint of the region, accepted only as https://storage.<region>.cloud.ovh.net/v1/AUTH_<tenant_id>
  (same guide, :16). Catalog region names and the account path on OVHcloud are UNVERIFIED until
  T025; a mismatch reads `blocked`/`not-run` with the reason, never a denial. Redirects are not
  followed (a 3xx is blocked, TestJudgeReach "other 3xx").
- **Record additions** (ignored by T029's reader): `route`, `bucket`, `seeds`, `roles` (T025 asks
  for the tenant users' role names).
- The fakes extended for T030 (see Test changes) are Go httptest servers written from the API
  shapes, not recordings; no pinned tool produces these answers offline.
