each for its stated reason.

## Maintainability

1. Duplicates existing code? The fake parallels bootstrap_admin_test.go's OAuth2/policy routes in
   another package (test helpers are not importable); `rr`-prefixed for the shared package.
2. A new abstraction without a second user? `Options` is shared with T033's iam-urn check by the
   data model.
3. Hidden coupling? The record's JSON names are a contract with T032; listed in the file header.
4. Error paths untested? Refused/failed deletes, lost create answer, leftovers, outages, deadline,
   invalid expiry: each a case.
5. Magic values? Statuses and durations are constants or named in the case.
6. Hard to change? The pure ResidualWindow table isolates the judging rules from the HTTP flow.
7. Non-determinism? The fake clock starts at the real time truncated to a second; every assertion
   is relative to it.
8. Surprising for a reader? The method-not-field Sweep; commented in both files.

## Learnings

Class: sensor.
- A fake clock that does not advance between token issue and delete makes issue-relative and
  delete-relative bounds identical: script one refused control so the two instants differ.
- A pure judging function (ResidualWindow) tested by table carries the boundary cases; the HTTP
  cases need only show the flow reaches it, so a test task proves the table satisfiable with a
  scratch reference before review.
- A case whose result is a stop (blocked by control, deadline, outages or expiry) needs a reach
  assertion as well as a bound: Settle used up, the deadline or the expiry reached, the anomaly
  actually observed; an upper bound alone passes a check that gives up at once.
- Compare the record with the fake's consumed answers one to one (time, status, flag); spot
  checks on two entries let a dropped or zeroed entry through.
- A fake that grants on any policy naming the identity lets the check omit the action and the
  resource; the fake checks the exact grant, with a wildcard control.
