## Deviations

- **The field is in runner.go**: `ProbeCheck.Sweep` with data-model.md's signature and comment
  (four lines), because the tests cannot compile without it and a struct field cannot live in
  another file. T038's scope owns the field's final comment. sweep.go holds the stub
  `(*session).sweep`, which returns "not implemented" and is not called. No other runner.go line
  changed.
- **What the tests fix beyond data-model.md** (T038 inherits them):
  - Sweep runs even when no apply started (the plan failed, no state): data-model.md's "on every
    way out". The fake tofu writes state when an apply starts, so "no state file" is reached
    through a failed plan; mutant `sweep-only-after-apply` fails.
  - Sweep runs after the destroy even when the root published nothing for its check (Undo skipped).
  - A failed Sweep and a failed leftover check both name `--cleanup <run-id>` in the run's error when the check has a Sweep.
  - Sweep gets the destroy's context, live after the run's deadline.
  - Sweep runs after a failed destroy too (round 1; data-model.md's "on every way out"). T038 should
    weigh the hazard this brings: with the root kept, Sweep may delete a resource the root's state
    still holds (tofu's refresh in the later `--cleanup` is believed to drop a resource that answers
    404; UNVERIFIED), or a credential the kept root's Undo needs; Sweep deletes the check's
    resources by name as well, so what Undo would remove is covered. If T038 decides otherwise,
    that is a `TEST` correction citing the decision.
  - "No state entry" is modelled by the stream alone (no `apply_complete`, so no inventory id,
    asserted): the fake tofu writes an opaque state file when an apply starts, which the runner
    never reads for entries. A real state without the entry is not modelled.
- **"Names or ids beyond the run's"** (case 7) is read as: Sweep's terminal is the run's redacted
  writer, holding the run's credential, its passphrase and the values the root published for the
  check; a sweep given the raw terminal or a redactor of its own fails (mutants
  `sweep-raw-terminal`, `sweep-own-redactor`). A foreign resource name Sweep might list is not a
  secret the redactor knows; T038 or the probes decide whether Sweep prints such names at all.
- **The fresh process for case 2** is the test binary started as `lz-sweep-run <config>`,
  dispatched in sweep_test.go's `init` (before TestMain), so fake_test.go and runner_test.go stay
  unchanged; it reuses runner_test.go's `fakeRunner`.
- **Whether tofu writes root outputs after a partial apply failure** stays UNVERIFIED (tasks.md);
  the tests cover both the no-output and the full-output case.

## Learnings

Class: sensor.
- A "fails on X" case must not already fail on an earlier step: give the failure under test an otherwise passing run, or a swallowed error passes.
- A fake that writes opaque state is not "no state entry": assert the absence where the runner looks (the inventory) and say what is not modelled.
- A test-binary fresh-process entry can be dispatched from `init` in the new test file, leaving shared fixtures untouched.
