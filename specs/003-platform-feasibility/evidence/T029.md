  The ordering and names are believed sound, not verified against OVHcloud: Keystone v3, Swift v1
  and the catalog region names are UNVERIFIED for OVHcloud until T025.
- **One-direction login failure is `blocked`, both refused is `not-run`**, as the task text says;

- The fakes are Go httptest servers written from the API shapes, not recordings: there is no

## Maintainability

1. Duplicates existing code? The fakes parallel storageiam_test.go's world but differ (Keystone,
   Swift, per-bucket S3 keys); names are `sw`-prefixed to share the package. Justified.
2. A new abstraction without a second user? No; swWorld is the one fake for five tests.
3. Hidden coupling? Sweep's API paths mirror leftovers.go; stated in the deviations.
4. Error paths untested? Refusals, outages, transport errors, lost answers, leftovers: each a case.
5. Magic values? Statuses and names are constants at the top or in the case.
6. Hard to change? The JSON names are the contract T030 must write; collected in the file header.
7. Non-determinism? Map order removed from failure output (undoReqs walks A then B); no clock.
8. Surprising for a reader? The method-not-field Sweep; commented in both files.

## Learnings

Class: sensor.
- A fake that hangs up on a GET over a kept-alive connection is defeated by net/http's silent
  resend of idempotent requests; disable keep-alive in the test client and assert the request
  count in a fixture test.
- "Every case runs both directions" must be scripted per direction; a precondition that counts
  objects in a bucket is satisfied by the other user's own control write, so fakes record who
  wrote what.
- A sweep case needs a resource outside the default region and a partial set, or a hard-coded
  region and an all-or-nothing sweep pass.
