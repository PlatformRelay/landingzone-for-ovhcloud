## Fixtures

tests/fixtures/tofu-probes/locked-recovery/: twelve tofu outputs and fixtures.json (command, exit,
class, sources). Composed from OpenTofu v1.13.0's source and the SDK modules its go.mod pins
(aws-sdk-go-v2 v1.43.5, service/internal/s3shared v1.19.37, smithy-go v1.27.7, go-multierror
v1.1.1), read from shallow clones of the tagged sources on 2026-10-16 (verified, read). Not
captured: no S3 backend is reachable offline, and the task fixes "taken from OpenTofu 1.13.0's
source". The wrapping (75 columns for detail lines, format/diagnostic.go), the request ids and the
S3 error messages are believed; T028 records whether the live diagnostics match, and a mismatch is
`blocked`. One fixture (unmatched.txt) is synthetic by design. Generation: hand-composed, detail
lines re-wrapped with the records dir's t035-wrap.py.

Facts read from the source (verified 2026-10-16, read): the lock refusal is the S3 backend's own
PutObject with `If-None-Match: *` answered 412 (client.go:313-345), so the conditional-PUT control
probes the very guarantee the lockfile relies on; LockInfo.Path is `<bucket>/<key>`
(client.go:264, :596-598) and the lock object `<key>.tflock` (:609-611); force-unlock reads the
lock object and compares ids before DeleteObject (client.go:524-557), so a 403 can come from
either call.

## Learnings

Class: sensor.

- A fake's "acknowledged but ineffective" mode must keep every piece of answer metadata plausible (version ids, headers) and also have a variant where the metadata matches but the content is wrong, or a check that judges by metadata passes. (round 1, round 2)
- A header contract ("X is an observation, not an error") needs an assertion on every path it covers, not only on the happy path. (round 1)
- Diagnostics composed from a tool's source go through the tool's own renderer rules (here word wrap at 75 columns): a fixture citing only the message lines misses the wrapping that splits the words a classifier keys on. (T035)
- A new test that reads outside tools/ needs its registry input declared and pinned in the same task (TestRegistryInputsCoverReads). (T035)
