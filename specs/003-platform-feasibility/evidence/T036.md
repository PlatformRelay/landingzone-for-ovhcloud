## Decisions taken here

- **condition-ignored is a behaviour gap** (dispatch item): fixed in the fake (above) and in the
  check: the conditional PUT's body is lock info whose ID is the held lock's (read from B's refusal)
  and whose Path is the lock's, so an ignored condition leaves force-unlock's comparison as it was
  and the recovery is still observed; the finding records the refutation.
- **Undo converges** with a first listing as the janitor: 404 NoSuchBucket means the bucket is
  gone; 403 InvalidAccessKeyId counts only when the state user's listing is also refused
  InvalidAccessKeyId and the admin's listing of the run's project no longer shows the bucket
  (review r2: keys revoked by hand prove nothing about the bucket). An invalid janitor key beside a
  state key that answers, a bucket still listed, or no project to list fails Undo and keeps the
  root (review r1, r2). For that listing RecoveryOptions gains `Project` (lz-live: the project
  probe.env records), a field beyond data-model.md's.
- **Writer A that could not take the lock** (it exits before its prompt with "Error acquiring the
  state lock", e.g. a lock PUT OVHcloud refuses) is `blocked (lock not taken (<reason>))`, not
  "owner alive" (review r2); an unexplained exit stays "owner alive" (T035's owner-alive cases).
- **A restore PUT allowed without a usable version id** is not as expected (its reason says why):
  the restore was not shown (review r2). Any other answer goes to state's undo unchanged; that
  extra listing is the one request Undo may send as the state user.
- **Sweep keeps the janitor** while the bucket may still exist (a failed listing or a failed bucket
  delete): it is the only identity that can empty a bucket holding retained versions (review r1).
- **B's refusal needs the 412**: OpenTofu prints the lock info it finds after any failed lock PUT
  (client.go:336-345, verified 2026-10-16, read), so `refused (locked)` also requires `StatusCode:
  412` and `api error PreconditionFailed`; a 5xx or 403 beside lock info is `blocked` (review r1).
- **A conditional PUT refused by something other than the condition** (403, 400) is not as
  expected and carries the reason `not a precondition failure`, but is no finding (review r1).
- **Lock id shape**: a UUID only (OpenTofu's), else `blocked (lock id unrecognised)` and nothing
  recorded or broken (lesson T030/T034: validate server text before recording it).
- **The seam's scratch HOME** is its own, of the run core's kind (live.ScratchHome: 0700 under the
  resolved TMPDIR that lz-live checked outside the checkout), created at the first call and removed
  when `lz-live probe` returns: the session's HOME is private to the run core, and the seam needs
  one directory across init and the later commands.
- **Init arguments** beyond T035's fixed `-backend-config=bucket=`: `-lockfile=readonly`, the
  region lowercased and `endpoints={s3="https://s3.<region>.io.cloud.ovh.net"}`
  (live.ObjectStorageEndpoint), so the backend root names no bucket, region or endpoint;
  `force-unlock` also gets `-no-color`.

## Retained cost

The bucket locks every version for one day in governance mode. On every way out the check's undo
deletes every version and delete marker with the janitor's bypass before the destroy, so a clean
run retains nothing. If the bypass is refused, the versions stay until a cleanup deletes them:
the retention only forbids a delete without the bypass for a day, it removes nothing, so after
the day a `--cleanup` (whose undo then needs no bypass) still has to run. What can be there is
small: A's lock object, the conditional PUT's version of it (only if the condition was ignored),
B's second-plan lock version and its delete marker, the unlock's delete marker, and the restore's
three versions, each under 1 KiB (B's refused PUT writes nothing). OVHcloud's Object Storage price
is not read here (UNVERIFIED); at any per-GB-month price this is far below one cent a month. The
bucket cannot be deleted while it holds them (Sweep's error says so, and Sweep then keeps the
janitor). T028 records the actual figure.

## Learnings

Class: guidance.

- A "gone" answer from a credential the cleanup itself may have deleted proves only that the credential is gone: confirm the resource's absence through an identity the cleanup does not delete (the admin's listing), or fail closed. (review r1, r2)
- A tool that prints the state it finds after any failure (OpenTofu's lock info after any failed lock PUT) makes "the output names X" no proof that X caused the failure: classify on the failure's own status, with a mixed-diagnostic case. (review r1)
- A seam that waits for a child's prompt should be checked once against the real tool offline (here OpenTofu 1.13.0 against a local fake S3): it showed the lock taken before the prompt, the death on SIGKILL and the real diagnostics' shapes (no box with -no-color). (T036)
- A cleanup that deletes identities deletes the one that can empty a locked bucket last, and only after the bucket is gone. (review r1)
