## Harness gaps

- Whether OpenTofu 1.13 with state encryption treats a missing local state file as empty on
  `plan -destroy` and its apply is UNVERIFIED; the fake assumes it only where a test opts in
  (`MissingStateEmpty`). If it does not, the `--cleanup` of a run without state still sweeps and
  runs the leftover check, but exits `fail` on the destroy and keeps probe.env and the passphrase
  (a failed cleanup of a run with a Sweep never removes them), so every later `--cleanup` fails the
  same way until the files are removed by hand. A live run (T025–T028) that ends without state
  shows it; if real tofu fails there, the fix is to skip a cleanup's destroy of a root whose state
  file is absent (believed safe: no state, nothing tofu created is known to it).

## Decision request (the coordinator's call; for T030, T032, T034, T036)

A root whose Undo passed and whose destroy failed is swept in the same run (T037's destroy-fails
case and data-model.md's "on every way out"). The next `--cleanup` runs Undo again from the
root's outputs; if a probe's Undo needs a credential Sweep deleted, that Undo fails, the root is
kept, Sweep is deferred, and the run never converges.
- A (recommended): keep the runner; each probe's Undo treats an already-removed write, or a
  credential that no longer exists, as undone (its own tests pin it in T030, T032, T034, T036).
- B: also count a failed root destroy after a passed Undo as a kept root (no Sweep until the
  cleanup destroys it); a `TEST` change to T037's destroy-fails case, citing this decision.

## Learnings

Class: sensor.
- A "keep the files until X passes" rule needs a case where the run fails before X runs (an early
  setup failure), or a negative marker ("X failed") lets that path delete them.
- A fake's tolerance added for one case is opt-in per stack; a global one silently weakens every
  other test of the same step.
- Mutants that delete a condition must keep its variables used, or they fail on compile, not on
  the test.
