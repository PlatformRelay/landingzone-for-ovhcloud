## Design (what the code does; verified by reading and the tests below, 2026-10-19)

- **Start** (`Probe.Start`): refusal `unreconciled-run` (all other run ids, `--cleanup <first>`) before any file; phase 1 `probe.env`, phase 2 passphrase (both `WriteCredentialFile`: temp, fsync, rename); phase 3 in `Execute` → `session.open` → `probeBaseline`, under the run's own deadline context with the signal handler installed (review round 1), before any child: the alert listing of `TF_VAR_project_id`, record copy `.local/live/<run-id>/baseline.json` then recovery copy `accounts/<account>/state/baselines/<run-id>.json` (dirs 0700 via `credentialDir`, never through a symlink), each by `writeOnce` (`O_EXCL` 0600 temp file, fsync, hard link onto the name, which fails if it exists, temp name removed, directory fsync; review round 1: no-replace is atomic). A failed listing writes the record copy only (`complete: false`, errors with the project as `<project>`), returns, and `Probe.run`'s no-state branch retires the run (passphrase, `probe.env`, recovery copy, directory). Plan-only runs take no baseline (they create nothing).
- **Baseline listing's retry, clock, budget** (T011's open point, decided here): the leftover check's `Backoff` and `Clock` (the shared `waitClock`), and a `retryBudget` (`newRetryBudget(end, minRetryReserve)`) ending at the run context's deadline; a signal cancels the listing and the error names the interruption.
- **Before**: `LeftoverCheck.candidate` (extracted from `Check`'s closure): after prefix, run id and inventory, a nameless kind with a `Before` entry is a candidate iff its id is absent. **Deviation (DR-T014-a below):** `Before` judges only the baseline's project (`beforeProject`, unexported, set with `Before` by `probeBaseline` and the cleanup); an alert of another project the check lists keeps today's matching.
- **Cleanup** (`Probe.Cleanup` → `classify`): `LoadBaseline` + `ClassifyRun` on state presence (an unexaminable state file counts as state) and inventory entries (an unreadable inventory refuses). Untrusted → `refused (untrusted): cleanup of run <id>: BASELINE_…; nothing deleted and its files kept: owner recovery, then --cleanup <id> --accept-lost-baseline`, before the passphrase. Baseline-backed → `Before` = the baseline. No state (pre-create, or baseline-backed without state: DR-T013-b) → no passphrase, no `tofu` (`Runner.stateless`, `cleanupStacks`), Sweep and leftover check only.
- **LoadBaseline**: record copy, else (missing or unreadable, read or decode) the recovery copy; both readable and byte-different → `BASELINE_INVALID copies-differ`; validation order run id, project digest, `complete`, `errors`, alert key (present and not `null`). `ClassifyRun`: valid → baseline-backed; state or inventory → untrusted; else `missing` / `incomplete` → pre-create; else untrusted (typed `baselineError`, no string parsing).
- **Recovery files until reconciliation**: `session.reconciled` now marks a failed leftover check of **any** probe run unreconciled (was: only roots with a Sweep), so `probe.env`, passphrase and recovery copy stay with or without state until sweep and leftover check both pass; success and the no-state retirement of a **start** also remove the recovery copy, `probe.env` last (`retire`), so a crash part-way leaves the record a cleanup starts from; a failed **cleanup** never retires (review round 1: it may have failed before its sweep and leftover check ran).

## Deviations and decision requests

Believed: the KD-1 sandbox account has one project (STATE = DEMO_DEV), so T019 is unaffected either way; the fresh second account is UNVERIFIED.

FR-007 ("kept, with or without state, until the sweep and the leftover check have both passed") and T013's `TestProbeRecoveryCleanupLeftoverFails` (files kept while `budget-alert` has no registered check) require it. Spec 005's "a run without state removes its files whatever the outcome" holds only when the leftover check passed (`TestSweepNone/no-state` still green).

## Learnings

Class: guidance.
- A filter keyed on a list of ids from one scope (`Before`, one project's alerts) must carry its scope, or every resource of another scope the check lists is judged against the wrong list: name the scope in the data model with the list.
- "Kept until reconciled" has two halves: a failure must not retire the run, and a cleanup that fails before its checks ran has not reconciled anything; retire only on an affirmative pass.
- Changing a shared writer's fsync order (`credentialDir`) breaks another feature's durability test that pins the order: make the new durability local to the new caller.
