## Design

- `item.scope` (new field): the parts the provider's id composes before the listed id, set where
  the listing knows them: a bucket `[project, region]` (its region loop), an S3 policy `[project]`.
- `inventoryKey(it)`: `type \x00 join(scope + listed id, "/")` for a kind the `stateIDAttr`
  register (chain.go, the retained side's register of the listed id per kind) names; `""` for any
  other kind (tags, Swift containers): never `inventory`. `candidate` looks this key up in the
  inventory set. No second per-kind table: the register says which kinds have a form, the listing
  says what composes it.
- Unchanged (verified by reading the diff, 2026-11-16): `item.id`, `Report.Listed`, `Leftover.ID`,
  the probe baseline (`listBaseline`, alerts by listed id) and the retained lookup
  (`retained[typ\x00id]`, chain.go `retainedIDs` via `stateIDAttr`).

## Known limit (not fixed, FR-013)

The retained lookup still matches a bucket by its name only (`stateIDAttr` `name`), so a retained
state's bucket exempts a listed bucket of the same name in any project or region. Bucket names are
unique per region and project in OVHcloud's S3 (believed); fixing it would need the state's
region and project in the retained key, outside this task.
