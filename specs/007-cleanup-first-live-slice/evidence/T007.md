## Design

- **Slot number.** `highestSlot` reads `attempts/` and takes the highest canonical decimal name (`strconv.Itoa(k) == name`, so `01` or `+1` do not count); the slot is `n+1`. spec.md FR-002 and data-model.md now agree on "one more than the highest" (verified 2026-10-16 by reading both). The slot is created with `os.Mkdir` (not `MkdirAll`), so an existing slot is an error, never merged into.
- **Order.** Slot created (0700, chmod pinned), `observations.json` copied (`O_EXCL`, 0600), then each other entry renamed into the slot. A moved entry keeps its mode; every writer of the record makes files 0600 and directories 0700 (`writeRecord`, `ensureDir`, `appendLine`; believed for tofu-written `*.tfplan`, which `stack`/`destroy` remove on return).
- **Failure.** An archive that fails (attempts/ not a directory, a rename refused) fails the cleanup before it writes anything: going on would write `summary.json`, `leftovers.json` and `errors.txt` over the record it could not keep (constitution V). A partial move leaves the rest at the top level; the next cleanup moves it into the next slot, so nothing is lost. Choice made here, not fixed by spec.md; tested by `TestRecordDirRefusesWhenArchiveFails`.
- **Only on `--cleanup`.** `recordDir` archives only when `cleanupOnly` (set by `Probe.run` alone); a chain or a fresh probe run never moves its record (`TestRecordDirArchivesOnCleanupOnly`).
- **Complexity.** The call sits in the new `recordDir`, so `Execute`'s cognitive complexity stays at its pre-task 71 (host gocognit, below) and no new function exceeds 15.

## Review

Round 1 on `e135e0b` (diff `ca14172..e135e0b`). Legs: review leg 1, and the strong review leg because the diff touches the live lane (`tools/internal/live`).

- review leg 1: REQUEST_CHANGES, three majors and two minors; none survived verification (2026-10-16, by reading the code):
  - "concurrent cleanups lack a run lock; one can archive another's open `errors.txt`, later writes land in the slot" → rejected: no record writer holds a descriptor on a moved file (`writeRecord` opens, writes and closes by path, `files.go:582-587`; the only long-lived descriptor is `inventory.jsonl`, which never moves), so a later write lands at the top level, never in a slot; two concurrent cleanups of one run were unguarded before this task too (no run lock in `internal/live`, verified by grep), and `os.Mkdir` makes them fail rather than share a slot.
  - "`attempts` symlink followed; archive written outside the run directory" and "`observations.json` symlink followed by `copyPrivate`" → rejected: the run directory is the user's own 0700 directory (`ensureDir`); whoever can plant a symlink there can already write the record directly; every other record reader and writer follows symlinks the same way (`writeRecord`'s `os.WriteFile`, `ReadInventory`, `session.undo`'s `os.ReadFile` of `observations.json`, `runner.go:787`), and the copy is 0600 in the same private tree, so it discloses nothing new. Not a new exposure; out of FR-002's scope.
  - (minor) "rename keeps an existing 0644/0755 mode" → rejected: every writer of the record makes 0600/0700 (`writeRecord`, `ensureDir`, `appendLine`); the only foreign files (`*.tfplan`) are removed when `stack`/`destroy` return (`runner.go:344`, `:853`).
  - (minor) "a max-int slot name wraps `n+1`; larger names ignored" → rejected: only `keepRecord` names slots; a hand-made huge name can at worst make the next number not the highest, never reuse a slot (`os.Mkdir` refuses an existing one).
- the strong review leg: CLEAN, four notes, no blocker or major:

  - a directory holding only `inventory.jsonl` and `observations.json` archives nothing → as FR-002's "a run directory without a record is cleaned up as today": `observations.json` stays in place, so nothing is lost; not pinned by a test (nit, accepted).
  - no fsync in `copyPrivate`/renames → the record's other writers do not fsync either (`writeRecord`); the original stays in place for undo; accepted.
  - non-canonical slot names untested → harmless (dropping the guard only skips a number); accepted.

## Learnings

Class: guidance.
- A new branch in a function already over the complexity limit goes into a small helper that replaces an existing call, so the old function's score does not move.
- A mutant's text must be unique in its file or name its occurrence; a mutant applied to the wrong occurrence reads as a survivor.
- A wiring mutant no entry test reaches needs a unit case on the wiring function itself.
