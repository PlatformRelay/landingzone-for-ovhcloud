## Design of the cases (from spec.md FR-005, FR-008 and the task text)

- **A test reaches a child module only through its outputs** (verified 2026-10-18, first focused run): an assertion on `module.project.ovh_cloud_project_alerting.this` errors `Unsupported attribute: This object does not have an attribute named "ovh_cloud_project_alerting"`, and the error skips every later run (`errored=1 skipped=7`). - **The alert's values in `local.budget_alert`** (added after review round 1): `main.tf` passes `budget_alert = local.budget_alert`, and case 1 asserts the local is enabled with threshold 1, delay 3600 and the mocked `ovh_me` address. - **Case 2** requires `alert_id` to equal the overridden id, `budget_alert_check`'s keys to be exactly `["alert_id"]`, every value a string (`tostring(v) == v` is false for a number or bool), and its `alert_id` to equal `alert_id`.
- **Case 3** (*pin*, run `module_in_reference_mode`): the mocked `ovh_cloud_project` data source carries a fixed URN (region `us`, distinct on purpose from the listing's `eu`); `module.project.urn` equals it only in reference mode (adopt takes the URN of a planned `ovh_cloud_project`, a generated mock value). It pins the one module call's mode, not a project declared elsewhere in the root (G2).
- **Case 4** (*pins*): four refusals copied from `alerting` (inside the checkout, under the checkout's `state/probes/`, another root's file name, a run id other than the state path's directory).
- **Case 5** (*pin*): `override_data` gives the account two projects, the run's second; `module.project.project_id` is the run's. It is a pin against a literal or other id passed to the module, not a test of project selection: `var.project_id` and `local.project.service_name` give the same value (the module's `project_id` output passes its input through).
- **Case 2's type checks** (review round 2): the key check is `sort(keys(…)) == tolist(["alert_id"])` (as `tests/live/probes/iam-urn/probe.tftest.hcl:73`), so an object literal and a `tomap()` both pass; `values()` sits inside `try()`, so a scalar output fails the assertion instead of erroring.

## Learnings

Class: guidance.
- An OpenTofu test reaches a child module only through its outputs (`module.x.<resource>` is `Unsupported attribute`, and the error skips every later run); to assert a module call's inputs, put the object in a root local and assert the local, and record the wiring line as a gap.
- An HCL key check of an output that may be an object or a map uses `sort(keys(x)) == tolist([...])`: `keys(...) == [...]` compares a list with a tuple and fails on a `tomap()` root.
- A known red in `test:live-lane` stops every later `LZ_TARGETS` target in CI (`set -e`), so the task's FINAL runs them all through the entry and the evidence says so.
