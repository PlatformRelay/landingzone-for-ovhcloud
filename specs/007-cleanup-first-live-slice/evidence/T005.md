## Design of the cases (from spec.md FR-002 and data-model.md, not plan.md)

- **Two layers.** `sweep_record_test.go` tests `keepRecord` itself on a hand-built run directory (cases 1–3: the move/copy/keep contract, the slot number, nothing to move, modes). `probe_cleanup_record_test.go` drives `lz-live probe --cleanup` through the entry (`run(args, deps)`) with the existing probe world (fake git, fake tofu, fake API): case 1 on the whole record a real failed run wrote, case 3's "it proceeds", and case 4 with the storage-iam check's real `Observe`, `Recorded` and `Undo`.
- **Stub.** `keepRecord` returns `"", error("not implemented")`, so case 3's unit test is red too (task: all four fail against the stub). A stub returning `"", nil` would have made case 3 a pin.
- **Spec versus data-model wording.** data-model.md's signature row says "every entry but `inventory.jsonl`, `baseline.json` and `attempts/`"; its *Run record archive* section and spec.md FR-002 also keep `observations.json` in place and copy it. The tests follow spec.md (the section and the spec agree; the row is shorter, not contrary). Verified 2026-10-16 by reading both.
- **Case 1 through the entry.** The net probe run fails its destroy (`destroy-fails` marker) and lists an `lzprobe-old` network, so the run itself writes `summary.json`, `leftovers.json`, `errors.txt`, `listings/<type>.json`, `plan-net.txt` and `inventory.jsonl` (premise asserted). `listings/network.json`, `baseline.json` (a plausible `Baseline`: run id, sha256 of `p1`, complete) and a check's `observations.json` are added by hand: FR-006's baseline does not exist yet, and the net root has no check. `inventory.jsonl` may be appended by the cleanup, so it is required in place and not archived, not unchanged; `baseline.json` and `observations.json` are required unchanged (spec: "stays in place unchanged").
- **Case 2.** Unit level: `attempts/1/` present → `attempts/2/`, and `{1, 3}` present → `attempts/4/` (data-model: `n` = 1 + the highest existing number); every earlier slot byte-for-byte unchanged. Through the entry it is also asserted in case 4 (the second cleanup leaves `attempts/1/` as the first left it).
- **Case 3.** Unit: `"", nil`, no `attempts/`, `inventory.jsonl` unchanged. Entry (`TestProbeCleanupWithoutRecord`): a cleanup of a run whose record directory holds only `inventory.jsonl` exits 0, writes its own pass summary and creates no `attempts/`. The entry part passes today (cleanup is "as today" without a record): it is a *pin* that guards T007's wiring (a cleanup that refuses on `kept == ""`); the case's red is the unit test's.
- **Case 4.** The storage-iam probe with the tenant's IAM write answered as accepted (`201`, a policy uuid) and a failing destroy: the run's `Observe` writes `observations.json` with that `policy_id` (premise asserted), the root is kept. Cleanup 1 fails its leftover check (an `lzprobe-old` network) and keeps the run's files (premise asserted); cleanup 2 passes. The policy listing answers `[]` throughout (lagging). Then: cleanup 2's admin `DELETE /v2/iam/policy/<uuid>` is seen, its terminal does not print the "no observations.json" line, `observations.json` is in place unchanged, `attempts/1/` and `attempts/2/` each hold a copy, `attempts/1/` is unchanged by cleanup 2. Today `observations.json` is never moved, so the undo half holds; the case is red on the missing archive copies. That the undo half kills the defect it names was established on a scratch implementation (below). "Fresh processes" are modelled as the entry tests model them (`probe_check_test.go` *cleanup*, `main_test.go`): each cleanup is a separate in-process `run(args, deps)` with new `deps`; the check and its `written`/`recorded` closures are built per invocation (`probe.go:258`, `storageiam.go:150-151`), so nothing of an earlier cleanup is held in memory (verified 2026-10-16 by reading; the scratch `move` mutant is killed in this model).
- **Slot number.** spec.md says "`n` the next free number", data-model.md "1 + the highest existing number"; the `after-a-gap` subtest takes data-model's, the more specific text. The two agree whenever slots are only added, which FR-002 guarantees ("nothing in `attempts/` is ever rewritten"); a gap arises only from a manual deletion. Proposed to the coordinator: align spec.md's wording.

## Learnings

Class: guidance.
- A test task whose case is "the stub returns the empty answer" needs a stub that errors, or the case is a pin against the stub.
- A record-file contract that a later task wires (archive, then undo) needs an assertion only the wiring can satisfy (the archive copy), or the case passes today on the unwired path; prove the other half on a scratch implementation and its mutant.
- `TestFilesOnlyWriter` confines file writers to `files.go`: an implementation of a file-moving helper (`keepRecord`) writes through `files.go`.
