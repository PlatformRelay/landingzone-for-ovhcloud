- **Unreconciled run.** Another run's directory (with a `probe.env`) refuses the start: `*Refusal` `unreconciled-run`, detail naming that run and `--cleanup <run-id>`; no own probe directory, no run record, no recovery copy, no `tofu` call, the other directory untouched. - **Digest, not id.** A 32-hex project id with its own alert listing; no file under the record directory or `state/baselines/` holds the id when apply starts; `baseline.json` does not hold it and records its digest and that project's alert.

## Learnings

Class: guidance.
- A test that checks file content after the run cannot tell a baseline written before the apply from one rewritten after it; make the world change at the apply (a listing that gains the created resource) so a late listing shows.
- When a "kept until reconciled" file is to be checked, fail a later step (the destroy) so the run stays unreconciled and the file survives to be read.
- A table over a function that gets no run id (`ClassifyRun`) is best driven through the function that validates (`LoadBaseline`): rows on files, not on hand-built inputs, leave the split between the two to the implementation.
