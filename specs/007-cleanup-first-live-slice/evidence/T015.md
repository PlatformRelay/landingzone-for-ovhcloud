## Design (what the code does; verified by reading and the tests below, 2026-10-19)

- **API operations** (`apicheck.go`): `ListAlerts` (GET `/cloud/project/{p}/alerting`, keeps `Alerts`, every id a uuid or the answer is an error), `GetAlert` (keeps `Alert{ID, MonthlyThreshold, Delay, Email, Emails}`; the answer's id must be the asked one, threshold and delay present), `DeleteAlert` (status). Gate: project and id required; id a uuid; project one path segment (`apiProjectSegment`, see *Deviations*). `GetMe` now keeps a 2xx answer's `email` in `APIAnswer.Email` (never printed). Shapes: kb `api/v1/cloud.json` (`uuid[]`, `cloud.alerting.Alerting`, void; read 2026-10-19, verified).
- **Observe** (FR-008): one `GetAlert` in `Options.Project` with the sandbox admin, then `GetMe`; record `{alert_id, project_sha256, monthly_threshold, delay, matches_plan}` (threshold and delay omitted when the alert could not be read); 404 → error "not found (404) … missing"; a differing threshold, delay or recipient → error naming each (never the address), record with `matches_plan: false`.
- **Sweep** (FR-007): `classify` reads `LoadBaseline(RunDir(id), StateDir/baselines/<id>.json, id, project)`, state at `StateDir/probes/<id>/budget-alert.tfstate` (an unexaminable file counts as state) and `inventory.jsonl` (unreadable → untrusted), then `ClassifyRun`. Pre-create: one terminal line, no request. Untrusted: error carrying the baseline error (`BASELINE_MISSING` / `BASELINE_INVALID …`), no request. Baseline-backed: list in the runner's `project` argument (probe.env's); ids in the baseline dropped; if any remain, `GetMe` once, then per id `GetAlert`: 404 → nothing; plan match (threshold 1, delay 3600, every recipient in `email`+`emails` equal to the account's address, at least one) → `DeleteAlert` (2xx or 404) and a terminal line; otherwise reported and kept, error. After any delete, list again; a deleted id still listed is an error. All errors joined, so B beside a foreign alert is still deleted and checked.
- **Registration** (`probe.go`): `probeCheck(…, project, paths runPaths)` with `runPaths{RunDir: <checkout>/.local/live/<id>, StateDir: accounts/<account>/state}` (the runner's own record directory and the account directory `ProbeDir`/`recovery` use).
- **`--accept-lost-baseline`**: a probe flag, with `--cleanup` only (else usage, exit 2). `beforeCredentials` (split out of `probe`, which drops from complexity 32 to 28) asks on the controlling terminal (`deps.Terminal`, `/dev/tty`, as `bootstrap --fresh-account`) for the run id, before any credential is read; no terminal, a failed read or another line → refusal `accept-lost-baseline` (exit 3). `Probe.AcceptLostBaseline` (`runner.go` `admit`): an untrusted run is admitted with no `Before`, stateless iff no state (so a run with state is destroyed from it, needing its passphrase), except for the roots in `baselineSweepRoots` (`budget-alert` only), for which `AcceptDeletesNothing` makes it stateless whatever the state (FR-007 "deletes nothing"; review round 1); a run of any other class is refused `accept-lost-baseline` (its plain `--cleanup` finishes it with its baseline). `acceptedCheck` drops the Sweep of the roots in `baselineSweepRoots` (it judges by the lost baseline, so it would refuse; FR-007's owner removed the alerts by hand); every other root's check, its Undo and Sweep included, runs as on a plain cleanup. Retirement, as for every cleanup, only when destroy, sweep and leftover check passed.

## Deviations and decision requests

- **DR-T015-a (alert operations' project shape).** The other project-scoped operations gate the project as 32 hex. The entry tests (T013's `rcWorld`, every probe test) run on project `p1`, so the alert operations gate it as one path segment (`^[A-Za-z0-9][A-Za-z0-9-]{0,63}$`: no dot, slash or escape, so no traversal; `TestAlertCallsGated/list-bad-project` and mutant `alert-project-any`). The project comes from `probe.env`, which lz-live wrote from `account.env`; the leftover check takes it unchecked. Believed harmless; a live project id is 32 hex. For the coordinator: accept, or move the probe tests to a 32-hex project (a test change across the probe world).
- **Accept on a `budget-alert` run that has state** (review round 1, both legs): FR-007 says the owner recovery "deletes nothing"; the coordinator's brief requires a destroy from state for the non-alerting roots only. Fixed: `Probe.AcceptDeletesNothing` (set for `baselineSweepRoots`) makes such a cleanup stateless, so `budget-alert` runs no `tofu` and no Sweep; its state file is retired with the run once the leftover check passed (`TestProbeRecoveryAcceptBudgetAlertState`). Every other root is destroyed from its state.
- Not in the spec, added fail-closed: `--accept-lost-baseline` refuses a run that is not untrusted (`TestProbeAcceptNotUntrusted`), so a trustworthy baseline sweep is never dropped.
- "Stdin is a terminal" (data-model) is implemented as the controlling terminal (`/dev/tty`), as the bootstrap's prompt: a pipe on stdin cannot answer. The pty test sets the pty as stdin and controlling terminal.
- Observe's `matches_plan` also compares the recipient (FR-008 "any value that differs from the plan's"); the record keeps the data-model's five keys.
- The live answer's recipient fields (`email` deprecated, `emails`) are UNVERIFIED: kb schema only. If the live API answered other recipients the sweep would report and keep the alert (fail-safe; T019 sees it in its read-back first).

## Learnings

Class: guidance.
- A wiring case for a path pair needs one entry row per path where only that path holds the evidence (only the record copy, only the recovery copy): with both present a wrong path still reads the other and the mutant survives.
- An owner-recovery flag that bypasses a safety class must say per root what it deletes in the prompt the owner reads, not only in the how-to, and refuse runs whose class does not need it.
