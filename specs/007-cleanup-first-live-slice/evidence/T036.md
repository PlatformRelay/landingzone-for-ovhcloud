## What the patch adds (verified, read 2026-11-16)

- `ApplyOptions.destroyBackoff`, `ApplyOptions.destroyClock` (apply.go): stub fields, read by nothing in production code. T037 wires them.
- Fake `tofu`: `laneStack.DestroyFail []laneDestroyFault{Call, Answers}`. The first `len(Answers)` destroy calls of `Call` (`init`, `plan`, `show-json`, `apply`) print the answer alone on stderr (no echo line, so `""` is a failure with no output) and exit 1. Destroy calls are `plan -destroy`, `show -json`/`apply` of a `plan -destroy` file, and `init` of a stack whose state holds resources. Counted per stack and fault in a file next to the call log. The call log records the plan file, nonce and var files of a failed call, so the lane harness's own judgement still applies.
- The ReadFail block of `fakeLaneTofu` moved into `laneReadFault` (same behaviour, same counter file), so adding the destroy fault leaves the function simpler: its complexity fell 208 → 201, and the baseline line was lowered to match (shrink only; `TestComplexityRealTree` demands it).
- Harnesses: `chainExec.destroyBackoff` / `destroyClock` and `laneHarness.destroyBackoff` / `destroyClock`; both pass `testBackoff` when unset, never the production 20 s / 60 s.

## Guidance for T037 (from the tests, not new requirements)

- The retry line is matched as `LZ-LIVE retry destroy <id> in <wait>: transient failure (attempt <n> of 3)` with an optional `: <redacted error>` suffix; it must not carry tofu's output.
- The exhausted error is matched on `attempt 3 of 3` (readRetained's convention); the refused wait on the instance id and the word `wait`.
- A cancelled `live:destroy` wait must return an error that `errors.Is(…, context.Canceled)`.
- The capture-limit row needs `len(output) >= errLimit` to count as full (`capped` keeps exactly errLimit).
