## Design (verified against the code, 2026-10-16)

- `lister.get` (leftovers.go) is every request of the check. `listRetry.ask` sends it (unless the token request has failed for good) and keeps its duration in the budget (`retryBudget.keep`, spec 006 data-model *Retry budget*: "reserve … estimated from the slowest listing so far"). On a failure `listRetry.failed` builds the row (`row`: class from `transientListing`, status, the path or `token`), decides (`refusal`: `permanent`, `attempts`, the context's end, `deadline` when the context's deadline is not after `now + wait`, `budget` when the budget is nil or refuses), prints the line and waits (`wait`), records one `ListingAttempt`, and returns the error to report (`reported`). `pages` asks a failed page again at its own cursor; `objectRaw` uses the same path.
- The context's end is `deadline` when its cause is the deadline (a timeout, or the destroy context's `at`), else `cancelled` (`ended`). A wait that fires while the context has ended makes no further attempt.
- A first page's 404 that `absentOK` admits, and the cached token refusal (`tokenRefused`: no request was sent), are returned unrecorded. A decode failure (`not a JSON array/object`, and an element that does not decode, `not a list of ids` or `unparseable element`, under the number of the attempt that answered) and a bounds failure (repeating cursor, page bound) are recorded `permanent` with class `decode`/`bounds`.
- Token request: one request for the whole check (FR-001 "the token request it needs first"). `binding.go`'s `callError` gains `code` and `sent` (not in the text, not unwrapped), and `do` reads the body before decoding it, so a failed body read is `sent` (transport) and not an undecodable answer. `tokenFailure` turns a non-200 into `*statusError{path: "token"}` and a failed send or body read into `*transportError{path: "token"}`. Its failures count their own attempts across the check (`tokenAttempts`), never a listing's; once no retry follows one, every later request gets that failure without being sent (`tokenErr`). Every token 4xx, 429 included, is permanent and stays cached (FR-001: "a 4xx answer from the token endpoint is never retried"). `statusError` and `transportError` name the token request "token endpoint", so existing texts hold (`TestLeftoversAPITokenAnswerNoEcho` pins "token endpoint" and "503").
- Error text: `(attempt n of 3)` after an exhausted retry; `(attempt n of 3, not retried: budget|deadline)` for a refused wait or a deadline; `; the retry ended: <cause>` for a cancellation; a permanent failure's text unchanged.
- **`transportError.Error()` (deferred by T003's review).** Decision: keep it never quoting the inner error, but name the kind by type (`request failed`, `timed out`, `cancelled`, `reading the answer failed`), so a reset no longer reads like a timeout. Reason: the inner error of a failed `Do` can quote an unparseable `Location` header (the reason `quiet` exists, `leftovers.go` comment), and the report's errors are redacted only when written; a type-only text cannot leak whatever constructs it. Pinned by `TestTransportErrorText` (mutant `transport-quotes-inner`).
- Wiring: `laneRunner.leftovers` (chain.go) sets `check.Budget` to the budget its retained reads use, before them, `check.Clock` to `r.stateReadClock` and `check.Term` to the run's terminal; `Runner.run` (runner.go) sets `check.Budget = newRetryBudget(<destroy context deadline>, minRetryReserve)` and `check.Term` to the run's redacting terminal, keeping a caller's `Clock` (the tests' seam).
- A listing whose retry wait was refused leaves the report `fail`, not `blocked`. Reading of FR-001 "(or `blocked` where spec 006 makes a refused wait `blocked`)": spec 006 makes the report `blocked` only when refused retained-read waits are its only errors (`chain.go` `leftovers`); a listing error is another kind of error, so the report is `fail` there, as before. Asserted as "not `pass`" by T004's spent case; no new pin (review round 1, strong leg's warning: decided here).
- Believed, not required by a case: the chain's baseline listing before the first apply runs with a nil budget, so it retries nothing (data-model wires only `leftovers`); its failures read `(attempt 1 of 3, not retried: budget)` (data-model: "A nil budget admits no wait", reason vocabulary fixed) and still block the run before any apply. The how-to page says so.

Second way: no; the check uses the existing `retryBudget`/`waitClock`. 5. Coupling: `binding.go`'s `callError` now carries a status and the transport failure for the leftover check, unexported, not unwrapped. 6. Abstraction: `Lister` unchanged; the retry sits above it, so tests' fake Listers are retried too. 7. Debt for green: `budget.keep` of each request is spec 006 data-model's reserve rule, not only for the mutant. 8. Legibility: `listRetry`'s steps are one function each (`ask`, `failed`, `row`, `refusal`, `wait`, `reported`).

Easier: a later probe baseline (FR-006) gets retries by passing a budget. Harder: error texts of listing failures now carry attempt suffixes, which a test matching whole strings must allow for.

## Learnings

Class: guidance.
