## Design of the cases (from spec.md FR-007, FR-008, data-model.md and the task text)

- **Fake API** (`tWorld`): an `httptest` server with the OAuth2 token endpoint, `GET /v1/me` (the account's address), and for two projects `GET …/alerting` (uuid[]), `GET …/alerting/{id}` (`cloud.alerting.Alerting`: id, delay, email, emails, monthlyThreshold) and `DELETE …/alerting/{id}`; every request is recorded as `METHOD path`. Shapes from `kb/api/v1/cloud.json` (`/cloud/project/{serviceName}/alerting` GET `uuid[]`; `…/{id}` GET `cloud.alerting.Alerting`, DELETE void), read 2026-10-18 (verified). A `sticky` id answers its DELETE 200 and stays listed.
- **Files**: the record copy `RunDir(<run-id>)/baseline.json`, the recovery copy `StateDir/baselines/<run-id>.json`, the run's state `StateDir/probes/<run-id>/budget-alert.tfstate`, the inventory `RunDir(<run-id>)/inventory.jsonl` (one `ovh_cloud_project_alerting` line); all 0600 in 0700 directories.
- **Plan**: threshold 1, delay 3600, the address `GET /me` answers. The alert in the baseline (A) also matches the plan, so a sweep that ignores the baseline deletes it.
- **Pairs**: every refusal has an acceptance control in the same world. Untrusted rows vs `TestSweepDeletesOnlyNewAlert` and `TestSweepRecoveryCopy` (same B, valid baseline → deleted); foreign rows vs `matches-plan` (same C matching → deleted); `missing-beside-state` / `missing-beside-inventory` vs `TestSweepPreCreate/no-baseline` (no state, no inventory → pass, nothing sent); `TestSweepFailsWhenStillListed` vs `TestSweepDeletesOnlyNewAlert`; each gate refusal vs its own control call in the same row; `TestSweepLostCreate` (valid baseline, no state, no inventory → deleted) vs `TestSweepPreCreate` (no or failed baseline → nothing sent).
- **Observe**: called with `{"alert_id": B}` as the runner hands it. The mismatch rows assert the record holds the API's values with `matches_plan` false (a plan-recording observer fails them); every row asserts the read was sent in the run's project; the 404 row puts B in the other project only. The error must name `threshold`, `delay`, or one of `404`/`not found`/`missing`.
- **Registration**: `TestProbeCheckBudgetAlert` lives in `tools/cmd/lz-live/probe_check_test.go` beside the other `probeCheck` tests (it needs package `main`). It calls `probeCheck` with today's seven arguments; T015 has to pass the run's paths (`RunDir`, `StateDir`) into it, which may add a parameter: that changes every call alike, not an assertion.
- **Names**: the test file's package-level names carry a `t` prefix (`tWorld`, `tDigest`, `tObservation`, `fakeAlert`, …) so T015's `check.go` cannot collide with them (a first reference run collided on `digest` and `observation`).

## Learnings

Class: guidance (recorded in loop.md *Lessons*).
- A refusal row that passes on a stub is red only with its acceptance control in the same row.
- Deleting fixtures that all carry state hide the lost-create class; one row without state shows it.
- A value reaching a function two ways (the `Sweep` argument and `Options.Project`) must differ in the fixture.
- "Report the foreign one and fail" needs the run's own resource beside it, in both list orders.
- Prefix a test package's package-level names: the next task's implementation shares the package.
- Spec gap closed by decision: a fixed `Options` that cannot reach a required input (recovery copy, state, project) is a signature gap; ask before writing tests against it (D-T012-a, D-T012-b).
